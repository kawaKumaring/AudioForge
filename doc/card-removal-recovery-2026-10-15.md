# 여러 파일 삭제와 카드 정보의 일괄 복구

## 확정 기준

카드 제거의 음원 유지 / 음원도 삭제 선택은 그대로다. 해당 카드의 입력 파일·선택한 생성 음원·현재 작업과 보관함의 모든 같은 카드 식별자를 하나의 복구 표로 처리한다. 목록에서 기록만 지우는 선택 제거는 파일을 보존하는 기존 규칙 그대로다.

원본, 이전 생성본의 참조 원본, 다른 카드가 참조하는 음원과 입력 파일, 연결 파일을 삭제 대상에서 보호한다. 공유 session/H3 기록의 삭제 범위는 넓히지 않았다.

## 저장·삭제 절차

1. 파일 이름·입력 소유 표·생성 세션·공유 경로를 먼저 확인하고 전체 삭제 계획을 만든다.
2. 카드 메타의 이전·다음 파일을 개별 사본으로 준비하고, 삭제할 파일의 경로·길이·지문을 복구 표에 확정한다. 원문 본문을 복구 표에 넣지 않는다.
3. 각 음원·입력을 원래 폴더 안의 고유한 .audioforge-delete-식별자-번호.pending 이름으로 옮긴다. 음원을 복사해 용량을 두 배 쓰는 방식은 아니다. 지문 측정은 일정 크기의 버퍼로 읽는다.
4. 모든 카드 메타를 교체한 뒤 같은 복구 표에 확정을 기록한다. 이 표 전에는 어느 임시 음원도 지우지 않는다.
5. 확정 뒤 임시 파일을 지운다. 청소가 실패하면 카드와 원래 음원 위치는 이미 제거된 상태를 유지하며 정리 대기와 재시도를 제공한다. 복구 표는 마지막에 지운다.

확정 전 실패·프로세스 중단은 음원·입력·카드 정보를 모두 되돌린다. 복구 도중 다시 종료돼도 다음 접근에서 이어 간다. 확정 뒤 중단은 삭제한 카드를 되살리지 않고 남은 임시 파일만 정리한다. 청소 대기 중에 복구 사본을 지우는 새 거래를 시작하지 않는다.

## 앱 연결

앱 실행과 카드 파일 통로의 진입 전에 복구를 시도한다. 기존 작업 읽기·쓰기·삭제도 같은 복구 함수를 사용한다. 복구 위치의 충돌이나 사본 변경이 있으면 성공으로 표시하지 않고 후속 카드 조작을 막는다. 카드 화면의 안내와 다시 정리로 재시도한다. 복구가 끝나면 저장본을 다시 읽어 이전 읽기 실패 상태를 해제한다. 직전 편집 저장이 실패했다면 카드 삭제를 시작하지 않는다.

## 관련 검사

구현 후 관련 단위 5파일 80건, 실제 앱 MCP 15건과 기존 작업 목록 11건, 합계 26건 통과. 렌더러·본체 타입 검사와 빌드 통과. 커밋 범위만 읽는 타입 검사도 확인한다.

단위 검사에서 준비·파일 이동·메타 교체·확정 직전·확정 직후·청소·복구 도중에 실제 하위 프로세스를 종료했다. 실패 전후 원본 파일과 카드 기록의 바이트를 비교했다. 초기 검사 1건에서 선택적 호출 인자의 증가 연산 때문에 단계 번호가 매겨지지 않던 문제를 찾아 수정했고, 해당 검사 묶음만 재실행해 통과했다.

실제 앱에서는 합성 WAV를 윈도우 파일 잠금으로 잠가 일부 입력 이동 뒤 음원 이동을 실패시켰다. 모든 파일·현재 작업·보관함이 복구됐고 잠금을 풀고 재시도하면 제거됐다. 실제 중단 기록의 복구 위치에 다른 합성 파일을 만들어 충돌 안내·조작 차단·재시도를 확인했다. 화면 오류는 0건이다. 사용자 파일·실제 목소리는 쓰지 않았고 새 음성 생성·GPU·전체 검사는 하지 않았다.

## 경계

운영체제가 파일을 계속 잠그거나 복구 사본을 외부에서 바꾸면 강제로 덮거나 지우지 않는다. 사본을 유지한 채 실패 상태를 표시하고 재시도를 기다린다. 저장장치 고장·전원 차단까지 보증한 검사는 아니다.

복구 표 확정 전 사본 준비 중에 프로세스가 종료돼 복구 표가 없는 임시 폴더가 남은 경우 원본은 아직 바뀌지 않았다. 알 수 없는 임시 파일을 자동으로 없애지 않고 확인 대상으로 보존한다. 복구 표의 삭제 경로·지문·임시 이름이 맞지 않아도 마찬가지다.

입력 파일을 새로 저장한 뒤 메타 저장이 실패해 참조되지 않는 입력 파일이 남는 문제는 이 삭제 거래와 별개다. 그 파일들을 일괄 탐색해 임의 삭제하지 않는다.
