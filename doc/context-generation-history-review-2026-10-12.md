## 현재 코드의 실제 연결

1. readerChunks.splitForReading은 표시용 문단과 합성용 덩이를 분리한다.
2. readerText.readingPlan은 원문 줄바꿈을 say에 보존한다.
3. useReadAloud는 plan.say를 본체에 보낸다.
4. readerRunConfig는 body를 ttsText에 그대로 담는다.
5. 참조 목소리는 separate.py → tts_worker → tts_grammar의 줄 분할 경로를 탄다.
6. 기본 Qwen 목소리는 별도 상주 경로에서 text_file을 직접 생성한다.

따라서 화면이 묶은 덩이가 모든 엔진에서 하나의 문맥으로 생성되는 것은 아니다.
기본 목소리와 참조 목소리를 같은 생성 경로라고 간주하면 안 된다.

## 방향 수정

- 과거 한 호출 비교를 없는 시험처럼 반복하지 않는다.
- 지난 턴의 context_line_pauses는 기본 꺼짐 진단이며 해결책으로 확정하지 않는다.
- 제품 연결 대상은 참조 Qwen의 표시 줄/생성 단위 분리다.
- 기존 semantic_chunk_planner·실제 tokenizer 예산·reference routing을 재사용해야 한다.
  500글자나 과거 176 token을 검증된 현재 제품 한도로 임의 확정하지 않는다.
- 문맥을 묶을 때 화자·참조·감정·명시 쉼을 잃지 않아야 한다.
- 과거 실행 설정은 tail off, 현재는 auto/말끝 보존 등 차이가 있으므로 과거 성과를 현재 음질 합격으로 확대하지 않는다.
- 안전한 무음이 없는 줄에는 사후 쉼 삽입으로 해결한 것처럼 표시하지 않는다.

이번 작업은 기록·코드 대조만 수행했다. 음성 파일을 새로 열거나 생성하지 않았고,
앱·화면 캡처·실행 검사·커밋·푸시도 하지 않았다. 새 생성은 사용자 보류 유지.


## 구현 연결 (후속 작업)

요청 JSON의 `ttsLineMode`를 `separate`(기본) 또는 `context`로 받는다.
`separate.py` → `synthesize` → `_synthesize_qwen_job` 양쪽 참조 모드 시도에 전달한다.
문맥 유지 요청은 참조 Qwen만 허용하고 다른 엔진에 조용히 무시하지 않는다.

현재 구현 범위는 같은 화자·같은 감정·같은 확정 참조 배정의 일반 줄이다.
문단, 명시 쉼, 화자/연출/참조 변경이 있으면 합치지 않고 요청을 거절한다.
한 줄 요청은 병합할 것이 없어 원래 생성 경로를 유지한다.
여러 조건의 대본을 부분 묶음으로 처리하는 기능과 사용자 화면 선택기는 아직 없다.
기본 방식은 그대로이며 제품 전체 자동 적용은 하지 않았다.

기존 진단의 500글자·12줄 한도를 없애고 실제 토큰 분할/참조 예산/동적 종료 한도를 그대로 쓴다.
자동으로 여러 생성 조각이 나와도 문맥 글의 순서와 본문은 유지한다.
새 무음은 전체 대사 정렬과 단어 사이 작은 신호가 함께 확인된 경계에만 추가한다.
정렬 실패는 소리를 잘라 해결하지 않으며 진행 표시로 쉼 미확인 개수를 알린다.
ASR 모델은 기존 로컬 Whisper를 재사용하고 추가 다운로드하지 않는다.
그 모델을 읽는 데 실패하면 요청도 실패한다. 추가 정렬 비용은 아직 측정하지 않았다.

서수 보정 전/후의 위치가 어긋나면 쉼 좌표를 추정하지 않는다.
원문은 기존 요청·파서 기록에 보존하고, 실제 생성 글과 원래 발화 번호의 범위를 기록한다.
쉼 기록은 별도 파일로 먼저 저장하지 않고 확정 결과 metadata/실행 기록에 함께 담는다.
조각 레이아웃은 쉼 삽입 이전, 속도 적용 후·음높이 적용 전 좌표임을 명시한다.
따라서 음높이를 바꾸거나 쉼이 삽입된 최종 음성의 구간 시각으로 그대로 쓰면 안 된다.
