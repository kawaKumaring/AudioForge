# 한국어 감정 조건 전달 검수 및 비교 준비

## 상태

사용자 지시로 새 음성 생성은 나중에 진행한다. 소희 비교 스크립트는 준비했으며 실행하지 않았다. 제품 기본 Qwen은 유지한다. 새 모델 다운로드·앱 실행·화면 캡처 없음.

## Cosy 코드에서 확인한 것

현재 흡수 경로는 공식 text_normalize를 호출하지 않고 텍스트를 직접 토큰화한다. 따라서 한국어가 영어 정규화로 변형됐다는 가설은 현재 경로에 해당하지 않는다.

참조 캐시는 참조 음성 SHA256과 실제 지시 문자열을 함께 열쇠로 쓴다. frontend_instruct2의 zero_shot_spk_id는 빈 값이며 공식 화자 캐시를 우회한다. 지시가 바뀌어도 예전 지시를 캐시에서 가져온다는 가설 역시 이 경로에서는 확인되지 않았다.

공식 instruct2와 같이 LLM 참조 음성 토큰은 제거하고 flow 참조와 화자 임베딩은 유지한다. 참조는 실제 리샘플링을 거치며 생성 표본율은 24000이다. 사용 가중치는 llm.pt이며 llm.rl.pt가 아니다. 이 확인은 외국인 같은 한국어 발음의 원인을 확정한 것이 아니다.

사용자 청취: 지시 언어 비교 네 조건 모두 외국어가 섞이고 한국어 지시에서는 분노가 작동하지 않았다. 지시 번역만으로 해결됐다고 보고하지 않는다.

## 소희 비교 준비

scripts/compare-sohee-emotions.py: 기존 로컬 Qwen CustomVoice 1.7B에서 기본·분노·슬픔·명랑 네 조건을 만든다. 모두 같은 모델·글·seed를 쓰고 지시만 바꾼다. 기본 조건을 0.6B로 만들지 않아 모델 크기 차이를 혼동하지 않는다.

CUDA 여유를 확인하고 부족하면 시작을 거절한다. CPU 자동 전환 없음. 원음 FLOAT WAV와 실제 지시·설정·지문·시간을 기록하고 정확한 경로가 있는 청취 페이지를 만든다. 실행 전이므로 결과 파일이나 품질 판정은 없다. 소희는 기본 화자 기준이며 참조 인물 A/B/C 복제 결과가 아니다.

## 확인 범위

관련 단위 검사 28건 통과(Cosy 18, Qwen 규칙 10). 비교 스크립트 AST 문법 확인 통과. 실제 감정 음성 생성·GPU 성능·사람 청취는 미실행이다. 전체 검사는 실행하지 않았다.

## 다음 순서

1. 사용자가 생성을 재개하면 소희 네 조건 생성 및 청취 제공.
2. 한국어 발음과 감정이 함께 유지되는지 사용자 판정.
3. 통과한 경우에만 참조 음색 변환 비교를 별도 설계. 음색 변환이 감정과 발음을 보존한다고 가정하지 않는다.
4. Fish는 공식 24GB 권장 조건·사용 조건과 현재 16GB 환경의 차이를 먼저 해결한 뒤 설치 여부 결정. 한국어 IndexTTS 체크포인트는 대응 설정 확보와 감정 지원 확인이 선행되어야 한다.
