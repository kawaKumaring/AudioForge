# 감정 목소리 변환의 단계 분리 보완

새 생성은 마지막에 한다. 이번 작업은 코드 검수, 구현, 합성 숫자·신호로 하는 CPU 검사에 한정한다. 사용자 음성을 새로 열거나 앱 실행·화면 캡처·모델 다운로드를 하지 않는다.

## 코드에서 확인한 결함과 한계

`song_vc/modules/audio.py`는 멜 필터 캐시 열쇠에 표본율·상한 주파수·장치만 넣었다. 같은 표본율에서 멜 개수·FFT 크기·하한 주파수가 바뀌면 앞 설정의 필터를 재사용한다. 창도 표본율만 같으면 다른 길이를 공유했다. 설정이 달라도 잘못된 필터를 쓰거나 모양 오류가 날 수 있다.

필터는 표본율·FFT 크기·멜 개수·하한/상한 주파수·장치로, 창은 길이·장치로 각각 나눴다. 같은 설정의 계산식과 재사용은 유지한다. 이번 실제 비교는 말하기와 노래의 표본율이 달랐고 각각 별도 실행이었으므로 이 결함을 기존 기계음 원인으로 단정하지 않는다.

말하기 모델은 지금도 22,050Hz·80멜·홉256이고 복원 모델 설정도 그와 맞는다. 기존 검증은 모델 이름을 봤지만 이제 실제 복원 설정의 표본율·FFT·멜 개수·홉·창·주파수 범위도 대조한다. 다르면 모델 추론 전에 거절한다. 맞는 현재 모델의 계산은 바뀌지 않는다.

## 마지막 비교에 쓸 관측

말하기 변환에 `--diagnostics-dir <새 폴더> --diagnostics-controls`를 명시했을 때만 입력 원음·참조의 멜을 같은 BigVGAN으로 복원하는 대조 기록을 추가한다. 변환 모델을 거치지 않는 복원 결과와 변환 뒤 복원 결과를 구분할 목적이다.

원음 대조는 본 변환 뒤에 실행하고 난수 상태를 복원한다. 기본 꺼짐이다. 기록 폴더 없이 대조를 요청하면 시작 전에 거절한다. 대조 자료는 `control_source_0`·`control_reference_0`, 실제 변환은 `chunk_N`으로 나눈다. 이름에 generated_mel이 있어도 control 계열은 변환 모델이 만든 멜이 아니라 원음 분석 멜이다. 사용자 음향 정보를 담으므로 로컬 보관 전용이다.

복원 대조는 시간축에서 원본과 같은 샘플이라는 보장이 없다. 홉 격자·패딩 차이도 있으므로 길이 또는 파형 차이만으로 기계음 원인이나 발음 손상을 확정하지 않는다. 실제 GPU에서 대조 자료가 채워지는지는 아직 미확인이다.

`python/vc_stage_report.py`는 저장된 기록만 읽어 배열·출력 지문을 확인하고 단계별 진폭, 제한 전후 차이, 영향받은 구간을 보고한다. 불완전한 기록·자료 변경·중복·모양 불일치·필수 대조 누락을 거절한다. 모노 이외 자료를 시간축으로 펴지 않는다. 기록의 구간은 각 조각 안의 시각이며 전체 음성의 위치로 주장하지 않는다. 음질·발음·감정·닮음 자동 합격 판정은 하지 않는다.

## 검사와 반영

관련 검사: 멜 캐시 5건, 말하기 계약 11건, 기록 5건, 단계 분석 6건, 합계 27건 통과. 구현 완료 후 네 파일을 한 번에 실행했다. 전체 검사·새 생성 없음. 첫 실행 명령은 Python 상대 위치를 잘못 지정해 실행되지 않았고, 제한 환경의 실행은 출력 없이 대기해 중단했다. 앱 전용 Python을 일반 실행 권한으로 다시 실행해 27건 통과를 확인했다. 이를 제품 실패나 GPU 결과로 세지 않는다.

개발선에 파일을 지정해 커밋·푸시한다. 기존 미커밋 기호·감정·말끝 작업, 개인 음성·모델, 보류 편집기는 이번 묶음에 넣지 않는다. master 병합은 아직 하지 않는다.
