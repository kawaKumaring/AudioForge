# 전체 코드 정적 검토와 실패 경로 보완 — 2026-10-15

## 검토 범위

검토 시작 시점에서 검사 파일·외부 흡수 모델 코드·음성 자산을 제외한 추적 소스 374개를 정적으로 분류했다. 파이썬 119개, 본체 61개, 미리 연결 통로 1개, 화면 104개, 공통 규칙 89개다. 빈 catch 후보 185곳을 오류로 일괄 간주하지 않았다. 로그·임시 파일 청소처럼 결과를 뒤집으면 안 되는 경로와 사용자 작업의 성공을 결정하는 경로를 구분했다. 전체 소스의 모든 실행 조합을 확인했다는 뜻은 아니다.

저장·이관·미리보기 실행·낭독 지연 저장·설정·파이썬 런타임을 직접 읽고, 위험이 확인된 공통 경로를 수정했다. 원문·음원·이미지·모델 파일은 열지 않았다. 기존 미커밋 엔진 실험과 보류 대본 편집기는 그대로 둔다.

## 개선한 동작

- 작업 폴더가 없을 때와 읽기 실패를 구분한다. 파일명과 안의 열쇠가 다르거나 연결 파일이면 손상으로 처리한다. 단건 복원도 읽기 오류를 없음으로 숨기지 않는다.
- 카드의 현재 작업·보관함을 별도 파일로 유지하면서, 여러 파일의 교체를 복구 기록으로 묶는다. 첫 파일 교체 뒤 실패하면 모두 이전 상태로 되돌린다. 프로세스 중단 뒤에는 다음 접근에서 준비 거래를 되돌리고 완료 거래는 유지한다. 복구 사본의 지문이나 중단 이후 대상이 바뀌었으면 덮지 않고 차단한다. 읽기·쓰기·삭제 진입점이 복구 절차를 공유한다.
- 옛 기록 이관을 성공하기 전에 완료했다고 기억하지 않는다. 이관 파일과 완료 표를 함께 확정한다. 옛 열쇠 정리가 실패한 경우에도 다음 실행에서 원래 기록을 다시 만들지 않고 정리만 재시도한다. 카드 입력의 외부 분리를 먼저 수행하고 내부 기록을 확정한다.
- 여러 작업 통로의 예외 응답을 한 곳에서 보장한다. 동기 종료 저장도 현재·보관함을 같은 묶음으로 보낸다. 최초 읽기 전에는 종료 저장으로 모르는 기존 작업을 덮지 않는다.
- 목록을 열어 둔 사이 작업이 바뀌면 예전 순번으로 다른 작업을 지우지 않는다. 직전 저장 실패 때 가져오기로 현재 작업을 갈아끼우지 않는다. 일부 옛 작업 읽기 실패는 읽을 수 있는 작업 목록을 가리지 않으며, 초기 읽기 실패를 화면에 알린다.
- 미리보기 실행 시작이 거절되거나 정리·타이머 해제에 오류가 나도 응답을 끝낸다. 결과 뒤의 명시적 오류를 성공으로 가리지 않는다. 완료 뒤 늦은 타이머는 취소하지 않는다. 시간 초과의 취소가 즉시 완료 신호를 보내도 시간 초과 판정이 유지된다.
- 서재 읽기가 실패하면 저장 허용 표시를 켜지 않아, 메모리에 남은 책으로 읽지 못한 저장본을 덮지 않는다. 정상적으로 다시 읽은 뒤에만 저장을 재개한다. 손상된 책이 일부 있으면 건수를 안내한다.
- 낭독 지연 저장은 저장값을 꺼내다 실패해도 값을 버리지 않고 실패로 남겨 재시도한다. 종료 동기 저장의 실패도 완료라고 표시하지 않는다.
- 설정·작업·카드 입력·옛 입력의 저수준 파일 쓰기를 공통화했다. 임시 파일 이름·이관·정리 규칙은 유지한다. 바이트를 끝까지 쓴 뒤 디스크 확정한다. 낭독 실행 대기열도 기존 공통 대기열을 사용한다.
- 파이썬 대본과 감정 캐시의 동일 직렬화를 공통화했다. 기존 지문 문자열과 캐시 기준은 바꾸지 않는다. 런타임 설정의 목록·빈 값·잘못된 버전·잘못된 구성 형식을 손상으로 구분하고, 손상된 원본을 새 설정으로 덮지 않는다.

## 남은 한계

파일별 사용자 입력 보존 구조는 유지한다. 입력 파일을 새로 쓴 뒤 카드 메타 저장이 실패하면 참조되지 않는 입력 파일이 남을 수 있으며, 자동 삭제하지 않는다. 여러 음원·입력 파일의 실제 삭제와 카드 메타 갱신 전체는 아직 하나의 복구 거래가 아니다. 삭제 도중 오류는 이미 제거한 파일 수를 명시하며, 메타 쓰기 묶음만 복구한다.

공유될 수 있는 session/H3 기록 자동 정리는 이전 승인 거절 범위 그대로 유지했다. 자동 삭제 범위를 넓히지 않았다. 기존 사용자 데이터의 일괄 이관·청소는 실행하지 않았다. 복구 기록 자체가 손상되거나 파일이 외부에서 바뀌면 사본을 보존하고 수동 확인을 요청한다. 복구 기록 확정 전 단계에서 프로세스가 종료돼 복구 표가 없으면 자동 삭제하지 않고 확인 대상으로 남긴다. 운영체제 전원 차단·저장장치 고장까지 검증한 것은 아니다.

전용 임시 파일 이름·run별 청소·서로 다른 출력 형식이 계약인 다른 저장소는 겉모양이 비슷해도 합치지 않았다. 모든 빈 예외 처리와 모든 모델 경로가 제거됐다는 판정은 하지 않는다.
