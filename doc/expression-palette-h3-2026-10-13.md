# 감정 아이콘 도구와 H3 연기 비교

## 카드 화면

생성 카드 머리의 ‘감정’ 단추가 이동 가능한 작은 도구창을 연다. 모달·배경 덮개·초점 잠금 없이 대사를 계속 입력할 수 있다. 제목을 드래그하거나 키보드 화살표로 이동하고, 닫기 전까지 카드 화면에 남는다. 다른 작업실로 이동한 뒤의 창 위치·열림 복원은 이번 범위가 아니다.

대사 입력칸을 선택한 뒤 감정 아이콘을 누르면 커서 위치에 표시를 넣는다. 선택한 대사는 삭제하지 않는다. 대사 안에는 아이콘이 보이고 저장·복사에는 기존 합성 문법이 남는다. 표시는 기쁨·슬픔·분노·두려움·경멸·놀람·기본 말투·속삭임·0.7초 쉼이다. 기본 말투는 H3 calm과 같은 기능으로 주장하지 않으며, 경멸도 H3 disgusted와 동일하다고 주장하지 않는다.

아이콘과 도구 버튼은 같은 제목·설명의 공용 방식인 title 툴팁을 쓴다. 생성 중에는 대사와 표시 삽입을 막는다. 감정을 지원하지 않는 목소리에서는 생성 시작을 화면과 요청 함수 모두 차단한다. H3는 카드 엔진에 연결하지 않았으며, 웃음·호흡도 동작하는 버튼으로 제시하지 않는다.

기존 문법은 줄 중간의 첫 감정 태그를 앞 대사에도 적용한다. 아이콘을 중간에 넣은 요청본에는 초기 말투를 먼저 명시해 앞 대사가 새 감정에 덮이지 않게 했다. 저장된 원문은 그대로다. 엔진의 실제 감정 효과·발음·인물 닮음을 보장하지 않는다.

## 확인 범위

- 순수 규칙 4건: 저장 왕복, 이스케이프 보존, 미지원 차단, 실제 합성 문법에서 원문과 700ms 쉼 보존.
- 숨긴 검사 브라우저 17건: 커서 삽입, 선택 원문 보존, 도구 유지와 배경 입력, 다른 카드 전환, 복원, 드래그·키보드 이동, 좁고 낮은 창, 되돌리기, 복사·잘라내기·안전한 붙여넣기, 생성 중 차단.
- 렌더러 타입 검사 통과. 화면 캡처·앱 실행·전체 검사·카드 음성 생성은 하지 않았다.

## H3 연기 시험

앞선 30초 시험과 같은 장문·참조 A·seed 2024를 사용한다. 글을 원문 위치로 여덟 구간으로 나누고 이어 붙인 글이 원문과 완전히 같은지 확인한다. 감정 순서는 기쁨·슬픔·분노·두려움·혐오·놀람·차분함·속삭임이다. 가벼운 웃음·한숨·호흡·웃음과 약 0.7초 쉼도 요청한다.

Speech 2.8의 감정 값, 비언어 태그, 쉼 표시는 H3 문법이 아니다. H3에서는 한국어 대사를 `<d>[Korean] … </d>`로 감싸고 밖에 자연어 연기 설명을 둔다. 말할 시간 확보를 위해 이번 요청 길이는 40초다. 이전 30초 결과와 시간 조건이 같지 않아 순수한 속도·품질 차이로 판정하지 않는다. 여러 감정과 발성을 한 번에 요청하므로 원인 분리 실험도 아니다.

40초 전체 연기 시험은 글·참조 인코딩에 1078.1초가 걸렸고 첫 샘플링 단계에서 메모리 압박으로 중단했다. 해당 시도의 음성 파일은 없으며 기록을 interrupted로 보존했다. 프로세스 전용 메모리는 약 58GB였다. 시작 뒤 ComfyUI 경합이 발견되어 사용자의 종료 승인 후 해당 서버만 종료했다.

후속은 같은 원문과 참조 A를 감정별 짧은 구간으로 독립 생성한다. 기준 seed는 각 구간 2024이고, 길이는 각 대사와 추가 발성에 시간을 확보하도록 정한다. 구간 소리를 자르거나 속도·음량을 바꾸지 않고 연결한다. 두려움 뒤에 0.7초 무음만 추가한다. 모델의 자체 쉼과 파일 여백도 포함되므로 전체 쉼이 정확히 0.7초라는 주장은 하지 않는다.

첫 짧은 구간 시도도 인코딩 지연으로 중단했다. 시작 때 GPU의 시스템·타 작업 사용량은 5234MiB였고, 실행기 텍스트 모델 적재 보고는 13268MiB였다. 메모리 초과·공유 메모리 이동 가능성이 있어 다음 시도는 6.5GiB를 다른 작업과 여유로 예약한다. 모델·양자화·seed·샘플러 설정을 바꾸지 않고 배치만 제한한다. 정상적인 단독 실행 시간 비교에 쓰지 않는다.

## 생성 중단과 사용자 청취 판정

사용자가 ‘지금 멈추고 이대로 테스트를한다’고 지시해 해당 생성 프로세스만 종료했다. 기쁨·슬픔·분노·두려움·혐오·놀람·차분함 7개 구간이 완성됐고 속삭임은 미완성이다. 기록은 interrupted로 보존했으며 8개 완료로 처리하지 않았다. 완성 파일 지문을 대조하고 원음 그대로 연결한 청취본은 43.95초다. 두려움 뒤 0.7초 무음만 추가했고 자르기·음량·속도 보정은 하지 않았다. 참조 A·앞선 기본 말투·연결본·개별 구간을 로컬 청취 페이지에 제공했다.

사용자 청취 원문:

> minimax에게 감정표현을 적용하니 대사가 망가진다 나중에 감정표현에 관해서는 따로 구현하고 이쯤에서 대기한다

판정: 이번 H3 감정 지시 적용 결과는 대사 손상 때문에 채택하지 않는다. H3 감정 기능의 제품 연결과 추가 생성은 보류한다. 감정 표현은 추후 별도 과제로 다룬다. 앞선 기본 말투에 대한 긍정 평가와 구분하며, MiniMax Speech 2.8 서비스나 모든 H3 조건으로 일반화하지 않는다.

손상된 정확한 단어·시각·감정 구간은 사용자 피드백에 없으므로 지어내지 않는다. 원인도 확정하지 않는다. 인물 닮음·비언어 발성·이음의 개별 합격 판정은 없다. 구간별 생성에는 요약의 따뜻한 말투 설명이 남아 있어 개별 감정과 충돌할 가능성도 있다. 이 사실만으로 손상의 원인이라고 단정하지 않는다.

후속 시험 준비 코드에서는 요약 말투를 중립적으로 바꾸고 독립 구간을 재생성으로 부르던 기록 이름을 고쳤으나, 이 변경으로 새 음성은 만들지 않았다. CPU 받아쓰기 보조 스크립트도 준비만 했고 실행하지 않았다. 사용자의 대기 지시를 유지한다.

감정 아이콘 GUI는 구현·개발선 반영한 상태를 보존한다. GUI가 있다는 것을 H3 감정 합격이나 H3 제품 연결 완료의 근거로 쓰지 않는다. 마지막 관련 확인은 조작 17건·순수 규칙 4건·렌더러 타입 검사이며 이번 문서 정리에서는 반복하지 않았다.
