# 폴더 규칙 — 무엇을 어디에 두는가 (2026-09-28, 임시 자리 추가)

이 문서가 **자리의 권위**다. 코드와 어긋나면 코드가 틀린 것이다.

★왜 생겼나 (사용자 지시)
> "C드라이브에 있는 파일들은 전부 삭제할것이고 구성을 개발툴 내부에 셋팅되도록 구성한다."
> "지금은 테스트라는 명목하에 너무 무분별하게 구성이되었다. 폴더규칙도 만들어서 철저하게 정리를 하라"

그 전에는 자리가 **네 군데로 흩어져** 있었다 — 윈도우가 정한 앱 데이터 폴더(시스템
드라이브), 원본 파일 옆, 임시 폴더, 저장소 안. 사용자는 그중 무엇도 고른 적이 없다.

---

## 1. 큰 줄기 — 두 자리뿐이다

```
<앱이 도는 자리>/
  AudioForge_data/      앱이 관리하는 것. 사용자가 직접 열 일이 없다.
  AudioForge_output/    사용자의 결과물. 열어 보고 옮기고 지우는 것.
```

**왜 둘로 나누나** 수명이 다르다. `AudioForge_data` 는 앱을 지우면 함께 사라져도 되는
것이고, `AudioForge_output` 은 **사라지면 안 되는 것**이다. 섞으면 청소할 때 구분이 없다.

둘 다 `.gitignore` 에 있다. 저장소에 올라가지 않는다.

---

## 2. `AudioForge_data/` — 앱이 관리하는 것

```
AudioForge_data/
  audio-forge/          정식 채널
    settings.json       설정과 작업 기록
    cardmedia/          영상에서 꺼낸 소리(중간 산출물)
    refclips/           참조 클립
    lab-takes/          옛 화면의 생성본
    joinPreview/        이어 듣기 미리듣기
    reference-library/  앱 보관 참조 자산
    logs/               앱 기록
    temp/               ★만드는 중에만 쓰는 자리(아래 2.1)
    works/              ★작업 기록 — **하나가 파일 하나**(아래 2.2)
    readerChunks/       낭독이 만들어 둔 조각(캐시. 400MB 넘으면 오래된 것부터)
    Cache/ … 			Electron 자체 캐시
  audio-forge-dev/      개발 채널(판 이름에 -dev 가 붙을 때)
```

**한 줄로 옮긴다** 자리를 쓰는 곳이 여덟 군데인데, 각자 고치면 반드시 하나를 빠뜨린다.
Electron 의 `userData` 자체를 옮기면 그 여덟이 자동으로 따라온다(`src/main/index.ts`).

**옮길 때 설정 한 장만 가져온다** 캐시·중간 산출물은 가져오지 않는다. 다시 만들어지는
것을 옮기는 것은 낭비이고, 옛 자리를 지울 때 헷갈린다.

★옛 자리를 짚을 때 `app.getPath('userData')` 를 쓰지 않는다. 개발 실행은 앱 이름을
모르는 채 떠서 그 값이 `Roaming/Electron` 이다 — 사용자의 설정이 있는 자리가 아니다.
반드시 `app.getPath('appData')` + 채널 폴더 이름으로 짚는다.

### 2.1 `temp/` — 만드는 중에만 쓰는 자리

설정 JSON, 꺼낸 소리의 중간물, 음원 분리 중간 폴더(기가 단위), 파이썬이 만드는 임시 파일.
**작업이 끝나면 스스로 지운다.** 남아도 다음에 다시 만들어진다.

★2026-09-28 이전에는 이 전부가 **시스템 드라이브**에 쌓였다. 본체 15자리, 파이썬 여러
자리, 검사 60여 파일이 각자 `os.tmpdir()` 을 불렀다. 사용자는 그 자리를 고른 적이 없다.

**한 점에서 돌린다** — `src/main/index.ts` 가 부팅 때 `TEMP`/`TMP`/`TMPDIR` 셋을 바꾼다.
`os.tmpdir()` 은 부를 때마다 이 변수를 다시 읽고, 파이썬 자식은 `...process.env` 를
그대로 물려받는다(실측). 그래서 75자리를 각각 고치지 않아도 전부 따라온다.
규칙은 `src/shared/tempRoot.ts` 하나가 소유한다.

★**새 임시 이름은 반드시 `audioforge_` 로 시작한다.** 비우기가 이름 접두로 우리 것을
고르기 때문이다. 짧은 이름(`af_`·`af-`)은 남의 파일을 삼키므로 쓰지 않는다 —
2026-09-28 에 흩어져 있던 짧은 이름을 전부 이 아래로 옮겼다.

★옮겨진 것을 **검사가 지킨다** — `test/e2e/temp-location.e2e.mjs`.
앱에 직접 물어보고, 부팅 기록을 읽고, 시스템 폴더가 늘지 않는 것을 본다.
자리 옮기기는 조용히 실패하므로 코드를 믿지 않는다.

### 2.2 `works/` — 작업 기록은 **하나가 파일 하나**

```
works/
  cards/        생성 카드 — 하던 것 / 보관함
  lab/          옛 작업실
  drafts/       현재 작업 자동 저장
  dialogue/     대화 구간 교정 (파일별)
  transcript/   전사 교정 (파일별)
  books/        낭독 — 책마다 본문·읽던 자리
```

★왜 (2026-09-28 지시)
> "셋팅.json 에 저장하는게 아닌 생성한 파일마다 정보를 따로 가지고있어서
>  그 파일만 삭제하게 하도록한다"

전에는 아홉 갈래가 `settings.json` **한 장**에 있었다. 하나를 지우려 해도 파일
전체를 다시 쓰고, 그 파일을 들고 있는 화면이 여럿이라 **누군가 옛 내용을 도로
써 넣으면 되살아났다.** 실제로 그렇게 됐다.

규칙은 `src/shared/workRecord.ts` 가, 읽기·쓰기는 `src/main/services/work-store.ts` 가 갖는다.
화면은 **갈래와 열쇠만** 말한다 — 경로를 만들어 보내면 언젠가 엉뚱한 자리를 지운다.

★옮기기는 **처음 읽을 때 한 번**, 그리고 **다 성공했을 때만** 옛 열쇠를 지운다.
  두 번 옮기면 지운 것이 되살아나고, 반쯤 옮기고 지우면 기록이 사라진다.
★아주 옛날 한 칸(`dialogueEdits`·`transcriptEdits`)은 모양이 달라 본체가 옮기지
  않는다 — 바꾸는 규칙은 화면 쪽이 갖는다. 변환 규칙을 두 곳에 두지 않는다.

남는 것 — `playbackVolume`·`pythonPath`·`outputRoot`·`lastDir`·배역 세트·참조 자산
등록부는 **앱 설정**이라 `settings.json` 에 그대로 둔다(작업 기록이 아니다).

## 3. `AudioForge_output/` — 사용자의 결과물

```
AudioForge_output/
  <기능>/<날짜>/<시각_원본이름>/
```

기능 이름은 **사람이 읽는 말**로 둔다 — `tts` 보다 `음성합성` 이 낫다.
음성합성 · 음악분리 · 대화분리 · 텍스트추출 · 트랙분할 · 노래변환 · 더빙.

규칙은 `src/shared/outputLayout.ts` 하나가 소유한다.

**자리를 원본 경로에서 뽑지 않는다.** 영상을 목소리로 쓰면 화면이 '꺼낸 wav' 를 건네는데,
그것을 기준으로 삼으면 결과가 앱 데이터 폴더에 쌓인다(2026-09-28 신고의 원인).

**바꿀 수 있는 세 갈래**
1. 기본 — 앱 자리
2. 고른 자리 — 설정에서 정한 폴더. 구조는 같다.
3. 원본 파일 옆 — 체크하면. **예전 모양 그대로**(기능·날짜 칸을 끼우지 않는다.
   본체가 이전 결과를 찾는 모양이기 때문이다)

우선순위는 **체크 > 고른 자리 > 앱 자리**.

## 4. 검사가 쓰는 자리

**검사는 사용자 자산을 건드리지 않는다.** 이것이 첫 규칙이다.

검사도 **시스템 드라이브로 가지 않는다.** `test/_temp-root.mjs` 가 `os.tmpdir()` 을
저장소 안 `_local/tmp/r<pid>/` — **실행마다 제 폴더** — 로 돌리고, 실행이 끝나면 그 폴더를 통째로 지운다.
들이는 자리 —
- 실제 앱·화면 검사 파일(`test/e2e/*.mjs`)마다 **첫 import**. 검사 도구(Playwright)가 불러오는 순간 임시 자리를
  정해 두므로 둘째 줄이면 늦다. 단독으로 돌려도 C 로 가지 않는다.
- `test/e2e/_e2e-helper.mjs` 맨 위, `scripts/verify.mjs` 맨 위, `npm test` 의 `--import`.
- 파이썬 검사(`python/test_*.py`)마다 첫 import 로 `python/_test_temp.py` — 같은 일을 한다.
  바로 앞 한 줄이 스크립트 폴더를 경로에 넣는다(내장 파이썬은 넣지 않는다).
- `src/shared/testTempRoot.contract.test.ts` 가 새 검사 파일이 이 줄을 빠뜨리면 울린다.

자식 프로세스(Electron·파이썬)는 부모의 폴더를 물려받아 쓰고(`AF_TEST_RUN_DIR`), 지우는 것은 만든 프로세스 하나다.
강제 종료로 남은 폴더는 다음 실행이 치운다 — 그 번호의 프로세스가 이미 없을 때만.
남겨 보고 싶으면 `AF_KEEP_TEST_TEMP=1` (폴더에 `.keep` 이 생겨 청소도 건너뛴다).

- 격리 userData: `_local/tmp/r<pid>/audioforge-e2e-userdata-<uuid>/`
- 격리 입력물: `_local/tmp/r<pid>/audioforge_e2e_<uuid>/`
- 화면 캡처·진단: `_local/artifacts/diagnostics/`

★이름을 `test-temp` 가 아니라 `tmp`, 실행 폴더를 `r<pid>` 로 짧게 둔 이유: 저장소 경로가 이미 79자다.
윈도우 경로 상한(260)까지 여유가 얼마 없다. 실행 폴더가 7자 안팎을 더 쓴다.

**실측(2026-09-28, 게이트가 도는 중)** — 임시 뿌리 94자, 가장 깊은 파일 205자, **여유 55자**.
옛 자리(시스템 임시, 33자)였다면 144자였다. 61자를 잃었지만 상한에는 닿지 않는다.
★저장소를 더 깊은 자리로 옮기면 이 여유가 먼저 바닥난다 — 옮길 때 이 숫자를 다시 잰다.

정리는 **반드시 `_e2e-helper` 의 함수로** 한다(`cleanupUserData`·`cleanupIsolated`).
prefix 와 부모 폴더를 확인하고, 연결(정션·심볼릭)이면 지우지 않는다.

★PowerShell 의 `Remove-Item` 을 임시 폴더 정리에 쓰지 않는다. 정션에 쓰면 **대상 안까지**
지운다(실측). Node 의 `rmSync` 는 연결을 따라가지 않는다.

★검사가 끝나도 남는 잔해가 쌓였다. 실패한 실행은 정리를 건너뛰고, 제 임시 폴더를 치우지 않는 검사도 많았다
(2026-09-30 실측: `_local/tmp` 4,812개 · 1.6GB, 단독으로 돌린 검사가 남긴 C 쪽 13,879개 · 570MB).
그래서 자리만 옮기는 것으로 끝내지 않고 **실행 단위로 통째로 지운다**(위).

★자리를 옮기기 **전**에 시스템 폴더에 쌓인 것은 스스로 사라지지 않는다.
설정 → 쌓인 것 비우기 → 중간 산출물이 우리 이름(`audioforge_`·`audioforge-`)만
골라 함께 치운다. 남의 파일은 개수조차 세지 않는다.

## 5. 저장소 안 `_local/`

개발 하네스가 쓰는 자리. 규칙은 `python/local_assets.py` 가 갖는다.
모델 가중치·데이터셋·실험 산출물이 섞여 있으므로 **한꺼번에 지우지 않는다.**

- `_local/tmp/` — 검사의 임시 자리. 여기만은 통째로 지워도 된다.
- `_local/artifacts/` — 화면 캡처·진단 묶음.

---

## 6. 하지 않는 것

- `resources/` 에 산출물을 만들지 않는다. 참고용 폴더다.
- 사용자 음원 폴더에 중간 산출물을 뿌리지 않는다. 결과만, 그것도 체크했을 때만.
- 앱이 만든 중간 산출물을 '원본' 으로 취급하지 않는다.
- 코드에 특정 PC 의 절대경로를 박지 않는다.
