# H3 긴 글 생성이 10분 30초에 끊기던 문제 — 2026-10-16

## 증상(사용자 신고)
많은 양의 글을 H3 로 만들면 진행 그래프가 움직이는데도 중간에 막혔다.
앱 기록: 21:35:10 시작 → 21:45:41 `JOB_STALLED: 합성이 630초 동안 한 조각도 진행하지 못했습니다 (완료 0조각)`.
21:50:17 다시 시작한 생성도 예측대로 22:00:48 같은 이유로 끊겼다.

## 원인 — 제한 세 곳
1. **화면 감시의 '조각 완료' 인식** (`src/main/services/longform-job.ts`). 그래프가 움직이는 신호는 '살아 있음' 일 뿐이고,
   630초(STALL_MS) 안에 '조각 완료' 가 와야 한다. 완료 판정은 낭독 모델 문구(`문장 s/n, 조각 c/m 완료`)만 읽는데,
   H3 는 `H3 생성 i/n · 단계/16` 만 보내 **완료가 한 번도 세어지지 않았다** → 진행 중이어도 630초에 무조건 끊김.
2. **상주 실행기 응답 대기** (`python/h3_resident_client.py`). 문장 하나 전체에 600초 고정 — 긴 문단은 진행 소식이 와도 10분에 끊김.
3. **전체 시간 예산** (`jobBudgetMs`). 조각당 300초는 '낭독 모델이 한 조각을 280초에 끊는다' 는 계약에서 나온 값. H3 에는 근거가 없다
   (H3 는 실제 길이의 약 10배 — 시험에서 조각당 8분이면 4조각째에 예산 초과로 끊겼다).

## 수정
- H3 가 조각 하나를 만들 때마다 `H3 생성 (문장 s/n, 조각 c/m 완료)` 를 보낸다(`h3_engine.py`). 문장 위치는 `tts_worker.py` → 상주 요청(`segment`) → 엔진.
- 상주 대기는 '마지막 소식 이후 600초' — 단계마다 소식이 오면 연장, 진짜 멈추면 600초에 끊는다.
- H3 위치를 본 작업만 조각당 예산을 STALL_MS(630초)로. 낭독 모델 예산·5분 무신호·630초 무진행 기준은 그대로.
- 결과: 조각이 계속 완성되는 한 긴 글도 끊기지 않고, 실제로 멈춘 경우는 지금처럼 잡힌다.

## 검증
- `longform-job.test.ts` 새 시험: H3 완료 문구 = 전진, 조각당 8분 × 4조각이 끝까지 감, 완료 없이 단계만 오면 여전히 무진행으로 잡힘, 낭독 모델 문구는 H3 예산을 쓰지 않음. 49건 통과.
- 파이썬 H3 시험 엔진 12·상주 10건 통과.
- 미확인: 실제 긴 글 H3 생성 끝까지(GPU 수십 분) — 사용자 다음 실행에서 확인. 조각 하나가 630초를 넘으면 여전히 끊긴다(170자 조각 기준 지금까지 그만큼 걸린 기록은 없음).
