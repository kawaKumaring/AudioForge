# Qwen 참조 재사용·반복 준비 보완 (2026-10-27)

## 목적과 확인 범위

사용자 요청: 주력 모델의 성능을 먼저 끌어올린다. 현재 경로를 코드로 확인하고 구현 후 관련 검사만 실행한다.
이번 변경은 Qwen 참조 준비·메모리 해제다. 실제 모델 생성, 사용자 자료 열기, 앱 실행, 다운로드는 하지 않았다.
모델 선택 기본값, 참조 자동 선택, 원문·발음 보정, 문장 분할, 생성 상한, 말끝 절단·연결, seed 정책은 바꾸지 않았다.

## 실제 구성과 시스템 연결

- Qwen Base 0.6B 기본 복제 경로, 설치된 1.7B Base 선택 경로가 있다.
- CustomVoice 0.6B/1.7B와 VoiceDesign 1.7B도 설치돼 있다. 참조 복제와 지정 화자 감정 지시는 같은 기능이 아니다.
- 카드/낭독 → tts_worker → 상주 qwen_voice_server → qwen_bridge.run_loaded → 조각 생성·발행.
- 고정 설계 목소리 → qwen_voice_server.Models.prompt → 공식 create_voice_clone_prompt → 생성.
- 상주 통로를 못 쓰는 경우 별도 프로세스 qwen_bridge.run_loaded 경로가 있다.
- 참조 길이 측정 → 분할 예산 → 생성 → 발행 근거의 codec 길이 확인. 이 두 확인에서 같은 오디오를 반복 인코딩했다.

## 발견과 수정

1. 고정 참조의 재사용 키가 경로·수정 시각뿐이었다. 전사가 달라지거나 시각을 유지한 파일 교체가 있으면 예전 특징을 사용했다.
   이제 모델·음원 SHA256·전사가 같을 때만 사용한다. 최근 사용 순서로 최대 8개만 보관한다.
2. 브리지 참조 캐시는 알 수 없는 옵션도 repr 문자열로 묶어 재사용했다. 주석의 우회 약속과 달랐다.
   이제 추가 옵션이 있으면 원래 함수로 보낸다. 인자를 추측해 합치지 않는다.
3. 기존 지문 계산은 음원 전체를 메모리에 읽었다. 공용 함수가 256KiB씩 읽도록 바꿨다.
   지문 계산 중 파일이 바뀌거나, 특징 준비 전후 내용이 다르면 새 특징을 저장·반환하지 않고 오류를 알린다.
   새 지문·대사를 디스크나 외부로 보내지 않는다.
4. 참조 프레임 캐시가 상주 실행의 다음 작업에도 남았다. 작업 진입 때 비우고 모델별로 구분한다.
   같은 작업 안에서는 분할 예산과 발행 근거가 실제 codec 프레임 측정을 재사용한다.
   시험용 측정 대역은 실제 발행 근거로 재사용하지 않는다.
5. 모델을 내릴 때 pop한 모델을 지역 변수가 계속 붙들었다. 참조 캐시를 비운 뒤 지역 참조를 지우고
   순환 참조도 정리한 다음 CUDA 캐시를 비운다. 새 모델을 열기 전에 수행한다.

## 구현 후 관련 검사

- 새 참조 재사용 17건: 전사 변경, 동일 시각·크기 파일 교체, 동일 내용 다른 경로, 모델 구분,
  최근 사용 순서·상한, 준비 실패, 파일 누락·변경, 모르는 옵션 우회, 순환 참조 모델 해제,
  반복 codec 인코딩 1회, 요청 사이 초기화 등.
- 기존 상주 실행기 15건, 참조 예산 10건, controlled-prefix 11건, 단계 시간 기록 11건.
- 최종 고유 사례 합계 64건 통과. 전체 검사·GPU 생성·앱 청취는 하지 않았다.
- 첫 검사에서 새 지문 비교가 Windows Python 3.12의 handle/path ctime 차이를 파일 변경으로 오판했다.
  파일 동일성 비교는 장치·파일 식별자·크기·수정 시각으로 하고, 내용은 매번 SHA256으로 확인하도록 수정했다.
- 발행 근거에서 시험용 길이 대역까지 재사용되던 실패도 발견해 실제 codec 경로와 분리했다.
  영향을 받은 검사만 재실행해 통과했다. 기존 검사에 열린 파일 경고와 pynvml 폐기 예정 경고는 남아 있다.

## 증거와 한계

- 가짜 codec으로 같은 작업의 반복 길이 확인 3회가 실제 encode 1회로 줄어드는 것을 검증했다.
- 순환 참조가 있는 가짜 모델이 다음 모델 로더 호출 전에 해제되는 것을 검증했다.
- 실제 GPU 메모리 절감량·첫 소리 시간·전체 생성 시간은 측정하지 않았다. 속도 개선 초 단위를 주장하지 않는다.
- 실제 음질·참조 닮음 보존은 새 생성·청취 전이므로 합격으로 판정하지 않는다.
- 참조 지문 확인과 특징 준비가 끝난 직후 외부 프로그램이 파일을 바꾸는 것까지 잠그지는 않는다.
  실행 중 입력 파일을 외부에서 수정하지 않는 기존 전제를 유지한다. 작업 중 codec 프레임 기록도 같은 전제다.
- 별도 프로세스의 조각별 참조 특징 재계산 자체는 이번에 바꾸지 않았다. 추가 최적화는 측정 후 판단한다.

## 다음 판단

1. 정상 청취 판정된 Qwen 기준과 같은 조건으로 실제 0.6B/1.7B 선택·참조 방식 기록 확인.
2. GPU가 비었을 때 첫 요청·상주 후 반복 요청의 준비/생성 시간을 구분해 측정.
3. 생성 결과 경로를 제공하고 말끝·발음·인물 닮음을 청취로 확인.
4. 한국어 참조 감정이 부족할 때 VoxCPM2, GPU 독립 낭독이 필요할 때 CPU 후보를 별도 비교.
