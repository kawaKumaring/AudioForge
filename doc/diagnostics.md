# 로그 파일과 진단 묶음

문제가 났을 때 화면 캡처 대신 건네는 것. 2026-09-17 까지 앱은 파일에 아무것도 남기지 않았고,
"안 된다" 를 전달할 길이 캡처밖에 없었다. 캡처는 이름표 없이 밖으로 나가 지울 수 없다.

## 로그 파일 — 어디에, 무엇이

- 위치: 사용자 폴더 안 **데이터 폴더의 `logs\` 아래**, 파일 이름은 `audioforge-YYYY-MM-DD.log`.
  하루 한 파일, 14일 지나면 지운다.
  ★데이터 폴더 이름은 **어느 빌드를 쓰느냐에 따라 다르다**(2026-09-17 부터) —
  정식은 `%APPDATA%\audio-forge`, 개발선은 `%APPDATA%\audio-forge-dev`.
  둘은 서로 아무것도 주고받지 않는다.
  **지금 쓰는 빌드가 어느 폴더를 쓰는지 확인하는 법**: 로그의 `[boot] 데이터 폴더 …` 줄,
  또는 진단 묶음 `summary.txt` 의 `data:` 줄을 본다. 짐작하지 말고 그것을 따른다.
  ★예전에 이 문서는 정식 폴더 하나만 적어 두었다. 개발선 사용자가 그대로 따라가면
  **정식 빌드가 남긴 다른 날 로그**를 보게 되고, 그것을 자기 기록으로 읽는다.
- 한 기록은 한 줄로 시작한다: `시각 수준 [꼬리표] 내용`. 여러 줄(오류 스택)은 뒷줄을 4칸 들여 쓴다.
- 적히는 것
  - `boot` — 기동(앱 판·electron·node·플랫폼)과 종료.
  - `job` — 작업 시작(`mode`, 실행 번호, **파일 이름만**), 끝(걸린 시간), 오류(코드·정제된 메시지), 취소.
  - `console` — main 과 화면(renderer)의 `console.warn` / `console.error`. `console.log` 는 적지 않는다
    (파이썬 진행 출력이 그 길로 흐른다 — 양이 많고 내용을 통제할 수 없다).
  - `uncaught` — main 의 잡히지 않은 예외. monitor 로만 봐서 Electron 의 오류 대화상자는 그대로 뜬다.
  - `diagnostics` — 진단 묶음을 만든 사실.
- **적지 않는 것**: 대사·전사 본문, 사용자 음원의 폴더 경로(이름만 적는다). 이 규칙은 호출부의 책임이고
  `src/main/services/app-log.ts` 머리에 적혀 있다.
  ★`console.error` 로 흘러온 메시지도 **폴더 경로를 지우고** 적는다(2026-09-24).
  예전에는 그대로 남아서, ffprobe 가 한 번 실패한 날의 로그에 사용자 음원의 절대 경로가
  실렸고 **그 로그가 진단 묶음에 통째로 복사돼 밖으로 나갔다.**
  지금은 (1) 오류를 만드는 자리에서 이름만 남기고, (2) 로그에 적을 때 한 번 더 씻고,
  (3) 진단 묶음을 만들 때 다시 한 번 씻는다. 파일 **이름**은 남긴다 — 무엇이 실패했는지는
  알아야 진단이 된다. 그래서 **파일 이름에 인물 이름을 쓰면 그것까지는 막지 못한다.**
- 로그는 앱을 멈추지 못한다. 쓰기 실패는 조용히 삼킨다(그 대신 기록이 비어 있다). 하루 파일이 20MB 를 넘으면
  그 사실을 한 줄 남기고 그 날은 더 쓰지 않는다.

## 진단 묶음 — 어떻게 만들고, 무엇이 들어가나

시작 화면 맨 아래 판 표시 밑의 **'진단 묶음 내보내기'** 를 누른다. 폴더를 고르면 그 안에
`AudioForge_진단_YYYYMMDD-HHmmss/` 가 생기고 탐색기가 그 폴더를 보여 준다.

- `summary.txt` — 앱 판·커밋·빌드 시각, 실행 환경(플랫폼·electron·node·파이썬 있음/없음),
  **설정 파일의 모양**(키 이름과 개수·글자 수만, 값은 한 글자도 없음), 묶은 로그 목록.
- `logs/` — 최근 3일의 로그 파일. 복사하면서 **폴더 경로를 지운다**(파일 이름은 남긴다).
- 들어가지 않는 것: 설정 값(대사·마지막 폴더 포함), 사용자 음원·생성본·참조 클립.

화면은 결과를 한 줄로만 말한다(묶음 폴더 이름과 로그 개수). 경로는 화면에 오지 않는다.

## 검증

- 단위: `src/main/services/app-log.test.ts`(10), `diagnostics-bundle.test.ts`(6) — 실제 파일로 눌러 본다.
  특히 묶음의 **모든 파일**을 읽어 심어 둔 대사·폴더 값이 없는지 본다.
- 실제 앱: `test/e2e/diagnostics-export.e2e.mjs`(17) — 기동 로그, 화면 오류가 파일에 닿는가, 단추 → 묶음 생성,
  값 없음. 게이트 `verify:ui` 에 들어 있다.

## 아직 아닌 것

- 작업 화면(파일을 연 뒤)에는 단추가 없다. 시작 화면으로 돌아와 누른다.
- 파이썬 워커의 stdout/stderr 는 파일에 남지 않는다. 필요해지면 **작업 단위 꼬리(마지막 N줄)** 만 오류 때
  붙이는 쪽이 맞다 — 전부 남기면 대사가 섞일 수 있다.
- 합성(qwen) 의 실행 기록(run bundle)은 이 로그와 별개다. 서로 가리키지 않는다.
