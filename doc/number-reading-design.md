# 숫자 읽기 보정 — 코드 설계안 (2026-10-09, 관리자 승인 전)

상태: 설계만. 코드는 아직 바꾸지 않았다. 승인 후 구현한다.

## 근거와 범위
- 근거는 서수 비교 실험 하나(대사 1개, 참조 1개, seed 42)다. "7번째"는 "칠 일 번째"로 잘못 읽었고 "일곱 번째"는 정상이었다. "5번째"와 "다섯 번째"는 둘 다 정상.
- 따라서 **"숫자+번째"(서수)만** 바꾼다. 모든 숫자를 일괄 변환하지 않는다.
- 이번에 바꾸지 않는 것: 날짜·시각·금액·소수·전화번호·식별자, 그리고 "7개"·"3명" 같은 수량. 같은 문제가 있을 수 있지만 근거가 없다.

## 원문과 발음용 텍스트 분리
- 원문: 화면 표시, 강조 위치, 저장, 기록의 기준. 바꾸지 않는다.
- 발음용: 엔진에만 넘긴다. 이미 같은 구조가 있다.
  - 낭독: `speakableText`(src/shared/readerText.ts:121)가 구절마다 발음용 글을 만든다.
  - 카드: `say_text = strip_spoken_symbols(line_text)`(python/tts_worker.py:4327). `line_text`가 기록 기준이다.
- 보정은 이 두 자리에서, 기호 정리 바로 뒤에 한 번 더 거친다.

## 변환 규칙 (ordinal-v1)
- 대상: 앞에 숫자·소수점·쉼표·콜론·영문자가 붙지 않은 1~99 정수, 뒤에 공백 0~1개와 "번째"가 오는 경우.
- 1~99를 고유어 관형형으로 바꾼다.
  - 1~9: 첫·두·세·네·다섯·여섯·일곱·여덟·아홉
  - 10~19: 10은 열, 11은 열한, 12는 열두, …
  - 20은 스무. 21부터는 스물한, 스물두, … 같은 방식.
  - 30 서른, 40 마흔, 50 쉰, 60 예순, 70 일흔, 80 여든, 90 아흔
- 결과는 "일곱 번째" 형태다. "1번째"는 "첫 번째"가 된다.
- 바꾸지 않는 경우: 100 이상, "3.5번째", "2-7번째", "A7번째", 전각 숫자. 원문 그대로 둔다.

## 적용 위치 — 한 규칙을 두 언어로
- 새 쌍을 만든다: `src/shared/spokenNumbers.ts`와 `python/spoken_numbers.py`.
  - 기존 `speechSymbols.ts`와 `speech_symbols.py`처럼, 같은 사례표를 두 쪽 검사가 함께 읽어 규칙이 서로 어긋나지 않게 한다.
- 낭독: `speakableText` 안에서 구절별로 적용한다.
  - 구절별로 바꾸므로 강조 시간 계산용 가중치(발음 글자 수)가 자동으로 맞는다.
  - 합친 뒤의 문자열(`say`)에 적용하면 가중치가 어긋나므로 그렇게 하지 않는다.
- 감정 구간: 감정 구간 텍스트(캐시 열쇠에 들어감)에도 같은 함수를 적용한다.
- 카드: `tts_worker.py`의 `say_text` 한 곳. 모든 엔진이 여기를 지난다.
  - Qwen의 긴 글 나누기(text_segmenter)는 이후 단계라 영향이 없다.
- 설정 단추는 만들지 않는다.
  - 이유: 실험에서 바꾼 표기("다섯 번째", "일곱 번째")가 모두 정상이었다. 끄는 선택지를 둘 근거가 없고, 옵션이 늘어나는 것을 피한다.

## 생성 기록
- 카드 기록(manifest)에 다음을 추가한다.
  - `spoken_normalizer: "ordinal-v1"`
  - `spoken_changes: 개수`
  - `spoken_text_sha256`
- 원문은 기존처럼 비공개 기록에만 둔다.
- 낭독 관측 기록(reader_trace)에는 덩이마다 정규화 판 이름과 바꾼 개수만 남긴다. 본문은 남기지 않는다.
- 품질 검수 MCP와 이어지도록, 기록에서 원문 해시와 발음용 해시를 둘 다 볼 수 있게 한다.

## 캐시 구분
- 낭독 캐시 이름은 `sha256(목소리 키 + 발음용 본문)`이다(src/main/ipc/reader.ipc.ts:54).
  - 발음용 글이 바뀌면 열쇠도 저절로 바뀐다. "7번째" 시절의 캐시가 새 결과로 잘못 쓰이지 않는다.
  - 서수가 없는 덩이는 열쇠가 그대로라 기존 캐시를 계속 쓴다. 불필요한 재생성이 없다.
- 규칙을 나중에 바꿀 때(v2)도 바뀐 글이 열쇠에 들어가므로 따로 판 번호를 열쇠에 넣지 않는다.
  - 판 번호는 기록에만 남긴다.
- 참조 전사 캐시는 참조 음성 기준이라 영향이 없다.

## 검사 (구현 때)
- 사례표, 두 언어 공통:
  - 바꾸는 것: 1, 7, 10, 11, 20, 21, 99, "7 번째"
  - 그대로 두는 것: 100, 3.5, "A7", "2024번째", 문장 안 여러 개
- 낭독: 구절 가중치와 강조 위치가 원문 기준으로 유지되는지. 캐시 이름이 서수 있는 덩이에서만 달라지는지.
- 카드: 기록에 판 이름, 바꾼 개수, 해시가 남는지. `line_text`가 바뀌지 않는지.
- 청취: 다른 대사와 다른 seed 여러 개로 소수 합성한다. 사용자 청취로 판정하며, 자동 전사 일치는 합격으로 치지 않는다.

## 구현 범위 (승인 대상)
- 새 파일 2개(규칙 쌍), 사례표 1개, 검사 2개.
- 기존 파일 수정 3곳: readerText.ts(speakableText 안), reader.ipc.ts(감정 구간·trace), tts_worker.py(say_text와 기록 필드).
- 화면, 설정, 엔진, 모델은 바꾸지 않는다.
