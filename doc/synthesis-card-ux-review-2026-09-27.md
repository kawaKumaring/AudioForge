## 새로 재현한 우선 결함 — Claude에게 전달

### 1. 기본 목소리와 생성 당시 정보가 저장 왕복에서 빠진다

실제 `serializeWork → JSON → parseSavedWork → hydrateWork`를 메모리 fixture로 실행했다. 사용자 설정 파일이나 음원은 변경하지 않았다.

```
beforeVoice: builtin
restoredVoice: none
beforeTakeVoice: true
restoredTakeVoice: false
takesRemaining: 1
beforeAppliedReference: { clip: 'clip.wav', region: { start: 2, duration: 4 } }
restoredAppliedReference: null
```

`cardSynthesis.ts`의 직렬화/복원과 `synthesisCardSave.ts`의 저장 형식/파싱을 모두 확인해야 한다. 기본 목소리와 생성본의 voice가 왕복하지 않고, 실제 적용 참조 구간도 복원에서 빠진다. 기존 전체 검사 통과와 별개인 실제 재현이다.

재현 스크립트: `C:\Users\kawae\Documents\Codex\2026-09-26\new-chat\outputs\AudioForge-card-persistence-repro.mjs`

실행: `node "C:\Users\kawae\Documents\Codex\2026-09-26\new-chat\outputs\AudioForge-card-persistence-repro.mjs"`

수정 요구:

1. 기본 목소리 종류·엔진·모델·언어·화자 식별과 실제 모델 경로가 저장/보관/복원에서 유지돼야 한다. 모델이 사라지면 지정 모델 불가로 표시하고 자동 대체하지 않는다.
2. 생성본 voice와 applied.reference를 복원까지 보존한다. 기존에 기록되지 않은 적용값을 기본값으로 지어내지 않는다. 현재 hydrateWork의 기본값 채움도 함께 검토한다.
3. 생성 요청 시작 시 job에 voiceSnapshot을 고정한다. 현재 setJob에는 voice가 없고 acceptCardResult는 현재 카드로 대체할 수 있다. UI 잠금만을 근거로 결과 시점의 설정을 과거 기록에 넣지 않는다.
4. 파서 단위 검사뿐 아니라 실제 앱에서 기본 목소리 선택 → 생성본 → 종료 → 재시작 → 명시 복원 검사를 추가한다. source만 있는 fixture는 이 결함을 잡지 못한다.
5. 현재/보관 작업 양쪽, 기존 참조 카드 저장본, 파일이 없는 결과, 기록 없는 옛 생성본을 함께 검사한다.

이번 Codex 수정은 GUI와 복제·수정 전 판정까지만이다. 이 저장 경로는 Claude 담당 기능 연결로 남겨 두었으며 고쳤다고 보고하지 않는다. 재시작을 포함한 카드 전체 완성으로 간주하지 않는다.

### 2. 옛 작업 가져오기 구현 순서

위 저장 결함 수정 후 `labWorkspace`부터 시작한다. 기존 문서와 오디오는 그대로 두고 별도 카드 작업 사본을 만든다. 현재 카드 작업은 보관해 유지한다.

- 줄 순서·대사·take·채택을 보존. 채택이 없던 줄을 임의로 채택하지 않는다.
- 미지원 설정은 출처 기록에 보존하고 적용 여부를 구분. silenceGap을 joins.gap으로 옮기지 않는다.
- 생성 당시 source/settings/applied를 현재 작업 값으로 채워 과거 기록을 만들지 않는다. 필요하면 저장 스키마와 화면의 '기록 없음' 처리를 함께 확장한다.
- source 길이는 실제 파일로 확인. 참조 파일 부재와 생성본 파일 부재를 구분해 실패/부분 가져오기 정책을 명시한다.
- 중복 가져오기를 구분할 출처 식별과 가져오기 요약을 마련하되, 새 공용 화면을 붙이기 전에 계약을 보고한다.
- 여러 배역 workDrafts는 다음 단계. 기존 파서가 확인한 발화 순서·명시/상속 배역·구간·쉼을 보존할 방법부터 합의한다. 정규식 줄 분할로 대체하지 않는다.

옛 버전 제거 조건: 저장 왕복 결함 해결, 가져오기 손실/미지원 항목 확인 가능, 필요한 기존 기능의 대체 경로 확보, 실제 사용자가 새 카드로 기존 작업을 이어갈 수 있음. 현재는 옛 버전을 유지한다.
