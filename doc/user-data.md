# 사용자 데이터 폴더 — 정식과 개발선을 나눈다

## 왜

2026-09-17 까지 master 빌드와 develop 빌드가 **같은** `%APPDATA%\audio-forge` 를 썼다. 한쪽이 바꾼 설정
모양을 다른 쪽이 그대로 읽어 조용히 되살리는 일이 실제로 있었다("되살리기" 사건의 배경). 판이 다른 두 앱이
한 설정 파일을 번갈아 쓰는 구조는 어느 쪽 검사로도 잡히지 않는다.

## 규칙

- **정식(Stable)·RC·알 수 없는 접미사** → `%APPDATA%\audio-forge`. **바뀌는 것이 없다.**
- **개발선(`-dev`)** → `%APPDATA%\audio-forge-dev`.
- 개발선 폴더가 처음이면(설정 파일이 없고 표식도 없으면) 정식 폴더의 **앱 데이터만 한 번 복사**한다:
  `settings.json`, `reference-library/`, `refclips/`, `lab-takes/`, `emotion-sampler-cache/`.
  Electron 캐시(Cache·Code Cache·GPUCache·Session Storage…)는 옮기지 않는다 — 실측 192MB 중 187MB 가
  그것이고 앱이 다시 만든다. 앱 데이터 본체는 5MB 미만이었다.
- **원본(정식 폴더)은 읽기만 한다.** 복사한 사실은 개발선 폴더의 `seeded-from.json` 에 남는다(폴더 이름·시각·
  복사/건너뜀 목록. 절대 경로 없음).
- 두 번째 실행부터는 아무것도 하지 않는다. 설정을 지웠어도 표식이 있으면 다시 복사하지 않는다(지운 뜻을 존중).
- **그 뒤로 두 폴더는 따로 간다.** 동기화·되돌리기는 없다. 개발선에서 만든 목소리·생성본은 정식 폴더에
  나타나지 않고, 그 반대도 같다.
- 채널 판정은 `currentBuildInfo().version`(package.json 이 권위)이다. `app.getVersion()` 은 package.json 을
  못 찾는 실행에서 Electron 판을 돌려주므로 쓰지 않는다.
- 로그(`logs/`)와 진단 묶음은 실제로 쓰는 폴더 안에 생긴다. 기동 기록에 `데이터 폴더 audio-forge-dev` 처럼
  이름이 남고, 진단 묶음 `summary.txt` 에도 `data:` 줄로 적힌다.

## 이 변경이 사용자에게 뜻하는 것

지금 매일 쓰는 것이 develop 빌드라면, 이 판을 처음 띄울 때 **기존 데이터가 개발선 폴더로 복사되어 그대로
이어진다**(목소리·참조·생성본). 그 시점부터 정식 폴더는 멈춘 사진이 된다. 나중에 정식 빌드로 옮겨 가면 그
사이 개발선에서 한 작업은 거기 없다 — 그때는 폴더를 손으로 옮기거나, 정식 판을 낸 뒤 개발선 폴더를 정식으로
이어 쓰는 절차가 필요하다(**아직 없다**, 아래).

## 검증

- 단위 `src/main/services/user-data-channel.test.ts`(7): 이름 규칙, 앱 소유 항목만 복사·캐시 제외·원본 지문 불변,
  두 번째 실행 무동작, 표식만 있어도 무동작, 원본 없음, 같은 폴더, 항목 목록 고정.
- 실제 앱 `test/e2e/user-data-channel.e2e.mjs`(14): `AF_E2E_USER_DATA_BASE` 로 부모 폴더를 바꿔 두 번 기동 —
  폴더 생성·복사·캐시 제외·표식·로그 위치·정식 폴더 지문 불변·재기동 무복사. 게이트 `verify:ui` 등록.

## 아직 아닌 것

- 정식 판을 낼 때 개발선 폴더를 정식으로 **이어 쓰는 절차**(반대 방향 복사)가 없다.
- 두 폴더가 갈라진 뒤 어느 쪽이 최신인지 화면이 말해 주지 않는다(기동 기록·진단 요약에만 이름이 있다).
- 정식 폴더가 없고 개발선만 있는 새 PC 는 빈 개발선 폴더로 시작한다(설계대로).
