# 목소리 정보의 소유 경계 — B안 (2026-09-17 확정)

사용자 결정: **"일반·고급 한 명·고급 여러 명의 첫 인물은 불러온 목소리를 공유하고,
여러 명에서 추가한 다른 목소리는 일반과 고급 한 명에 영향을 주지 않는다."**
(대안 A — 세 곳 완전 분리 — 는 한 명↔여러 명이 같은 대본을 본다는 계약을 깨야 해서 택하지 않았다.)

## 경계 (이 문서가 계약이다)

    불러온 파일(고급의 기본 목소리, 클립 자리 'default')
      ├─ 고급 한 명 → 그대로 쓴다
      └─ 고급 여러 명 첫 인물 → **복사해서** 이어받는다(자리 'spk:<이름>'). 이후 독립.
    고급 여러 명 2번 이후 인물 → 각자 자리 'spk:<이름>'. 기본 목소리·일반에 영향 없음.
    일반(작업실) → 자기 대본·자기 목소리·자기 설정·자기 자리 'lab'. 고급과 무관.

- **클립 자리(clipKey) 하나당 폴더 하나.** 새로 확정하면 같은 자리의 이전 폴더가 지워진다.
  그래서 **화면이 다르면 자리 이름도 달라야 한다.** 이 규칙을 어긴 것이 9/16 결함(일반이 고급 클립 삭제)이었다.
- 고급 한 명과 여러 명은 **같은 대본(원문)** 을 본다. 여러 명의 인물은 그 대본의 화자 표기에서 나온다.
  한 명은 화자 표기를 무시한다. 이 계약은 유지한다.

## 왜 문제가 됐나 (실사용, 2026-09-16~17)

1. 일반과 고급이 같은 자리('default')를 써서 **일반이 고급의 목소리 파일을 지웠다.** → 자리 분리로 해결.
2. 파일을 열면 **이전 작업이 조용히 되살아났다**(대본·인물·방식). 옛 인물 셋이 돌아왔는데 화면은
   무엇이 돌아왔는지 말하지 않았고, 사용자는 방금 지정한 한 명만 생각했다. → 되살리기 알림 + '새로 시작'.
3. 일반의 목소리 준비가 "불러온 파일과 같은 파일일 때만" 돌던 시제품 잔재. → 조건 제거.

## 이번에 한 것

- 일반의 준비 조건에서 "불러온 파일과 같을 때" 를 뺐다. 일반은 자기 목소리를 스스로 준비한다.
- 파일을 열어 이전 작업이 되살아나면 **"이 파일의 이전 작업을 되살렸습니다 — 인물 N명 · 대사 N줄 · 방식"**
  을 보이고 **[그대로 쓰기] [새로 시작]** 을 준다. 새로 시작은 대본·인물·방식을 비우고 **그 파일의 기록만**
  지운다(다른 작업 기록·목소리 파일 자체는 건드리지 않는다). 자동 저장은 기록을 지우지 못한다 — 지우는 길은 이것뿐.
- 경계를 화면 검사로 못 박았다: 여러 명에서 인물을 더하고 지워도 고급 기본 목소리·일반은 변하지 않는다.

## 하지 않은 것 (남은 판단)

- 세션 복원(이전 결과 폴더의 `session.json` 으로 "복원" 을 **누르는** 길)은 사용자가 고르는 동작이라 그대로 뒀다.
- 클립 파일이 사라졌는데 상태가 "준비됨" 으로 남는 구조는 그대로다(지우는 원인만 막았다).
- 목소리 준비가 화면 구성(어느 패널이 떠 있는가)에 얹혀 있는 구조 자체는 정리하지 않았다.
