# 대화 분석 — pyannote Community-1 연결 준비 (착수 전)

상태: **막혀 있음 — 사용자 행동이 필요하다.** 설치·다운로드·동의·계정 생성은 하지 않았다.
기존 엔진은 그대로다. 이 문서는 **연결 지점**과 **막힌 정확한 항목**만 적는다.

## 지금 막혀 있는 것 (이 장비에서 확인)

공식 페이지: <https://huggingface.co/pyannote/speaker-diarization-community-1>

- 모델이 **접근 조건 수락이 필요한 상태**다 — 조회한 메타데이터의 `gated` 값이 `auto`.
- 이 장비의 환경에 **Hugging Face 토큰이 없다**(`HF_TOKEN` / `HUGGING_FACE_HUB_TOKEN` 모두 없음).
- 공식 안내가 요구하는 것: ① 모델 페이지에서 이용 조건 수락 ② `hf.co/settings/tokens` 에서
  접근 토큰 생성.

**둘 다 계정과 약관 동의가 필요한 일이라 대신 하지 않았다.** 조회는 공개 메타데이터만 읽었고
가중치는 내려받지 않았다.

### 사용자가 해야 하는 일 (그 외에는 아무것도 필요 없다)
1. 위 모델 페이지에서 **접근 조건 수락**.
2. 접근 토큰 생성 후 이 장비에서 쓸 수 있게 두기(예: 환경변수 `HF_TOKEN`).

그 뒤에 아래 "연결 계획" 을 별도 작업으로 진행한다. **Precision-2 클라우드 API 로 대체하지
않는다** — 사용자 음성을 외부로 보내지 않는다.

## 현행 결과와 Community-1 결과의 연결 지점

현행(자체 파이프라인)이 내는 것:

    화자 구간 = [{start, end, speaker}]          ← python/conversation_worker.py
      · 프레임 argmax 마스킹으로 만든 **hard label** 이다(겹침 개념이 없다).
      · 같은 값이 제품 결과(`dialogueSegments`)와 진단 sidecar 두 곳으로 나간다.
      · 화면의 '대화 구간 수정' 과 `dialogue-rebuild` 재구성이 **이 모양 하나**만 본다.

Community-1 이 내는 것(공식 문서):

    output.speaker_diarization            ← 일반 diarization. **겹침 구간이 있을 수 있다.**
    output.exclusive_speaker_diarization  ← 한 시점에 한 화자만. 전사 시간과 맞추기 쉽다.

**연결 지점은 하나다.** 새 엔진의 결과를 위의 `[{start, end, speaker}]` 로 바꿔 주면, 화면의
구간 수정과 `dialogue-rebuild` 재구성이 **그대로** 동작한다. 두 결과를 이렇게 나눠 쓴다.

- **트랙 재구성·구간 수정에는 `exclusive_speaker_diarization` 을 쓴다.** 한 시점에 한 화자만
  있어야 구간을 떠서 트랙에 배정하는 일이 말이 된다.
- **겹침 정보(`speaker_diarization` 에서만 보이는 구간)는 따로 표시한다.** 같은 목록에 섞지
  않는다 — 섞으면 어느 것이 배타적 결과인지 알 수 없게 된다.

### 표시 규칙 (이것을 어기면 안 된다)
- **겹침 구간을 찾았다는 것은 겹친 목소리를 갈라냈다는 뜻이 아니다.** 지금 재구성은 원본
  구간을 화자별 트랙에 **배정**할 뿐이고, 새 엔진을 붙여도 그 성질은 달라지지 않는다.
  화면 문구는 현재와 같은 기준을 지킨다.
- **기존 엔진 대비 정확도 향상률을 쓰지 않는다.** 같은 자료로 직접 비교한 근거가 없다.
- **새 엔진을 기본값으로 삼지 않는다.** 고를 수 있는 경로로만 붙이고, 기본은 현행 엔진이다.

## 연결 계획 (동의·토큰이 준비된 뒤)

1. **격리 환경.** `pyannote.audio` 는 torch 를 끌고 온다. 앱 파이썬은 ComfyUI 내장 파이썬이라
   섞지 않는다 — faster-whisper 때와 같이 `externals/` 아래 전용 venv 를 만든다.
   호환이 불명확하면 **무리한 설치나 소스 빌드로 확대하지 않고 그 사실만 보고한다.**
2. **로컬 경로 적재.** 가중치를 받은 뒤에는 로컬 절대경로로만 적재하고 실행 중 자동 다운로드를
   막는다(faster-whisper 와 같은 규칙).
3. **장치 기록.** 실제 사용 장치를 기록하고 **몰래 CPU 로 바꾸지 않는다.** 실패는 사유와 함께
   그대로 올린다.
4. **선택 경로.** 대화 모드에 실행 방식 선택을 하나 둔다(기본은 현행 엔진). 텍스트 추출의
   '실행 방식' 과 같은 모양이다.
5. **후속 UI 는 이미 있다.** 구간 듣기·화자 배정 수정·경계 수정은 이번에 만들었고, 배정 수정
   때문에 모델을 다시 돌리지 않는다. 새 엔진을 붙여도 그 화면을 그대로 쓴다.

## 이번에 하지 않은 것

- 모델 다운로드, 로그인, 약관 동의, 계정 생성 — 전부 하지 않았다.
- 설치(venv 생성 포함) 없음. 기존 대화 분석 엔진·가중치 미변경.
- 정확도 비교 수치 없음(직접 비교 근거가 없다).
