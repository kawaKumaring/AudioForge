# TTS 표현·세부 조절 UI 정보구조 연구 (Phase 1)

> 담당: 에이전트 C (expression UX / IA)
> 브랜치: `research/tts-expression-ux` (origin/develop `b933ab5` 분기)
> 성격: **연구·설계·합성 목업 전용.** production UI 코드·스키마·의존성 변경 없음. 이 문서 + 합성 wireframe/mock 파일만 커밋한다.
> 작성일: 2026-08-23
> 선행 근거: `doc/research/tts-prosody-control.md`(C, Base 한계·제어 2축), `doc/work-in-progress/tts-prosody-integration-contract.md`(A/B/통합 계약).

이 문서는 현재 TTS 화면의 정보 밀도·중첩 토글을 감사하고, 화면을 **목소리 / 대사 / 표현 / 합성** 4흐름으로 재구성하는 정보구조(IA)와 세부 조절·도움말·프리셋·접근성 설계를 제시한다. **구현이 아니라 설계**이며, Agent A(대사 문법)·Agent B(오디오/pause 계약)의 산출을 소비하는 지점을 명시적으로 플래그한다.

---

## 0. 핵심 요약 (먼저 읽기)

- 현재 TTS 화면은 **최상위 접이식 섹션 5개 + 그 안의 재귀 토글**로 정보 밀도가 매우 높다. 특히 `TTSEditor.tsx`는 634줄 단일 컴포넌트로 목소리·감정·전사·대사·고급설정을 한 파일에 담고, "고급 설정" 안에 엔진·속도·간격·음높이가 다시 접혀 있으며, "감정별 음성 등록" 안에 등록/미등록/구간 패널이 **3중 중첩**된다.
- 4흐름(목소리→대사→표현→합성)으로 나누면 각 단계가 "지금 무엇을 하는가"를 명확히 하고, 중첩 토글을 요약 배지 + 별도 관리 패널로 평탄화할 수 있다.
- **세부 조절은 "사용 켜기(enable)"와 "펼치기(expand)"를 분리**한다. 접혀 있어도 적용값 요약을 항상 보이게 한다.
- **현재 실제 지원되는 값만 활성화**한다: pitch / speed / 문장 간격 / 감정 전환 간격 / 말끝 다듬기 / 끝 여백. formant / brightness / breathiness / 가성 강도는 **가짜 슬라이더로 노출하지 않는다** (Base 모델·현 파이프라인이 못 함).
- 가성/여성적/남성적 인상은 **pitch만으로는 부분적으로만** 가능하고 크게 밀면 화자 유사도가 깨진다. UI 표현은 `남성↔여성`이 아니라 **`낮고 묵직함 ↔ 높고 가벼움`** 축으로 프레이밍한다.
- 제어를 **생성축(재합성 필요)**과 **빠른 후처리축(재합성 불필요)**으로 시각적으로 구분해, 사용자가 "이 변경이 다시 합성을 부르는가"를 항상 알 수 있게 한다.

### 1.3 중첩 토글 목록 (평탄화 대상)
- `showEmotionSetup` (`:22`) — 감정 등록 섹션 전체.
- `collapsedRefs[id]` (`:34`) — 등록 감정 **항목별** 구간 패널.
- `showUnregistered` (`:32`) — 미등록 감정 목록.
- `showRefPrompts` (`:25`) — 참조 전사 섹션.
- `showAllTags` (`:31`) — 감정 태그 더보기.
- `showAdvanced` (`:30`) — 엔진/속도/간격/음높이 묶음.
→ 최상위에서만 **접이식 5개**, 그 안에 항목별 토글이 다시 열린다. 사용자는 "음높이를 어디서 바꾸지?"를 찾으려면 **고급 설정을 펼쳐야** 하고(발견성 낮음), 감정 참조 구간을 확정하려면 **감정 섹션 > 항목 > 구간 패널** 3단을 열어야 한다.

### 1.4 세부 조절 관련 관찰
- 음높이 슬라이더(`:585-628`)는 이미 capability 게이팅·중앙 눈금·후처리 설명·미지원 사유 표시가 잘 되어 있다(재사용 자산). 단 **"고급 설정" 안에 숨어** 발견성이 낮다.
- 속도·간격·음높이는 **enable/expand 개념이 없다**. "고급 설정"을 펼치면 항상 세 슬라이더가 다 뜨고, 접으면 **적용값 요약이 사라진다**(예: speed 1.2x로 둔 채 접으면 화면에 흔적이 없음). → 요구 9(접었을 때 적용값 요약) 미충족.
- 옵션 컴포넌트(`Options.tsx`)는 TTS에선 쓰이지 않지만(App:170 분기), **접었을 때 활성 옵션 미리보기**(`Options.tsx:54-61`) 패턴은 좋은 선례 — TTS 표현 요약에 그대로 차용 가능.

### 1.5 도움말·용어 현황
- 도움말은 전부 `title=` 툴팁(`:540, :564, :577, :593`)에 의존 — **키보드/스크린리더 접근 불가**, 마우스 호버로만 뜬다.
- 라벨 옆 현재값은 슬라이더 우측 숫자로만 존재(예 `:568` 속도 값). 접으면 사라짐.
- 요구 6(라벨+현재값 항상 노출, ⓘ 한 문장 도움말, 자세히 보기, 전역 `설정 설명 표시`)은 현재 **전혀 없음**.

## 2. 4흐름 IA 제안 (목소리 / 대사 / 표현 / 합성)

현재의 "블록 6개 세로 스택"을 **여정 순서의 4단계 흐름**으로 재배치한다. 각 단계는 카드 헤더 + 한 줄 상태 요약을 항상 보여주고, 세부는 그 안에서 편다.

```
[1] 목소리   → 참조 음성(기본) + 감정 음성 요약 배지 [관리]
[2] 대사     → (도구 바: 감정·쉼 삽입) + 대사 편집기
[3] 표현     → 프리셋 4종 + 세부 조절(enable/expand) + 적용값 요약
[4] 합성     → 엔진 요약 + 준비 상태 + [음성 합성 시작]
```

### 2.1 [1] 목소리 (Voice)
"이 목소리로 말하게 한다"를 정하는 단계. **화자 정체성**에 관한 모든 것.
- 기본 참조 음성 패널(`ReferenceRegionPanel default`) — 위치 유지.
- **감정별 음성**은 긴 등록 토글 대신 **한 줄 요약 + [관리]**로 축약(§3). 예: `감정 음성 2개 등록됨 · 준비 1 · 확정 필요 1  [관리]`.
- 참조 전사(현 `showRefPrompts`)는 이 단계의 **[관리] 패널 안**으로 흡수(화자 정체성 보조라 대사·표현과 섞지 않는다).

### 2.2 [2] 대사 (Script)
"무엇을 말하는가". 대사 편집기가 주인공.
- **편집기 바로 위에 도구 바**: 감정 태그 삽입 + **쉼(pause) 삽입**(§5). 현재 태그 삽입은 편집기 *아래*(`:489-523`)에 있어 삽입 흐름이 역방향 — **위로 이동**.
- 대사 편집기(현 textarea `:475-488`) 유지.
- 문장 수·미입력 경고(현 `:470-472`)는 편집기 헤더에 유지.

### 2.3 [3] 표현 (Expression)
"어떤 톤·속도·높낮이로 말하는가". **여기가 이번 사이클의 신규 핵심.**
- 상단: **기본 프리셋 4종**(원본 / 낮고 차분하게 / 중성적으로 / 밝고 가볍게, §7).
- 그 아래: **세부 조절** — `세부 조절 사용` enable 스위치 + 펼치기(§8). 지원 6항목만 활성(§9).
- 접혀 있어도 **적용값 요약 배지**를 항상 노출(§8.3).
- **생성축/후처리축 배지**로 각 컨트롤이 재합성을 부르는지 표시(§11).

### 2.4 [4] 합성 (Synthesize)
"실제로 만든다".
- 엔진 선택은 기본 접힌 요약(`자동 · Qwen3 준비됨`)으로, 펼치면 5택(현 `:540-555`).
- Qwen preflight 상태 줄(현 `:201-219`)을 이 단계로 이동(합성 직전 맥락).
- `ProcessButton`(별도 컴포넌트) — 준비 필요 사유·게이팅 그대로.

### 2.5 흐름 카드의 공통 규칙
- 각 카드 헤더: **번호 · 이름 · 한 줄 상태 요약**을 항상 표시(접힘 여부와 무관).
- 카드는 순차적이되 **강제 마법사는 아님**(자유 스크롤). 단 미완 단계는 헤더 요약에 `준비 필요`를 rose로 표기.
- 최대 폭 720px 유지, 좁은 창에서 세로로 안전하게 접힘(§14).

## 3. 감정 관리 패널 스펙 (긴 등록 토글 → 요약 + [관리])

### 3.1 요약(collapsed) 표현
현재 `TTSEditor.tsx:222-240`의 "감정별 음성 등록" 헤더 + 배지 4종을 **목소리 카드의 한 줄**로 축약:

```
감정 음성 2개 등록됨 · 준비 1 · 확정 필요 1 · 대사에서 사용 2      [관리]
```
- 0개면: `감정 음성 없음 (대사의 [감정] 태그는 기본 참조로 합성)  [감정 음성 추가]`
- 집계는 현 로직 재사용: `registeredCount/readyCount/needsConfirmCount/usedCount`(`:160-165`).

### 3.2 [관리] 패널(모달 또는 확장 영역) — 열별 정보
현재 감정 항목 한 줄(`:270-295`)이 담는 정보를 **표 형태의 관리 뷰**로 정리한다. 각 등록 감정 행(row):

| 열 | 소스 | 비고 |
|---|---|---|
| 감정명 | `emotion.label`(색상 dot 포함) | `:279` |
| 등록 상태 | `준비됨`(cyan) / `확정 필요`(rose) / `대사에서 사용` 배지 | `slot.ready` `:282-285`, `usedIds` `:281` |
| 참조 길이 | 확정 구간 길이 또는 원본 길이(초) | region.duration 또는 analysis.duration_sec |
| 미리듣기 | ▶ 버튼(구간 재생) | `ReferenceRegionPanel.playRegion` 재사용 |
| 변경 | 파일 다시 선택 | `handleEmotionFile` `:286-290` |
| 삭제 | 제거 | `removeEmotionRef` `:291-294` |

- 행을 펼치면 그 감정의 `ReferenceRegionPanel`(구간 확정 파형) + 참조 전사 편집이 인라인으로 열린다(현 3중 중첩을 **패널 1단 안의 행 확장**으로 평탄화).
- "미등록 감정 추가"(현 `:316-354`)는 이 패널 하단의 `+ 감정 추가` 드롭다운/그룹 선택으로.
- **참조 길이는 반드시 3~10초 게이트를 시각화**(`ReferenceRegionPanel` MIN/MAX_SEC `:10-11`) — 관리 뷰에서 한눈에 "확정 필요" 원인을 보이게.

### 3.3 접근성
- 관리 뷰가 모달이면 focus trap + `Esc` 닫기 + 복귀 포커스. 확장 영역이면 `aria-expanded` + 헤더로 포커스 이동.
- 각 행의 상태 배지는 색상만이 아니라 **텍스트 라벨 병기**(색맹 대비).

## 4. 감정·쉼(pause) 삽입 도구 — 대사 편집기 위 배치 (Agent A 의존)

### 4.1 배치
- 현재 감정 태그 삽입 UI는 편집기 **아래**(`TTSEditor.tsx:489-523`). → **편집기 위 도구 바**로 이동(삽입은 커서 위치 기준이므로 위/아래 무관하나, "먼저 도구를 보고 → 입력"이 자연스러움).
- 도구 바 2그룹:
  1. **감정**: 자주 쓰는 태그(`FREQUENT_TAGS`) + `더보기`(현 `showAllTags` `:499-522`). 삽입 로직 `insertEmotionTag`(`:85-106`) 재사용 — 커서/선택 위치 삽입 + 줄 단위 적용 이미 구현됨.
  2. **쉼(pause)**: 짧게/보통/길게(또는 `[쉼]`·`[쉼=0.5s]` 형태) 삽입 버튼.

### 4.2 Agent A 의존 (문법) — ⚠️ 계약 필요
쉼 삽입은 **대사 문자열에 무엇을 써넣는가**의 문법을 Agent A가 소유한다. C(UI)는 그 문법의 **소비자**다. 다음을 A로부터 받아야 확정 가능:
- **쉼 마크업 토큰 형태**: 예 `[쉼]` / `[pause]` / `[쉼=0.5]` / `<0.5>` 중 무엇인지, 인자(초/등급) 유무.
- **감정 태그 문법의 정본**: 현재 `[기쁨]` 한글 라벨을 텍스트에 넣고 `parseUsedEmotionIds`(`:6`,`:156`)가 역파싱한다. A가 문법을 재정의하면(예 라벨↔id, 인라인 vs 줄단위) 삽입 도구·역파싱·미리보기가 함께 바뀐다.
- **삽입 단위**: 줄 단위(현 `insertEmotionTag`의 `needNL` 규칙 `:94`)를 유지하는지, 인라인 span을 허용하는지.
- **미리보기/검증**: 잘못된 마크업(닫히지 않은 태그 등) 표시를 A가 파서 레벨에서 제공하는지, UI가 자체 검증하는지.

C는 A의 문법이 확정되기 전까지 **삽입 버튼의 시각/배치만** 설계하고, 실제 삽입 문자열은 A 계약에 바인딩한다.

## 5. 설정 도움말 구조 (요구 6)

현재 `title=` 툴팁 의존(§1.5)을 **4계층 도움말 모델**로 교체한다.

### 5.1 계층
1. **라벨 + 현재값 항상 노출** — 접힘 여부와 무관하게. 예: `속도  1.2x`, `음높이  +1.0반음`, `말끝 다듬기  켬`. (현재는 접으면 사라짐 → 항상 보이게.)
2. **ⓘ 한 문장 도움말** — 라벨 옆 작은 ⓘ 버튼. 클릭/포커스 시 **한 문장** 설명을 인라인 노출(툴팁이 아니라 실제 텍스트 → 키보드·스크린리더 접근 가능). 예 음높이: "재합성 없이 결과 음성의 높낮이만 반음 단위로 보정합니다."
3. **자세히 보기** — ⓘ 옆 `자세히` 링크. 펼치면 2~3문장 + 주의(예: "크게 올리면 다른 사람 목소리처럼 들릴 수 있어요").
4. **전역 `설정 설명 표시` 토글** — 표현 카드 헤더(또는 전역 설정)에 스위치. 켜면 모든 ⓘ 한 문장 설명이 **기본 펼침**으로 상시 노출(입문자 모드), 끄면 아이콘만(숙련자 모드). 상태는 store에 영속.

### 5.2 문구 원칙 (계약 §8 + 아티스트 친화 메모리 준수)
- 후처리 축은 "재합성 없이 결과에 적용"을 명시.
- **금지**: "AI가 문맥 읽고 감정 연기", "텍스트로 감정 지시"(Base 불가, §10·계약 §8).
- formant 등 내부 옵션명 노출 금지 — "자연스러움 우선"으로.
- 용어: pitch=음높이 보정(반음), speed=속도, pause=문장 간 간격/쉼.

## 6. 기본 프리셋 4종 (요구 7)

표현 카드 상단에 **원본 / 낮고 차분하게 / 중성적으로 / 밝고 가볍게** 4버튼. 프리셋은 **후처리 축 값의 묶음**(생성축을 건드리지 않음 → 재합성 불필요).

- **원본**: pitch 0 · speed 1.0 · 말끝 다듬기 끔 · 끝 여백 기본. (= reset)
- **낮고 차분하게**: pitch 약간 -(예 -1.0) · speed 약간 느리게(0.95) · 문장 간격 약간 김.
- **중성적으로**: pitch 0 근처 · speed 1.0 · 미세 정리만.
- **밝고 가볍게**: pitch 약간 +(예 +1.0) · speed 약간 빠르게(1.05) · 문장 간격 약간 짧게.

주의(연구 근거, §10·`tts-prosody-control.md §4`):
- 프리셋 pitch 폭은 **±1~2 반음 이내**로 보수적으로(유사도 보호). 확정 수치는 계약 §4 표를 초기값으로 하되 **블라인드 평가 전까지 가설**로 표기.
- 프리셋 이름을 **감정이 아니라 톤(낮고/밝고)**으로 둔 것은 의도적 — Base가 "감정 연기"를 못 하므로 신호 톤 조정임을 정직하게 표현.
- 프리셋 선택 후 사용자가 세부 슬라이더를 만지면 프리셋 배지는 `사용자 지정`으로 바뀐다(프리셋=시작점).

## 7. `세부 조절 사용`(enable) vs 펼치기(expand) 분리 (요구 8·9)

현재는 "고급 설정" 하나가 enable과 expand를 겸해(펼치면 항상 활성, 접으면 흔적 없음). 둘을 분리한다.

### 7.1 두 컨트롤
- **enable 스위치 `세부 조절 사용`**: 끄면 프리셋 값만 적용(슬라이더 무시), 켜면 세부값이 프리셋을 덮어씀. **끈 상태로 접어도** "프리셋: 밝고 가볍게"가 표현 카드에 남는다.
- **expand 토글(펼치기)**: 세부 슬라이더 UI의 표시/숨김만. enable과 독립 — 켜고 접을 수도, 끄고 펼쳐 미리 볼 수도 있다.

상태 조합:
- enable off + collapsed → 프리셋 요약만.
- enable off + expanded → 슬라이더가 **비활성(회색)**으로 보이되 프리셋 값이 표시(미리보기).
- enable on + collapsed → **적용값 요약 배지**(§7.3).
- enable on + expanded → 슬라이더 조작 가능.

### 7.2 근거
- pitch 게이팅과 충돌 없음: enable과 무관하게 pitch capability 게이트(계약 §7, `ProcessButton.tsx:182-185`)는 유지. enable off여도 프리셋의 pitch가 0이 아니면 capability 게이트가 걸릴 수 있으므로, **프리셋 pitch는 capability 미지원 시 0으로 강등하고 사유 표시**(조용한 무시 금지).

### 7.3 접힌 상태 적용값 요약 (요구 9)
`Options.tsx:54-61`의 "활성 옵션 미리보기" 배지 패턴을 차용. 접혀도 표현 카드 헤더에:
```
표현: 밝고 가볍게 · 음높이 +1.0 · 속도 1.05x · 말끝 다듬기 켬        [펼치기]
```
- 값이 기본(원본)인 항목은 배지에서 생략해 노이즈를 줄인다.
- 후처리/생성 축 배지(§11)도 함께.

## 8. 지원 vs 미구현 컨트롤 목록 (요구 10·11 — 핵심)

### 8.1 지금 활성화할 값 (실제 지원 — 근거 있음)
아래만 슬라이더/스위치로 노출한다. 각 항목은 config 또는 metadata에 **실측 근거**가 있다.

- **pitch(음높이 보정, 반음)** — `ttsConfig.ts:117` `ttsPitch`, Python `pitch_shift`(계약 §2.1·§7), metadata `pitch_semitones/pitch_method/pitch_postprocessed`(`tts_worker.py:810`). capability 게이트 필수(`ProcessButton.tsx:182`). **후처리 축.**
- **speed(속도)** — `ttsConfig.ts:116` `ttsSpeed`, atempo 후처리, metadata `speed/speed_postprocessed`(`tts_worker.py:807`). **후처리 축.**
- **문장 간격(silence_gap)** — `ttsConfig.ts` `ttsSilenceGap`, metadata `silence_gap`(`tts_worker.py:807`). 문장 경계 무음. **후처리 축(결합 단계).**
- **감정 전환 간격** — 현 `silence_gap`은 문장 경계에만 적용(`tts_worker.py:1021-1030`, 내부 chunk는 0). "감정이 바뀌는 줄 경계"에 다른 간격을 주는 것은 **Agent B의 pause 계약 확장 여부에 의존**(§12). B가 별도 필드를 열면 활성, 아니면 문장 간격에 흡수. → **B 의존, 조건부.**
- **말끝 다듬기 / 끝 여백** — 문장 끝 페이드/트림·말미 무음 여백. 이는 **결합/후처리 단계의 신호 처리**로, 현재 코드에 독립 필드가 **없음**. Agent B의 오디오 후처리 계약에서 필드가 열려야 활성(§12). → **B 의존, 현재 미배선.**

> 정정 주의: 요구 10은 이 6항목을 "현재 지원"으로 활성화하라 하지만, 실측상 **완전히 배선된 것은 pitch/speed/문장 간격 3개**뿐이다. `감정 전환 간격`·`말끝 다듬기`·`끝 여백`은 **Agent B가 후처리 필드를 열어야** 실제 동작한다. UI는 이 3개를 **B 계약에 바인딩된 플레이스홀더**로 설계하고, 필드 미제공 시 "준비 중"으로 비활성(가짜 활성 금지). 이 사실을 A/B 통합 계약에 반드시 반영한다(§12·§15).

### 8.2 절대 노출하지 않을 값 (미구현 — 가짜 슬라이더 금지)
아래는 **Base 모델·현 파이프라인이 못 하는 것**이다. 슬라이더/입력으로 노출하면 사용자를 속인다.

- **formant(포먼트) 독립 조절** — 현재 pitch는 `rubberband ... formant=preserved`(계약 §7)로 **포먼트 보존만** 한다. 포먼트를 *독립적으로 밀거나 당기는* 별도 컨트롤은 파이프라인에 없다. 노출 금지.
- **brightness(밝기/음색 EQ)** — 신호 EQ 후처리가 파이프라인에 없음. 노출 금지.
- **breathiness(숨소리)** — 음색 합성 파라미터. Base가 텍스트/신호로 제어 못 함(`tts-prosody-control.md §2`). 노출 금지.
- **가성 강도(falsetto strength)** — 성구(register) 전환은 모델 생성 특성이지 후처리 신호가 아님. Base·후처리 어느 쪽도 "가성 강도" 노브를 제공하지 않음. 노출 금지(§10).

이들은 UI에서 **아예 없어야** 한다(회색 비활성으로도 넣지 않는다 — "언젠가 될 것"이라는 오해 방지). 필요하면 별도 "실험/로드맵" 문서에만.

## 9. 가성·여성적·남성적 인상 연구 (요구 12 — 정직한 능력·위험 프레이밍)

근거: `doc/research/tts-prosody-control.md`(Base 한계·pitch/formant 상호작용)와 계약 §7(rubberband formant=preserved 실측).

### 9.1 pitch만으로 되는 것 / 안 되는 것
- **되는 것(부분)**: 반음 단위 pitch 시프트로 **전체 음높이 인상**을 낮거나 높게 옮길 수 있다. rubberband `formant=preserved` 덕에 소폭(±1~2반음)에서는 "같은 사람이 조금 낮/높게 말한다"에 가깝게 유지된다.
- **안 되는 것**: pitch는 **성별 인상의 본질(포먼트 분포·성구·호흡·억양 곡선)**을 바꾸지 못한다. "여성적/남성적으로 바꿔줘"를 pitch만으로는 만들 수 없다. 크게 밀수록(±3반음 초과) **포먼트가 틀어져 "다른 사람/기계음"**이 되고 화자 유사도가 급락한다(`tts-prosody-control.md §3.2`).

### 9.2 독립 formant 제어가 필요한가?
- 성별 인상 전환에는 **pitch + formant를 함께** 옮겨야 자연스럽다(성도 길이 시뮬레이션). 즉 "진짜 성별 전환"에는 독립 formant 제어가 이론상 필요하다.
- 그러나 현재 파이프라인은 **formant 보존만** 지원(독립 이동 아님). formant 독립 제어를 추가하면:
  - 저품질 시 금속성/모음 왜곡("도날드덕") 위험.
  - **화자 유사도 훼손이 크다** — 원 화자 음색이 무너져 voice-clone의 의미가 약해진다.
- 결론: **독립 formant 노브를 지금 UI에 넣지 않는다**(§8.2). 성별 전환은 "pitch 미세 조정"의 한계로 정직하게 표현하고, 진짜 필요하면 **다른 참조 음성(생성축)**을 쓰라고 안내한다.

### 9.3 참조-기반 접근 (권장 주 수단)
- 낮고 묵직한/높고 가벼운 인상을 **제대로** 원하면, 그 인상의 **참조 음성 자체를 그런 목소리로** 고르는 것이 정공법(생성축). pitch 후처리는 그 위 **미세 보정**.
- 감정 참조 시스템(§3)이 이미 "감정별 다른 참조"를 지원하므로, 같은 메커니즘으로 "톤별 참조"도 가능(단 화자 유사도는 참조에 종속).

### 9.4 로컬-DSP 접근 (후처리)
- pitch(rubberband) = 이미 있음. formant-shift도 rubberband가 이론상 가능하나(품질/라이선스·GPL 이슈 계약 §7), **유사도 훼손 위험** 때문에 노출을 보류.
- 로컬 DSP로 얻는 것은 "낮게/높게" 표층 신호뿐 — **성별의 지각적 본질은 못 만든다**는 점을 UI 문구가 넘지 않게.

### 9.5 UI 프레이밍 (`남성↔여성` 금지 → `낮고 묵직함 ↔ 높고 가벼움`)
- pitch 슬라이더의 양 끝 라벨/도움말을 **`낮고 묵직함 ↔ 높고 가벼움`**으로. `남성적/여성적`은 쓰지 않는다(성별 고정관념·과장·불가능 암시 회피).
- 한 문장 도움말: "결과 음성의 높낮이만 반음 단위로 보정합니다. 크게 옮기면 다른 사람 목소리처럼 들릴 수 있어요."
- "성별을 바꾼다"는 표현·기능은 **제공하지 않는다.**

### 9.6 위험 요약 (timbre-damage / speaker-similarity)
- ±1~2반음: 유사도 대체로 보존(1차 안전 범위, 가설·평가 필요).
- ±3반음 초과: 포먼트 왜곡·유사도 급락 — **1차 상한 ±2~3반음**을 슬라이더 max로(현 UI는 -2~+2 `TTSEditor.tsx:594`, 보수적이라 유지 권장).
- pitch+speed 동시 최대 금지(다람쥐 효과, `tts-prosody-control.md §3.3`) — UI에서 조합 경고.

## 10. 생성축 vs 빠른 후처리축 구분 (요구 13)

계약 §0의 2축을 **UI에 시각적으로** 반영한다. 사용자가 "이 변경이 다시 합성을 부르는가"를 항상 알게.

### 10.1 축 분류
- **생성축(재합성 필요)** — 바꾸면 모델을 다시 돌린다:
  - 감정 참조 음성(등록/변경/구간 재확정), 참조 전사/모드(ICL↔x-vector), 언어, 엔진, **대사 텍스트 변경**.
  - metadata 근거: `actual_engine`, `prompt_source`, `x_vector_only_mode`, `target_language`(`tts_worker.py:803-807`).
- **빠른 후처리축(재합성 불필요, 빠른 재처리 후보)** — 생성 WAV에 신호 처리:
  - pitch, speed, 문장 간격, (B가 열면)감정 전환 간격·말끝 다듬기·끝 여백.
  - metadata 근거: `speed_postprocessed`, `pitch_postprocessed`, `silence_gap`.
  - 주의: "빠름"은 재합성보다 빠르다는 뜻이지 **즉시/실시간이 아니다**(WAV 길이·CPU 의존, 계약 §0). UI 문구도 "즉시" 대신 "재합성 없이".

### 10.2 UI 표현
- 각 컨트롤/카드에 작은 배지: **`재합성`**(rose 계열) vs **`빠른 재처리`**(cyan 계열).
- 표현 카드(§2.3)는 전부 후처리축 → 카드 레벨에 `재합성 없이 적용` 배지.
- 대사·목소리·엔진 변경은 생성축 → 변경 시 "다시 합성해야 반영됩니다" 안내.
- **미래 여지(개념만, 이번 구현 아님)**: 결과가 나온 뒤 후처리축만 바꿨다면 "빠른 재처리"(모델 재실행 없이 마지막 WAV에 재적용) 버튼을 줄 수 있다. 단 이는 **raw/최종 WAV 보관 정책**(`tts-prosody-control.md §6.1`)이 필요하고 B 파이프라인 계약이 열려야 함 → **needs-more-research**(§15).

## 11. 반응형 · 접근성 고려 (요구 14)

### 11.1 반응형 (800×600 / 일반 창 / 125%·150% 배율)
- 최대 폭 720px(`App.tsx:98`) 유지. 800×600에서 좌우 여백 40px가 과하면 좁은 창에서 `padding` 축소(예 24→16px) 반응형 분기.
- 표현 카드의 슬라이더 행은 현 `flex: 1 1 200px + flexWrap`(`TTSEditor.tsx:558-560`) 패턴 계승 → 넓으면 3열, 좁으면 1열로 안전 접힘.
- 125%·150% 배율(Electron zoom / OS 스케일): px 고정 폰트(10~13px)가 확대되면 좁은 창에서 줄바꿈·overflow 위험. **고정 height(예 textarea 140px, waveform 72px)를 min-height로** 완화, 배지 줄은 `flexWrap` 필수.
- 감정 관리 뷰가 모달이면 작은 창에서 **뷰포트 높이 초과 시 내부 스크롤**(`overflow-y:auto`) — 파형/전사가 잘리지 않게.
- 가로 스크롤 금지: 긴 파일명은 이미 ellipsis(`:280`,`:400`) 처리됨 — 패턴 유지.

### 11.2 키보드
- 모든 접이식 헤더는 `<button>`(현 구조 유지) → Tab/Enter 동작. `aria-expanded` 추가 필요(현재 없음).
- 프리셋·enable 스위치·ⓘ·자세히 링크 전부 실제 focusable 요소로.
- 슬라이더는 `input[type=range]`(현재 그대로) → 화살표 키 조작 가능. focus-visible 링 이미 있음(`globals.css:205-208`).
- 감정 삽입 도구 바는 버튼 그룹 → 방향키 roving tabindex 고려(선택).
- 모달 관리 뷰: focus trap + Esc.

### 11.3 스크린리더
- **툴팁(`title=`) 의존 제거**(§5) — ⓘ 도움말을 실제 텍스트로 노출해야 SR이 읽는다.
- 상태 배지(준비됨/확정 필요)는 색+텍스트 병기(현재 텍스트 있음 — 유지).
- 슬라이더에 `aria-label` + `aria-valuetext`(현 `ReferenceRegionPanel.tsx:256-257`가 좋은 선례) — 표현 슬라이더에도 동일 적용(값+단위 읽기).
- 적용값 요약 배지 영역은 `aria-live="polite"`로 값 변경 알림(과도하지 않게).
- 준비/오류 카드는 이미 `role="status"/"alert"`(`ProcessButton`, `ReferenceRegionPanel`) — 표현/관리 패널에도 동일 원칙.
- `prefers-reduced-motion` 존중(현 `globals.css:223-232`) — 새 전환도 이 가드 안에.

## 12. 소유 파일 / 공유·충돌 파일 / A·B 의존성 + 필요한 필드

### 12.1 C(표현 UX)가 소유(구현 단계에 수정 예정)할 파일
- `src/renderer/components/TTSEditor.tsx` — 4흐름 재구성의 주 대상(현재 634줄 → 흐름별 분할 권장).
- (신규 제안) 흐름별 컴포넌트 분리: `VoicePanel` / `ScriptPanel` / `ExpressionPanel` / `SynthesizePanel` + `EmotionManagePanel`(§3) — TTSEditor 비대화 해소.
- `src/renderer/stores/app.store.ts` — 표현 프리셋 선택·`세부 조절 사용`·`설정 설명 표시` 등 UI 상태 추가(단, 이 파일은 B도 소유 → **충돌 파일**, §12.3).
- `src/renderer/styles/globals.css` — 새 배지/도움말 스타일(공유, 저충돌).

### 12.2 공유(읽기/계약 소비만, C가 직접 수정 안 함)
- `src/shared/ttsConfig.ts` — **통합 브랜치 소유**(계약 §9). C는 필드를 **요청**만 하고 직접 수정하지 않는다.
- `src/renderer/components/ProcessButton.tsx` / `TtsResultInfo.tsx` — 게이팅·결과 표시. C의 표현값이 여기로 흐르지만 수정 소유는 통합/기존 배선. C는 요약 표시 요구만 제기.
- `python/tts_worker.py`, `python/separate.py` — 읽기 전용(능력 근거 확인용). C는 수정하지 않는다.

### 12.3 충돌 위험 파일 (같은 사이클에 여러 에이전트가 만짐)
- **`src/renderer/stores/app.store.ts`** — C(표현 상태) + B(감정 참조/클립 수명, 계약 §9)가 동시 수정. 병합 순서·필드 네임스페이스를 통합 계약에서 합의 필요.
- **`src/renderer/components/TTSEditor.tsx`** — C(4흐름) + B(감정 참조 UX)가 겹친다. **B의 감정 참조 로직을 C의 [1]목소리/[관리] 패널로 이관**하는 협의 필수. 분할 컴포넌트로 나누면 충돌 표면이 줄어든다.
- **대사 문법(Agent A)** — 삽입 도구·역파싱(`parseUsedEmotionIds`)이 A 문법에 종속(§4).

### 12.4 Agent A(대사 문법)로부터 필요한 것 — ⚠️ 계약 의존
- 쉼(pause) 마크업 토큰 문법(형태·인자).
- 감정 태그 문법 정본(라벨↔id, 줄단위 vs 인라인).
- 잘못된 마크업 검증/미리보기 API(파서 제공 여부).
- 삽입 문자열을 A 문법에 바인딩 — C는 버튼 UI만, 삽입 payload는 A 계약값.

### 12.5 Agent B(오디오/pause 계약)로부터 필요한 것 — ⚠️ 계약 의존
- **감정 전환 간격 / 말끝 다듬기 / 끝 여백**의 실제 후처리 필드(config 키·범위·기본값·단위). 없으면 UI는 "준비 중" 비활성(§8.1).
- 이 필드들의 metadata 반영 키(적용 여부 표시용, `speed_postprocessed`류 패턴).
- pause가 문장 경계 외(줄/감정 경계)에도 적용되는지 — `silence_gap` 현 동작(`tts_worker.py:1021-1030`)의 확장 여부.
- (미래) 후처리축 "빠른 재처리"를 위한 최종/ raw WAV 보관 여부(§10.2).

### 12.6 통합 브랜치에 요청할 config/session/metadata 필드
- **config(`ttsConfig.ts`)**: 표현 프리셋 식별자(선택), `세부 조절 사용` 플래그, (B 제공 시)감정전환간격/말끝다듬기/끝여백 값. — 통합/B가 스키마 확정.
- **session(재현)**: 위 표현값 + 프리셋 선택 + `설정 설명 표시` 토글을 session 스냅샷에 저장/복원(현 `RestorableSession.options` 패턴 `app.store.ts:33-56` 확장). pitch/speed/silenceGap은 이미 복원됨(`app.store.ts:369-372`).
- **metadata(결과 표시)**: 신규 후처리 필드의 `*_postprocessed`류 키(TtsResultInfo가 "적용됨/없음" 표시). pitch/speed는 이미 있음(`tts_worker.py:807-810`).

## 14. 구현 가능(now) vs 추가 연구 필요(needs-more-research)

### 14.1 지금 구현 가능 (근거·배선 확실)
- 4흐름 IA 재구성(목소리/대사/표현/합성) — 순수 렌더러 재배치.
- 감정 등록 토글 → 요약 + [관리] 패널(§3) — 기존 store/IPC 재사용.
- 감정·(감정)태그 삽입 도구 편집기 **위**로 이동 — 기존 `insertEmotionTag` 재사용(단 쉼 문법은 A 대기).
- 표현 프리셋 4종(후처리축 값 묶음) + enable/expand 분리 + 접힘 요약 — pitch/speed/문장간격 기반.
- 도움말 4계층(라벨+값 상시 / ⓘ 한 문장 / 자세히 / 전역 설명 토글) — 툴팁 의존 제거.
- 생성축/후처리축 배지 — metadata 근거 확실.
- 반응형·a11y 보강(aria-expanded, aria-valuetext, 툴팁 제거, 모달 focus trap).

### 14.2 추가 연구·계약 필요
- **가성/성별 전환** — pitch만으론 불가, 독립 formant는 유사도 훼손 위험으로 보류. "다른 참조 사용" 안내로 우회. formant 노출은 **금지 유지**(§8.2·§9).
- **감정 전환 간격 / 말끝 다듬기 / 끝 여백** — **Agent B 후처리 필드 계약이 열려야** 활성. 그전엔 UI 플레이스홀더(비활성). (요구 10이 "지원"으로 표현했으나 실측상 미배선 — 통합 계약에서 정정 필요.)
- **쉼(pause) 삽입** — **Agent A 문법 확정** 후 삽입 payload 바인딩.
- **빠른 재처리 버튼**(결과 후 후처리만 재적용) — raw/최종 WAV 보관 정책(`tts-prosody-control.md §6.1`) + B 파이프라인 필요. 이번 범위 밖.
- **프리셋 수치 확정** — §6·계약 §4 표는 가설. `tts-prosody-control.md §5` 블라인드 평가로 좁혀야 확정.
- **감정 전환 경계 정의** — "감정이 바뀌는 줄"의 판정은 A 문법(태그 위치)과 B 간격 필드의 합의 필요.
