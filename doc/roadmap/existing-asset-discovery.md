# 후속 과제 — 설치 전 기존 자산 탐색·재사용

상태: **기록만**(미구현). 현재 진행 중인 "앱 전용 환경 설치·연결"의 완료 조건과 범위는 그대로 둔다.

## 배경
지금 설치기는 내부 자산이 없으면 곧바로 내려받아 앱 전용 환경에 넣는다. 그러나 이 PC처럼 ComfyUI·기존
venv·HF 캐시가 이미 있는 환경에서는 같은 모델을 두 번 받게 된다. 설치 **전에** 재사용 가능한 자산을
찾아보면 시간·디스크·대역폭을 아낄 수 있다.

## 아이디어
내부 자산이 없을 때, 설치 전에 **알려진 로컬 경로·캐시·사용자 지정 폴더**에서 재사용 가능한 모델과
실행 도구를 탐색한다.

## 구현 원칙(합의됨)
- **모델은 버전·해시를 검증한 뒤에만 재사용**한다. 실행 도구는 호환성을 검증한 뒤 재사용한다.
  파일 이름이나 존재만으로 "쓸 수 있다"고 판정하지 않는다.
- 외부 자산은 **junction 이 아니라 설정의 경로 참조**로 연결한다.
  (링크는 이번 사고처럼 재귀 삭제가 대상까지 지우는 경로가 된다.)
- **외부 venv 의 패키지를 파일 단위로 가져오거나 링크하지 않는다.** 환경은 통째로 참조하거나 쓰지 않는다.
- **앱 소유 자산과 외부 자산을 구분**해 기록하고, 외부 자산은 **수정·업데이트·삭제하지 않는다**(읽기 전용).
- 재사용 불가하거나 아예 없는 항목만 앱 전용 환경에 설치한다.
- **사용자 동의 없는 전체 디스크 탐색 금지.** 알려진 후보 경로와 사용자가 지정한 폴더만 본다.

## 탐색 후보(예시, 구현 시 확정)
- HuggingFace 캐시(`~/.cache/huggingface/hub`), 앱이 아는 기존 externals, 사용자가 설정에서 지정한 폴더.
- 도구류(ffmpeg 등)는 PATH 존재 여부가 아니라 실행·버전 확인으로 판정.

## 이 과제가 답해야 할 것
1. 어떤 자산을 "동일하다"고 볼 것인가(모델 repo+revision+파일 해시 / 도구 버전 범위).
2. 외부 자산이 나중에 사라지거나 바뀌었을 때 앱이 어떻게 감지하고 무엇을 할 것인가.
3. 재사용과 설치가 섞인 상태를 사용자에게 어떻게 보여줄 것인가(무엇이 앱 소유이고 무엇이 빌린 것인지).
