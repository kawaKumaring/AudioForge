# 낭독 리더 GUI 인수인계

사용자 요청: 새 콘텐츠 만들기에 책을 읽어주는 플레이어의 GUI를 먼저 구성. 엔진과 상세 적용은 Claude 담당.

## 구현한 화면
- ModeSelector `reader` → App → ReaderWorkspace. 기존 공유 음원 실행 UI와 분리.
- 빈 화면의 어두운 TXT 드롭존, 여러 파일 추가, 책 목록, 선택한 책 본문.
- 문단 선택·이전/다음 문단·글자 크기, 목소리 선택 팝업.
- 재생 버튼은 하단 중앙. 엔진 미연결이므로 비활성, 실제 재생처럼 움직이는 타이머 없음.
- 책과 위치·글자 크기·목소리 표시값은 renderer 메모리에 유지. 메뉴 왕복 보존, 앱 재시작 복원 없음.
- UTF-8 TXT, 파일당 10MB 한도. 다른 인코딩·빈 파일·읽기 실패는 표시. 원본 수정 없음.

## Claude가 연결할 것
1. 기본 목소리 실제 조회 및 선택 ID. 현재 기본 목소리는 UI 표시값뿐이며 설치 확인을 의미하지 않음.
2. 참조 음성 선택은 현재 이름만 보관. 실제 경로·참조 준비·모델 계약 연결 필요. 이 표시값을 합성 입력으로 쓰지 말 것.
3. 장문을 합성 단위로 나누되 원문 문자 위치와 대응 보존. 지금 문단은 표시용이며 음성 분할 규칙이 아님.
4. 모델 상주, 다음 구간 미리 준비, 재생/일시정지/오류/버퍼링, 파일 끝 다음 책 진행.
5. 시작 위치와 실제 낭독 위치를 구분. 현재 하이라이트는 사용자 선택 위치, 청취 완료 진도가 아님.
6. 책별 읽던 위치·책 목록의 영속 보관과 명시 복원. 무제한 본문을 settings 한 칸에 넣지 말고 관리 파일로 설계.
7. 기존 공용 음량·재생 소유권·GPU 실행 잠금 참여. reader를 기존 audio:process 분리 모드로 그대로 보내지 말 것.
8. 취소·책/목소리 변경·문단 이동 시 늦은 생성 결과 폐기. 캐시는 본문/목소리/설정 지문으로 구분.
9. 큰 책은 가상 목록 또는 창 단위 렌더링 적용. 현재 본문은 GUI 초안으로 전체 문단 렌더링.
10. 브라우저 File 입력을 Electron 파일 선택/드롭 경로와 연결하고 UTF-16/CP949 인코딩 대응 결정.

## UX 유지
생성 카드를 독자에게 노출하지 않는다. 장황한 설명은 툴팁, 오류는 짧게 표시.
배속·취침 타이머·자동 따라가기는 실제 연결 때 추가하되 현재 불필요한 비활성 옵션은 나열하지 않음.
기본 재생 흐름을 구현한 뒤 실제 초기 대기와 합성/재생 속도를 측정한다. 실시간이라는 보장은 하지 않음.

기존 measure-read-aloud-speed.mjs와 연기 편집기 작업은 수정하지 않았다.
