# TTS 표현 음성 토론 결정 기록

> 기록 기준일: 2026-08-26
> 성격: 사용자 요구·제품 의도·용어를 보존하는 관리자 기록
> 주의: 이 문서는 구현 완료를 선언하지 않는다. 구현 사실과 음향 검증 결과는 별도 문서에서 확인한다.

## 1. 목표

AudioForge의 표현 음성 기능은 감정 태그가 등장하는 순간 목소리를 새로 시작하는 방식이 아니라, 같은 화자가 문장 안에서 감정을 자연스럽게 이동시키는 것을 목표로 한다.

핵심 목표는 다음과 같다.

- 화자 정체성과 목소리 개성을 유지한다.
- 감정 구간 전환을 별개의 녹음 조각처럼 들리지 않게 연결한다.
- 문장 시작과 끝을 모두 자연스럽게 처리한다.
- 긴 글에서도 조각별 음높이·속도·종결 억양이 매번 초기화되지 않게 한다.
- 사용자가 복잡한 모델 설정을 몰라도 감정과 표현을 선택하고 비교할 수 있게 한다.

## 2. 감정과 표현의 분리

감정, 문장부호 표현, 비언어 음성은 서로 다른 축으로 다룬다.

| 축 | 예 | 제품 의미 |
| --- | --- | --- |
| 감정 | 기쁨, 슬픔, 화남, 불안, 다정함 | 구간 전체의 음높이 범위·강도·속도·호흡 경향 |
| 스타일 | 요염함, 장난스러움, 진지함 | 기본 감정 위에 얹는 말투·연기 방향 |
| 문장부호 표현 | `!`, `?`, `!?`, 점 반복, `~` | 단어나 문장 끝의 국소적인 억양·길이·감쇠 |
| 비언어 음성 | `[ㅋㅋㅋㅋ]`, `[ㅎㅎㅎㅎ]`, 웃음 이벤트 | 글자를 읽는 것이 아닌 실제 웃음·숨·감탄 소리 |

`요염함/유혹`은 기본 감정으로 고정하지 않고 스타일 축으로 두는 것이 타당하다. 같은 유혹 대사도 밝음·차분함·자신감 등 서로 다른 감정과 결합할 수 있기 때문이다.

## 3. 문장부호 표현 의도

아래 의미는 제품 의도이며, 현재 production 지원 여부와 구분한다.

- `!`: 문장 또는 강조 구간의 강도를 높이고 종결을 단단하게 한다.
- `?`: 말끝의 음높이를 올려 질문하는 느낌을 만든다.
- `!?` 및 선택적으로 `?!`: 음높이가 점차 상승하고 마지막을 강하게 닫는 경악·반문 표현이다.
- 단일 `.`: 일반 종결 또는 짧고 단단한 마무리다. 강조 단어를 만들기 위한 기호로 오해하지 않는다.
- `..`, `...`, `......`: 점 개수에 따라 말끝의 힘과 음량을 점진적으로 줄이는 표현이다. 무음만 추가하는 것이 아니라 감쇠 곡선이 필요하다.
- `~`: 마지막 모음을 자연스럽게 늘이는 표현이다. 자음을 기계적으로 반복하지 않는다.
- 받침이 있는 `~`: 지속 가능한 종성(ㅇ·ㄴ·ㅁ·ㄹ)과 그렇지 않은 종성을 구분하되, 실제 지원 판정은 음향 probe와 청취 검증 전까지 미검증으로 둔다.

문장부호와 감정 태그는 그 자체로 강제 조각 경계가 되어서는 안 된다. 감정 전환과 문장 휴지가 겹쳐 이중으로 긴 공백을 만들지 않도록 하나의 경계 정책에서 조정해야 한다.

## 4. 웃음 표현 의도

`ㅋㅋ`, `ㅎㅎ`, `헤헤`, `호호`, `히히`를 그대로 발음하는 것은 목표가 아니다. 사용자가 원하는 것은 다음과 같은 비언어적 연기다.

- 대화 시작이나 끝에 웃음을 넣어 감정을 전달한다.
- 반복 횟수는 웃음의 길이·강도에 영향을 준다.
- `헤헤`, `헤헷`, `호호`, `호홋`, `히히` 등 표기는 웃음 스타일의 힌트가 될 수 있다.
- 실제 생성은 텍스트 낭독 경로와 분리된 nonverbal event 또는 검증된 웃음 전략을 사용해야 한다.

현재 실험 장문에서 웃음 글자가 들렸다는 사실은 웃음 기능 성공을 의미하지 않는다. 해당 파일은 웃음 텍스트를 읽은 것이며 실제 비언어 웃음 엔진은 검증되지 않았다.
## 5. 참조 음성 사용성 결정

### 5.1 한 번 분석한 참조의 재사용

참조 구간은 대사를 바꿀 때마다 다시 분석하지 않는다. 한 번 확정한 구간을 앱 소유의 지속 저장소에 보존하고 다음 합성에서 재사용할 수 있어야 한다.

- 임시 폴더는 staging에만 사용한다.
- 검증 후 동일 파일시스템에서 atomic promote한다.
- manifest의 신원 권위는 content SHA-256이다.
- 경로·크기·수정 시각만으로 캐시 신원을 판단하지 않는다.
- 앱 재시작 후에도 저장된 참조를 복원한다.

### 5.2 여러 후보 보존

자동 분석은 하나의 후보만 강제하지 않고 여러 비중첩 후보를 저장할 수 있어야 한다.

- 이미 채택한 half-open 구간은 다음 탐색에서 제외한다.
- 경계가 맞닿는 것은 허용한다.
- 후보가 소진되면 `NO_MORE_REFERENCE_CANDIDATES`처럼 명확하게 알린다.
- 기존 후보를 조용히 교체·재정렬·삭제하지 않는다.
- 후보마다 재생·선택·삭제·다시 분석을 제공한다.

### 5.3 감정별 참조와 단일 참조

여러 참조가 항상 품질을 높이는 것은 아니다. 서로 다른 구간의 음색·환경·억양이 섞이면 화자 일관성이 떨어질 수 있다. 기본 합성은 명시적으로 선택한 단일 참조를 유지하고, 다중 후보는 사용자가 비교·선택하는 라이브러리로 제공한다. 감정별 참조는 해당 감정 구간에만 명시적으로 매핑한다.

## 6. 감정 샘플러의 목적

감정 샘플러는 단순한 버튼 미리듣기가 아니다. 같은 화자·같은 조건에서 감정별 음향 프로필을 측정하고 사용자가 실제로 감정처럼 들리는지 확인하는 보정 도구다.

각 감정에는 두 종류의 대사를 제공한다.

1. 공통 비교 대사: 모든 감정을 같은 문장으로 비교한다.
2. 상황 대사: 해당 감정이 자연스럽게 발생하는 문맥을 사용한다.

예시:

| 감정/스타일 | 상황 대사의 방향 |
| --- | --- |
| 기쁨 | 좋은 소식이나 기다리던 일이 이루어진 상황 |
| 화남 | 잘못을 반복한 상대에게 단호하게 화내는 상황 |
| 슬픔 | 이별이나 소중한 사람을 떠나보내는 상황 |
| 불안 | 결과를 기다리며 걱정하는 상황 |
| 다정함 | 상대를 안심시키거나 위로하는 상황 |
| 자신감 | 결심과 확신을 전달하는 상황 |
| 요염·유혹 | 상대를 자연스럽게 유혹하는 상황 |

모든 진단 샘플에는 시작 전과 종료 후 각각 약 500ms의 무음을 둔다. 이는 음성 내용의 일부가 아니라 onset과 tail을 사람이 식별하기 위한 진단 여백이다.

샘플 화면에는 다음을 함께 표시한다.

- 사용한 대사와 감정/스타일 이름
- 참조 후보 및 content fingerprint
- 재생·다시 생성 상태
- 중립 대비 F0·강도·속도·휴지 변화
- 지원됨, 미검증, 지원 안 됨의 구분

합성에 성공했다는 이유만으로 “그 감정처럼 들린다”고 표시하지 않는다. 사용자 청취 또는 검증된 평가 근거가 필요하다.

## 7. 사용성 단순화 원칙

기본 화면에는 대사, 화자 참조, 감정/스타일, 속도·음높이, 생성 버튼만 우선 노출한다. 경계·말끝·pause·진단 수치와 같은 고급 항목은 접힌 영역으로 둔다.

- 감정 태그는 팔레트에서 커서 위치에 한 번에 삽입한다.
- 잘못된 태그는 즉시 표시한다.
- 감정별 참조는 한 목록에서 등록·해제·미등록 상태를 보여준다.
- 샘플러는 기본 접힘이며 요약 상태만 표시한다.
- 설정 이름은 모델 내부 용어보다 사용자 행동을 설명한다.
- 기존 참조 재사용을 기본으로 하여 연속 실험의 반복 작업을 줄인다.

## 8. 확정하지 않은 사항

- 감정별 절대 Hz 범위: 화자마다 기본 음역이 달라 보편적인 절대값으로 고정하지 않는다.
- 특정 감정이 지원된다는 판정: 실제 같은 화자 비교와 청취 전에는 미검증이다.
- 생성 상한 상향: 모델 한도가 아니라 watchdog·월클럭 정책과 연결되므로 별도 결정이다.
- 웃음 생성 전략: 텍스트 낭독을 대체할 실제 전략이 아직 검증되지 않았다.
- v3 표현 문법의 production 활성화: 명시 flag·parity·session 영속 배선이 완료되기 전에는 legacy v2가 기본이다.
