# 옛 작업 → 생성 카드 가져오기 — 조사

2026-09-27. **조사만 했다. 변환도 새 화면도 만들지 않았다.**
공용 화면 파일은 하나도 손대지 않았다(Codex 가 카드 GUI·UX 를 고치는 중이다).

원칙(지시 그대로): **기존 작업은 보존하고, 카드 작업은 별도 사본으로 만든다.**

---

## 1. 무엇을 가져오는가 — 저장본은 셋이고 성격이 다르다

- **`labWorkspace`** (옛 '문장별 제작') — 카드와 **가장 가깝다.**
  한 목소리 + 줄 목록 + 줄마다 생성본·채택. 카드 구조와 1:1 에 가깝다.
- **`workDrafts`** (옛 '대본·배역 편집') — **구조가 다르다.**
  대본이 통째 문자열 하나(`ttsText`)이고, 배역이 따로 있고, **생성본이 없다.**
- **`synthesisCards`** — 카드의 저장 자리. 목적지다.

셋은 서로를 읽지도 쓰지도 않는다. 열쇠가 다르고 본체가 열쇠 하나씩 원자 교체한다.

## 2. 지금 이 컴퓨터에 실제로 있는 것 (개수만 셌다. 대사·경로는 읽지 않았다)

정식 앱(`audio-forge`)
- 문장별 제작: 줄 3 · 생성본 3 · **소리 파일 3개 전부 살아 있다** · 채택된 줄 **1**
- 목소리 파일: 있고 실제로 존재
- 대본 작업 4개 · 그중 **여러 배역 2개** · 배역 합계 10 · 구간이 지정된 배역 5 · 감정 켠 배역 **0**

개발판(`audio-forge-dev`)
- 문장별 제작: 줄 3 · 생성본 2(둘 다 파일 살아 있음) · 채택된 줄 2 · `tailResidual` 가진 생성본 1
- 대본 작업 5개 · 여러 배역 3 · 배역 합계 7 · 구간 지정 3 · 감정 켠 배역 0

읽어 낸 사실 두 가지
- **채택하지 않은 줄이 있다**(정식 3줄 중 1줄만 채택). 가져와도 최종 연결은 막힌다 — 정상이다.
- **감정을 켠 배역이 하나도 없다.** 지금 자료에 한해서는 감정 손실 위험이 실제로는 없다.

## 3. `labWorkspace` → 카드 : 항목 대조

### 그대로 옮길 수 있는 것

- **대사 순서** — `lines[]` 배열 순서가 곧 카드 순서. 순서 정보 손실 없음.
- **줄 대사** `lines[].text` → `card.text`
- **생성본** `lines[].takes[]` → `card.takes[]` (`id` · `path` · `text` · `createdAt` 그대로)
- **채택 여부** `lines[].adoptedTakeId` → `card.adoptedId` (없으면 null 그대로 — 지어내지 않는다)
- **목소리 파일** `voicePath` → `card.source.path`, `voiceLabel` → 카드 이름 후보
- **속도·음높이** `settings.speed` → `card.settings.speed`, `settings.pitch` → `card.settings.pitch`

### 값을 만들어 넣어야 하는 것 — **지어내면 안 되는 자리**

- `card.source` 는 `{path, name, duration}` 인데 옛 문서에는 **길이가 없다.**
  → 파일을 실제로 읽어 채워야 한다. 파일이 사라졌으면 **0 으로 채우지 말고** 가져오기를
  막거나 '파일 없음' 으로 표시해야 한다.
- `card.takes[].source` · `settings` · `applied` 가 **필수**인데 옛 생성본에는 셋 다 없다.
  `applied` 는 **엔진에 실제로 간 값**이다. 모르는 값을 요청값으로 채우면
  "왜 +4 로 했는데 이 소리지" 를 영영 설명할 수 없게 된다.
  → 화면이 이미 `appliedOf()` 로 '기록 없음' 을 그릴 수 있다. **비워 두는 쪽이 옳다.**
- `card.takes[].voice`(VoiceSnapshot)와 옛 `take.voiceKey`(경로 문자열)는 모양이 다르다.
  경로 → 참조 목소리로 옮길 수는 있으나 **그때의 구간은 알 수 없다**(아래 참조).

### 카드에 **자리가 없는** 것 — 가져와도 적용되지 않는다

카드는 생성할 때 `productDefaults()` 에 속도·음높이만 덮어 보낸다. 나머지는 전부 제품 기본값이다.

- `settings.engine` · `qwenModel` — 카드는 엔진 `auto` 고정
- `settings.referenceConditioningMode`
- `settings.refTargetSec`(참조 목표 길이)
- `settings.tailMode` · `tailPaddingMs` · `tailFadeMs`
- `settings.silenceGap` — 이름이 비슷한 `joins.gap` 이 있으나 **같은 것이 아니다.**
  `silenceGap` 은 합성 워커가 문장 사이에 두는 무음이고,
  `joins.gap` 은 최종 연결이 **카드와 카드 사이**에 두는 빈 자리다. 한쪽을 다른 쪽에 옮기면
  같은 소리가 나지 않는다. **옮기지 않는 편이 안전하다.**
- `takes[].tailResidual`(말끝 잔량) — 카드 생성본에 그 자리가 없다(실제 1건 존재)

### 아예 저장돼 있지 않은 것

- **참조 구간.** `LabDoc` 에는 구간이 없다 — 저장되는 것은 `voicePath`/`voiceLabel` 뿐이고,
  구간(`LabRefState`)은 **화면 상태라 저장되지 않는다.** 옛 작업실은 열 때마다 자동 확정했다.
  → 카드의 `settings.start/end` 를 옛 값으로 채울 **근거가 없다.**
  카드 기본값(`reference: 'auto'`)으로 두고 다시 준비하게 하는 것이 정직하다.

## 4. `workDrafts` → 카드 : 구조가 다르다

- **대본이 통째 문자열 하나**(`ttsText`)다. 카드는 카드마다 대사를 가진다.
  → 나누는 규칙이 필요하다. 문장 분리 규칙을 우리가 정하면 **사용자가 쓴 줄 나눔과 달라질 수 있다.**
- **배역**(`speakers`)이 있다. 카드에는 배역 개념이 없다(카드 하나 = 목소리 하나).
  배역별 목소리는 카드마다 목소리를 달리해 흉내 낼 수 있으나,
  **"이 대본 안의 배역" 이라는 묶음은 사라진다.** 실제로 여기 배역이 10개·7개 있다.
- **배역 구간**(`speakers[].region`)은 저장돼 있다 → `card.settings.start/end` 로 옮길 수 있다.
  (문장별 제작과 반대다. 이쪽은 구간이 남아 있다.)
- **`emotionEnabled`** — 카드에 자리 없음(현재 자료에는 켠 배역 0)
- **`renames` · `inheritSpeakerId`** — 카드에 대응 없음
- **생성본이 없다.** 이 저장본은 "만들던 것" 의 기록이고 결과는 작업 폴더의 `session.json`에 있다.
  → 결과까지 가져오려면 `session.json` 을 따로 읽는 **별개의 일**이다.

## 5. 손실 위험 — 실제로 일어날 수 있는 것부터

1. **원본·생성본 파일이 사라진 경우.** 저장본에는 경로만 있다.
   지금은 전부 살아 있지만(3/3, 2/2), 일반적으로는 없을 수 있다.
   → `missing: true` 로 표시하고 재생·채택을 막는 자리가 카드에 **이미 있다.** 그것을 쓰면 된다.
2. **`applied` 를 지어내는 것.** 가장 위험하다. 모르는 값을 아는 것처럼 적는 순간
   그 생성본의 내력이 거짓이 된다. 비워 두는 편이 낫다.
3. **`silenceGap` → `joins.gap` 혼동.** 뜻이 다른 값을 옮기면 소리가 달라진다.
4. **대본 통째 → 카드 나누기.** 우리가 정한 규칙이 사용자의 의도와 다를 수 있다.
5. **되돌릴 수 없는 가져오기.** 원칙대로 **옛 저장본을 건드리지 않고 사본만** 만들어야 한다.
   카드 저장 자리에는 이미 두 칸 구조(`current` / `kept`)가 있어
   **지금 카드 작업을 밀어내지 않고 옆에 둘 수 있다.**
6. **중복 가져오기.** 같은 작업을 두 번 가져오면 카드가 두 배가 된다.
   → 가져온 출처를 기록해 두지 않으면 알 수 없다(지금 카드 구조에 출처 칸이 없다).

## 6. 정리 — 구현 범위를 정할 때의 권고

**가장 값싸고 안전한 것**: `labWorkspace` → 카드. 대사 순서·생성본·채택이 그대로 옮겨진다.
못 옮기는 것은 참조 구간과 엔진 세부 설정인데, 둘 다 **카드에 자리가 없거나 저장돼 있지 않다** —
즉 가져오기를 잘 만들어도 해결되지 않고, 카드 쪽에 자리를 만드는 별개의 일이 필요하다.

**비싼 것**: `workDrafts` → 카드. 대본 나누기 규칙과 배역 묶음이 걸린다.
배역이 실제로 10개·7개 있으므로 "카드마다 목소리" 로 펴면 묶음 정보가 사라진다.

**추가로 필요할 수 있는 카드 쪽 자리**(이번에 만들지 않았다)
- 생성본의 '기록 없음' 표시는 있다. **가져온 출처**를 적을 칸은 없다.
- 참조 구간을 옛 값으로 채울 근거가 없으므로 `reference: 'auto'` 로 두는 것이 맞다.

Codex 의 기능 대응표(`doc/synthesis-card-feature-map.md`)와 합쳐 범위를 정한 뒤 구현한다.
**공용 화면 파일을 바꿔야 하면 그 전에 파일과 이유를 먼저 보고한다.**
