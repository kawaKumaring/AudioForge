# 상황 기반 호흡·환경음 생성 및 자동 믹싱 — 향후 구현 예정

기록만 한 상태다. 구현·모델 설치·다운로드·GPU 실행은 하지 않았다.

## 개요

사용자가 목소리와 대사를 고르고 상황을 한 줄 적으면, 로컬 AI 가 장면을 해석해
호흡·환경음·효과음을 계획하고 **음성과 별도 트랙으로** 생성·믹싱한다.

예시 입력
- 대사: 등산 중 동료를 독려하는 한 문장
- 상황: 달리는 운동선수, 주변에 폭포와 숲의 새

이때 앱이 제안하는 태그: `달리며 말함` / `거친 호흡` / `폭포` / `숲의 새소리`

## 사용자 흐름

1. 목소리 선택
2. 대사 입력
3. 상황 입력(선택)
4. 표현 강도: 자연스럽게 / 강하게
5. AI 가 짧은 제안 태그를 표시
6. 사용자는 필요 없는 태그만 끄고 `음성 만들기`
7. 세부 음량·위치·타이밍은 고급 옵션에 숨김

기본 화면에 슬라이더를 늘어놓지 않는다. 사용자가 다루는 것은 태그 on/off 까지다.

## 구조

| 계층 | 역할 | 비고 |
|---|---|---|
| 로컬 LLM | 상황 → 비언어 음향 타임라인 | 기존 번역용 LLM 재사용 검토 |
| TTS | 화자 음색과 대사 | 기존 Qwen3-TTS / GPT-SoVITS |
| 호흡 표현 엔진 | 들숨·날숨·헐떡임·한숨 | 생성 또는 **검증된 자산 선택** |
| 환경음 엔진 | 폭포·새·바람·발소리·옷 마찰 | 선택 설치 |
| 믹서 | stem 조립·ducking·공간 배치·잔향 | AudioForge |

## 핵심 원칙

- 음성·호흡·환경음을 **한 파형으로 직접 생성하지 않는다.** 별도 트랙으로 관리한다.
- 환경음이 **화자 복제 조건이나 참조 음성에 섞이지 않게 격리**한다.
  참조 오염은 이미 겪은 실패 유형이다(controlled-prefix 혼입 조사 참고).
- 각 트랙은 개별 음소거·재생성·음량 조절이 가능해야 한다.
- 상황 해석 결과는 사용자가 읽고 판단할 수 있는 **짧은 태그**로 보여 준다.
- 환경음 모델은 **선택 설치** 항목이며 필요할 때만 받는다(runtime_spec assets 계약).
- 완전 로컬·오프라인 실행이 기본 목표다.
- **어떤 모델을 쓸지 지금 고정하지 않는다.** 비교 검증 후 결정한다.
- capability 가 입증되지 않은 호흡·감정·환경음을 **지원됨으로 표시하지 않는다**
  (expressive_capability 계약: supported 는 프로브로 확인된 것만).
- 자동 생성이 실패해도 **깨끗한 대사 음성만은 발행**할 수 있도록 계층을 분리한다.
- **거리 기반 음량 변화는 `spatial_automation` 의 책임이다.** 화자가 멀어지거나 다가오는 연출은
  대사 트랙의 연기(`performance_prosody`)가 아니라 공간 축에서 처리한다. 이때 gain 만 움직이지
  않는다 — 고역 감쇠와 direct/reverb 비율을 함께 바꿔야 거리로 들린다.
- 대사 트랙 자체는 **안정된 청취 loudness** 를 유지한다. 수십 초에 걸친 점진적 gain drift 는
  감정 표현이 아니라 결함으로 다룬다(roadmap 「연기·믹싱·공간」 참고).
- `[멀어짐]`, `[다가옴]` 같은 **명시적 공간 지시가 있을 때만** 점진적 fade 를 건다.

## 단계

- **A** 상황 → 음향 타임라인 schema 와 로컬 LLM planner
- **B** 호흡 표현 생성·배치
- **C** 환경음 생성 또는 로컬 자산 검색
- **D** 다중 stem 믹서와 자동 ducking
- **E** 기본 UI 단순화와 고급 타임라인 편집
- **F** 장면별 청취 평가 및 capability 승격

## 착수 시점

현재 진행 중인 **장문 단일 호출·동적 분할 안정화** → **감정 표현 다듬기** 를 끝낸 뒤 착수한다.
