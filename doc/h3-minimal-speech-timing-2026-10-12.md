# H3 최소 음성 생성 시간 측정 준비

사용자는 GUI 흡수 전에 최소 생성 경로에서 첫 생성과 재생성 시간을 측정하도록 승인했다. 구현은 `scripts/probe-h3-speech.py`다. 기존 ComfyUI 설치의 노드·추론 코드를 같은 Python 프로세스에서 직접 호출하며 서버·GUI·커스텀 노드·영상 VAE·영상 디코딩·영상 저장을 쓰지 않는다. 이것은 흡수를 가정한 시험이며 모델·코드를 AudioForge에 독립 흡수한 제품 경로는 아니다.

## 조건

REF2VA INT8 본체 20,970,379,616바이트, Qwen3VL NVFP4 AWQ 인코더 15,687,142,551바이트, 오디오 VAE 605,254,808바이트. 설치된 파일을 읽기만 한다. 복사·다운로드·삭제하지 않는다.

기존에 승인된 참조 A 조각의 SHA256을 확인하고 재사용한다. 전달받은 LocalBlend의 참조 31초 파일을 새로 열지 않는다. 대사는 전달된 73자 문장, 언어 Korean, 256×256, 243프레임(요청 10초), 16단계, cfg1, res_multistep/simple, shift12/3. Turbo LoRA 및 단계 계산 재사용 캐시를 쓰지 않는다. 영상 잠재 계산은 남는다.

seed2024 첫 생성, seed2025·2026 두 번의 실제 재생성을 같은 프로세스에서 수행한다. 재생성에서는 같은 참조·글의 확정 조건만 재사용하고 음성은 매번 새로 생성한다. 모델 객체는 유지하지만 VRAM 상주까지 보장하지 않는다. ComfyUI가 메모리 사정에 따라 CPU와 GPU 사이에 옮길 수 있다.

모델 로더·참조/대사 인코딩·샘플링·오디오 디코딩·저장 시간을 GPU 동기화와 단조 시계로 기록한다. 첫 전체 시간은 의존 라이브러리 초기화부터 포함한다. OS 파일 캐시는 비우지 않으므로 이 컴퓨터의 최초 파일 읽기 시간으로 주장하지 않는다. 각 생성 전후 GPU 메모리와 사용률을 함께 남긴다. GUI에서 관측한 138초 및 89·97·90초와 설정이 완전히 같다는 보장은 없다.

LocalBlend 성공 스크립트를 확인한 결과 res_multistep였다. 해당 경로에는 계산 재사용 캐시, 샘플링 미리보기, 영상 디코딩·저장도 포함됐다. 따라서 이번 차이를 흡수 자체의 효과나 같은 품질에서의 순수 속도 향상으로 단정하지 않는다.

## 준비 확인 및 남은 일

준비 전용 명령은 실제 모델 추론 없이 세 모델 경로·파일 크기·조건을 확인했고 정상 종료했다. 시작 시 GPU 여유 3,175MiB, 사용률100%; 이후 3,420MiB, 사용률100%. 경쟁 작업을 종료하지 않았다. 측정 시작 조건은 여유6GiB 이상·사용률20% 이하로 두고 충족하지 않으면 생성 전에 거절한다. 사용자에게 여유 확보를 요청한 상태다.

현재 생성 결과 없음. 실제 노드 직접 실행·오디오 출력·시간·청취 품질은 미확인이다. 실행 오류도 성공 기록과 별도로 보존한다. 이후 결과는 master의 `_local/테스트/결과/h3-direct-speech-시각/`에 원본 WAV·기록·비교 페이지로 보관한다. 사용자 음성·결과는 커밋·외부 전송하지 않는다. 시험기와 문서만 개발선에 반영한다.

## 첫 직접 실행 중단과 시험기 보완

GPU 여유 약9GiB 확보 후 실행했다. 라이브러리 초기화8.60초, 본체 로더0.89초, 텍스트 로더3.63초, 오디오 VAE 로더1.34초, 참조·글 처리189.14초. 로더 시간은 GPU에 모두 적재된 시간과 다르다. 이후 샘플링16단계의 첫 단계가 끝나지 않아 약7분30초에 이번 프로세스만 중단했다. 음성0개·재생성0회, 첫 생성 완료 시간으로 쓰지 않는다. 기록: `_local/테스트/결과/h3-direct-speech-20261012-213019/record.json`, 상태interrupted.

직접 호출에 LocalBlend의 `--fast fp16_accumulation` 및 모델 단위 Comfy Kitchen 어텐션 설정이 빠져 있었다. 비교 조건을 맞추도록 시험기를 보완했다. 속도 차이의 전체 원인이라는 결론이나 보완 후 개선 수치는 아직 없다. 단계별 기록을 즉시 저장하고 샘플링 완료 단계도 표시하게 했다. 계산 캐시는 여전히 꺼짐이며 확정 조건 재사용과 생성 음성 재사용은 구분한다.

이번 프로세스 종료 뒤 다른 GPU 작업으로 여유 약4GiB에 다시 못 미치는 시점이 있었다. 다른 프로세스는 종료하지 않았다. 보완한 조건에서 완주·재생성 측정은 아직 남았다.

## 연산 설정 보완 후 메모리 관측

사용률7%·여유5,287MiB에서 사용자의 진행 지시에 따라 메모리 분산을 허용하는 시작 조건4GiB로 시험했다(기본 시작 조건6GiB 유지, 명시 옵션으로만 변경). 활성 GPU 작업이 없는 것과 메모리가 비어 있는 것은 다르므로 깨끗한 측정으로 주장하지 않는다.

동시 적재 실행은 참조·글 인코딩145.92초 후 본체 적재를 시작했고 시스템 여유 메모리472,760KiB(약0.45GiB)를 관측해 중단했다. 순차 적재 실행도 인코더만 쓰는 동안378,768KiB(약0.36GiB)까지 감소해 중단했다. 두 실행 모두 완성 음성 없음. 중단 직후 여유 메모리약23GiB로 회복했다. 시간 수치는 성공·재생성 측정으로 세지 않는다.

시험기를 인코더·오디오 VAE 적재→조건 인코딩→인코더 해제→본체 적재 순서로 바꾸고 단계별 시스템/GPU 메모리 관측을 추가했다. ComfyUI 기본의 고정 메모리 버퍼(최대 약26GiB 설정)와 비동기 전송도 이번 시험기에서만 끈다. 고정 버퍼가 지연의 유일한 원인이라는 실측은 없으며 이 보완의 효과도 아직 미확인이다. 이 실행 정책을 제품 기본값으로 바꾸지 않는다.

보완한 다음 실행은 GPU 경합으로 모델 적재 전에 거절됐다. LocalBlend의 별도 실행기(PID11824, 포트7950)가 GPU를 쓰고 있음을 확인했으며 종료하지 않았다. 준비 전용 경로와 문법만 확인하고, 보완 후 완주·재생성은 남긴다.
