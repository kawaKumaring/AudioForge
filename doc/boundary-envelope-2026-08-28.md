# 경계 envelope — 시작·끝 급절단(클릭) 수정 (2026-08-28)

상태: **구현 완료**. 브랜치 `feature/tts-boundary-envelope`.

## 1. 증상과 증거의 순서

사용자가 Qwen3-TTS 산출물 앞뒤에 진단용 1초 무음을 붙여 듣고 **"S자 없이 딱 켜지고 딱 꺼진다"**
고 확정했다. 이것이 1차 증거다. 자동 검사가 "급절단 후보 없음"이라고 말했지만 그 판정이 틀렸고,
왜 틀렸는지는 §5에 따로 적었다.

계측 대상은 `E:\AudioForge_output\expressive-comparison\20260827-A2-emotion3` 의
`happy_raw.wav` / `angry_raw.wav` / `sad_raw.wav`(24 kHz mono, 4.32~4.88초)와 대조군
`reference_clip.wav`(실제 녹음, 9.0초)다. 전부 읽기 전용으로 다뤘고 숫자만 뽑았다.
그 위에 정답을 아는 synthetic 신호를 얹어 판정 기준을 세웠다. GPU 합성은 하지 않았다.

## 2. 무엇이 실제로 일어나고 있었나

**합성 산출은 sample 0 부터 이미 소리를 담은 채 시작한다.** 앞 10 ms 의 RMS 가 각각
−30.94 / −32.05 / −29.43 dBFS 이고, 첫 2 ms 프레임의 RMS 가 그 파일에서 가장 큰 프레임의
8.8 % / 8.4 % / 3.9 % 다. 디지털 무음(정확히 0)에서 이 레벨로 **한 샘플 만에** 올라선다.

대조군을 보면 이것이 왜 결함인지가 분명해진다. 실제 녹음은 같은 자리가 최대 프레임의 **0.4 %**
(앞 10 ms RMS −57.48 dBFS)이고, 235 ms 짜리 진짜 저레벨 lead-in 을 갖고 있다. 켜짐이 들릴 수가 없다.

한 가지 흔한 오해를 먼저 지운다. **DC 계단은 클릭의 원인이 아니다.** 첫 샘플 값은
0.006409 / 0.007690 / 0.005554 로 peak 의 0.9~1.3 % 에 불과하고, 같은 구간에서 신호가 스스로 만드는
샘플 간 변화량(happy 기준 RMS 0.0194)보다 오히려 작다. 귀에 걸리는 것은 **envelope 의 계단**이다 —
소리의 크기가 0 에서 −30 dBFS 로 순간 이동하는 것.

국소 고역(2차 차분, support 3 샘플)으로 경계 ±3 ms 의 피크를 본문 median 으로 나눈 값을 재면
그 계단이 숫자로 드러난다. 무처리 상태에서 happy 56.4, angry 17.7, sad 17.8 인 반면
**실제 녹음은 0.4** 다. 즉 합성물의 시작 경계는 본문의 평범한 지점보다 18~56배 튀고,
실제 녹음의 시작은 본문보다도 조용하다.

끝쪽은 소재를 탄다. happy 는 마지막 200 ms 가 이미 감쇠해 마지막 10 ms 가 −92.7 dBFS 로 사실상
무음이고, angry 도 마지막 15 ms 는 디지털 무음이다. 반면 **sad 는 끝나기 12 ms 전까지 최대 프레임의
13 % 짜리 내용이 살아 있다가 마지막 5 ms 에서 0.05 % 로 떨어진다** — 이쪽은 실제로 잘린 끝이다.
그래서 시작 결함은 3종 공통이고, 끝 결함은 소재에 따라 나타난다.

## 3. 창 길이를 고른 방법

고정값을 추측하지 않기 위해, 판정 기준을 먼저 세웠다.

> **경계가 '경계 없는 같은 소재' 보다 날카롭지 않을 것.**

측정 방법은 이렇다. 발화 한복판(1.2 / 1.8 / 2.4 / 3.0 초 지점)에서 파일을 잘라 무음 뒤에 곧바로 말
한복판이 오는 **최악의 계단**을 만들고, 거기에 후보 창을 건다. 그리고 그 경계의 고역 피크를,
**자르지 않은 원본의 바로 그 지점**(경계가 아예 없는 상태)의 값과 비교한다. 0 dB 이하로 내려가면
"계단이 사라져 원래 소재와 구별되지 않는다"는 뜻이다.

이 기준을 쓰면 클릭 쪽 곡선은 창이 길수록 단조롭게 좋아진다. 그러므로 **어디서 멈출지는 전적으로
자음 보존이 결정한다.** 사용자가 최우선 제약으로 못 박은 바로 그것이다.

### onset = 10 ms (24 kHz 에서 240 sample)

10 ms 에서 최악 계단의 잔여는 happy −15.7 dB, angry −19.1 dB, sad −17.0 dB, 대조군 −15.1 dB 다.
이미 무경계 상태보다 한참 아래다. 자연 상태 파일의 시작 경계비도 56.4 → 3.9, 17.7 → 1.4,
17.8 → 1.2 로 떨어져 **−22.0 ~ −23.4 dB** 의 감소를 얻는다.

여기서 멈추는 이유는 자음이다. A2 3종에서 검출된 **가장 이른 고역 버스트는 sad 의 8 ms 지점**이다.
onset 10 ms 이면 그 지점의 gain 이 smoothstep(0.8) = 0.896, 즉 감쇠가 **0.95 dB** 로 1 dB 안에 들어온다.
12 ms 로 늘리면 같은 지점이 0.741(−2.6 dB)로 떨어지고, sad 의 앞 20 ms 에너지 손실이
0.35 dB 에서 0.95 dB 로 2.7 배 뛴다. 20 ms 면 0.352(−9.1 dB)까지 간다. 클릭 쪽에서 더 얻는 것은
2~3 dB 인데 자음 쪽에서 잃는 것이 그보다 크다. 그래서 10 ms 가 **가장 이른 실측 자음 버스트를
1 dB 안에서 지키는 가장 긴 창**이고, 그것이 선택 근거다.

부수적으로, A2 3종 모두 주 유성 에너지는 50~70 ms 에서 서기 때문에 10 ms 창은 거기에 닿지도 않는다.
앞 100 ms 기준 에너지 손실은 0.008~0.028 dB, 발화 전체 기준으로는 0.0003~0.0008 dB 다.

정직하게 남길 것: **앞 2~4 ms 는 설계상 반드시 감쇠된다.** fade 는 0 에서 출발해야 하기 때문이다.
happy 는 그 구간에 고역 성분이 있고(2~4 ms 프레임이 파일 median 의 37.7 배), 10 ms 창에서 3 ms 지점의
gain 은 0.216(−13.3 dB)이다. "아무것도 안 깎았다"고는 말할 수 없다. 말할 수 있는 것은,
지각적으로 자음을 이루는 구간(파열 5~15 ms + 이후 20~60 ms 의 기식, 마찰음 50~150 ms) 전체로 보면
손실이 앞 20 ms 에서 0.35~2.29 dB, 앞 100 ms 에서 0.03 dB 이하라는 것이다.

### offset = 20 ms (24 kHz 에서 480 sample)

20 ms 에서 최악 계단의 잔여는 happy −26.6 dB, angry −28.0 dB, sad −26.3 dB 로 시작 쪽보다도
여유가 크다. 더 늘릴 이유가 없다. 오히려 늘리면 **말끝을 지운다**.

말끝 20 ms 구간의 에너지 손실로 보면, 20 ms 창일 때 happy 0.62 dB / angry 0.06 dB / sad 2.82 dB 인데,
30 ms 로 가면 4.40 / 3.01 / 7.26 dB, 40 ms 면 8.13 / 6.51 / 11.18 dB 로 급격히 커진다. 150 ms 면
26.9~32.1 dB — 마지막 음절이 사라지는 수준이다. 계단 억제는 20 → 150 ms 사이에서 고작 0.5~3.9 dB
더 좋아질 뿐이다. 지시받은 20~150 ms 범위에서 20 ms 가 최소이자 최소 distortion 이다.

sad 는 끝나기 12 ms 전까지 내용이 살아 있어 20 ms 창에서도 그 지점이 0.648(−3.8 dB) 감쇠한다.
이건 피할 수 없다 — 그 파일 자체가 바짝 잘려 있다. 다만 허용 범위 안의 모든 대안이 더 나쁘다.

### smootherstep 대조

계약대로 smoothstep(3u²−2u³)을 유지했다. 다만 참고 수치는 남겨 둔다 — 국소 계측 기준으로
smootherstep(6u⁵−15u⁴+10u³)이 **두 기준 모두에서 더 낫다**.

onset 10 ms 에서 시작 경계비가 happy 3.85 → 2.15, angry 1.35 → 0.75, sad 1.23 → 0.84 로
클릭 억제가 **3.3~5.1 dB 더** 좋아진다. 동시에 8 ms 지점 gain 이 0.896 → 0.942 로 올라가
자음을 **더** 지킨다(앞 20 ms 손실은 happy·angry 동률, sad 는 0.345 → 0.247 dB 로 개선).
곡선이 양 끝에서 2차 도함수까지 0 이라 창의 스펙트럼 스커트가 더 빨리 떨어지기 때문이고,
같은 이유로 중앙부가 더 가팔라 초반 감쇠가 덜하다.

그럼에도 "기본 의도는 S자 ease-in-out" 이라는 계약을 임의로 바꾸지 않았다. 바꿀지 말지는
계약 소유자의 결정이며, 바꾸기로 한다면 위 수치가 근거다. 코드에서는 `_smoothstep` 하나만
교체하면 되고 창 길이(10/20 ms)는 그대로 유효하다.

⚠️ 이 수치들은 **국소 고역 계측**으로 다시 잰 값이다. 전역 FFT 계측으로 재면 차이가 절반 이하로
작게 보인다(§6 의 함정). 재검토할 때 계측 방법을 먼저 확인할 것.

## 4. 무엇을 어디에 넣었나

순수 함수는 `python/audio_finishing.py` 에 있다. `compute_boundary_plan(length, sr, tail_owns_offset)`
가 계획을 내고 `apply_boundary_envelope(samples, sr, plan)` 이 적용한다. 창은
`smoothstep_fade_in_window`(첫 샘플이 정확히 0)와 `smoothstep_fade_out_window`(마지막 샘플이 정확히 0)
이며, 뒤쪽 위상 관례는 기존 `_cosine_fade_window` 와 같다. 길이는 바뀌지 않는다 — gain 곱셈뿐이고
padding 이 없다. 같은 plan 을 두 번 적용하면 `BOUNDARY_DOUBLE_APPLY` 로 막는다(두 번 걸면 gain 이
제곱돼 실제로 들린다).

배선은 `python/tts_worker.py` 의 `_finish_and_place` 한 곳뿐이다. 여기가 **조립이 끝난 최종 배열을
보는 유일한 지점**이라, 단문이든 장문이든 자동으로 "결과물 바깥 경계에만 한 번"이 된다.
내부 chunk 결합(`_concat_with_boundaries`)은 손대지 않았다 — 청크마다 fade 를 넣으면 파츠 느낌과
공백이 생기기 때문이고, 내부 join 처리는 별도 경계 계측이 있을 때의 일이다.

적용 순서는 pitch → **경계 envelope** → tail(조건부 fade + 0 padding) → 검증 → 원자 교체다.
tail plan 은 envelope **적용 전 원본**으로 산출한다. 그러지 않으면 tail 의 `already_silent` 판정
(마지막 5 ms peak ≤ 1e-4)이 우리 offset fade 때문에 뒤집혀 tail 계약의 의미가 달라진다.

적용한 샘플 수는 metadata 로 나간다: `boundary_onset_samples`, `boundary_offset_samples`.
clamp 된 결과가 아니라 **실제로 적용한 값**이다.

## 5. 기존 tail 처리와의 관계 — 중복이 아니라 보완

기존 `ttsTailMode` 는 **기본값이 `off`** 다. A2 실행 config 도 `"ttsTailMode": "off"` 였다.
즉 사용자가 들은 그 음성에는 fade 가 **아예 없었다**. 그리고 tail 은 `auto` 일 때조차 말끝만
다루고 시작 쪽 개념이 없으며, fade 상한이 20 ms(기본 8 ms)에 padding 120 ms 를 덧붙여 길이를 바꾼다.

경계 envelope 은 다른 물건이다. tail 설정과 무관하게 항상 적용되고, 길이를 바꾸지 않으며,
시작을 담당한다. 겹칠 수 있는 유일한 지점은 말끝인데, 거기서는 **tail 에 권위를 양보한다** —
`tail auto` 가 실제로 cosine fade 를 거는 경우(`fade_applied`)에만 offset 을 0 으로 두고
`boundary_offset_samples = 0` 으로 기록한다. 같은 구간을 두 번 fade 하는 일은 없다.
tail 이 fade 를 걸지 않는 경우(무음 말끝, `fade_ms = 0`, `off`)에는 우리 offset 이 그대로 간다.

## 6. 기존 검사는 왜 급절단을 놓쳤나

세 가지가 겹쳤다.

**첫째, 시간 해상도가 두 자릿수 모자랐다.** `analysis.json` 의 판정은 `head300_dbfs` / `tail300_dbfs`,
즉 **300 ms RMS** 위에서 이뤄졌고 `abrupt_start_candidate` / `abrupt_end_candidate` 가 전부 `false` 였다.
클릭은 5~10 ms 사건이다. 300 ms 창으로 평균 내면 완전히 뭉개진다. 실제로 happy 의 head300 은
−18.64 dBFS 로, 그냥 평범한 말소리 레벨처럼 보인다. "마지막 30 ms RMS 비교" 변형도 같은 병이다.

**둘째, 끝 검사는 무음에 속았다.** happy 와 angry 는 마지막 10~15 ms 가 디지털 무음이다. 마지막
30 ms 의 RMS 를 재면 그 무음이 평균을 끌어내려 안전해 보인다. 정작 계단은 끝나기 15~45 ms 전에 있다.

**셋째, 아무도 불연속 자체를 재지 않았다.** 재던 것은 전부 **구간의 레벨**(head 대 tail, RMS 대 peak)
이었다. 클릭은 레벨이 아니라 **레벨의 변화율**이고, 무음을 붙이지 않으면 관측조차 되지 않는다.
경계 앞에 진짜 무음을 붙인 상태에서 envelope 기울기나 국소 고역 트랜지언트를 보는 항목이 없었다.

이번 계측에서 우리도 한 번 같은 함정에 빠졌으므로 기록해 둔다. 처음에 쓴 **전역 FFT brick-wall
고역 통과**는 sinc 누설이 신호 전체에 퍼져 경계 측정에 바닥을 만든다. 창을 늘려도 값이 더 내려가지
않는 **가짜 포화**가 보였고(happy 가 −9 dB 부근에서 멈춤), 하마터면 그 포화를 "더 늘려도 소용없다"는
근거로 읽을 뻔했다. support 3 샘플짜리 국소 고역(2차 차분)으로 바꾸자 곡선이 단조로워지고
숫자가 2~3 배 달라졌다. **경계를 재는 필터는 반드시 국소여야 한다.**

## 7. preview 규격

처리된 음성 앞뒤로 각각 1.0 초 무음이며, preview 길이 = 처리 길이 + 정확히 2.0 초다.
현행 산출물로 검증했다: happy 117120 → 165120, angry 115201 → 163201, sad 103680 → 151680 프레임.
전부 차이가 정확히 48000 샘플(= 2.000000 초)이다.

경계 envelope 은 길이를 바꾸지 않으므로 이 관계는 수정 후에도 그대로 성립한다(같은 프레임 수로 재확인).
**앞뒤 1 초는 진단용 무음이지 fade 길이가 아니다.** fade 는 10 ms / 20 ms 뿐이고,
1 초 구간 전체에 거는 일은 없다. raw / cache 는 처리 이전 산출물이고 preview 는 청취 전용 파생물이라
서로 구분해 다룬다.

`python_embeded` 는 `._pth` 때문에 스크립트 디렉터리와 `PYTHONPATH` 를 자동으로 잡지 않으므로,
`test_audio_finishing.py` 같은 파일은 경로를 주입해 실행해야 한다(기존 조건이며 이번 변경과 무관).

## 9. 확인하지 못한 것

- **실청취 확인을 받지 못했다.** 수정 후 음성을 사용자가 들은 결과가 없다. 클릭이 사라졌다는 주장은
  계측(국소 고역 경계비 −22 dB, 계단 잔여 −15.7~−19.1 dB)까지이고, 최종 판정은 귀다.
- **GPU 재합성을 하지 않았다**(금지). 검증은 기존 WAV 와 synthetic 신호 위에서만 했다.
  envelope 이 걸린 실제 Qwen3 산출물은 아직 존재하지 않는다.
- **소재 3종 + 대조군 1종이 전부다.** 화자·언어·감정이 다르면 가장 이른 자음 버스트가 8 ms 보다
  앞설 수 있다. 그 경우 10 ms 창은 지금보다 더 깎는다. 새 소재가 생기면 §3 의 계측을 다시 돌려야 한다.
- **장문(다중 chunk) 조립물에서 실측하지 않았다.** 배선상 최종 배열 한 곳에만 걸리는 것은 코드로
  확인했지만, 실제 장문 산출물의 경계를 계측한 적은 없다.
- **tail `auto` 경로의 실청취 균형을 확인하지 않았다.** auto 일 때 말끝은 tail 의 8 ms cosine 이
  가져가는데, 이번 계측 기준으로는 20 ms 가 필요했다. 즉 auto 의 말끝은 우리 기준보다 짧은 창으로
  남는다. tail 계약을 침범하지 않기로 한 결정이며, 필요하면 별도 논의 대상이다.
- **renderer/TS 쪽은 건드리지 않았다.** 새 config 필드를 만들지 않았으므로 배선도 parity 상수도 없다.

## 10. B envelope 1단계 — 조립 중 열리는 segment 경계 (2026-08-29 추가)

§4 의 배선은 `_finish_and_place` 한 곳뿐이었다. 그래서 **최종 파일의 바깥 시작·끝**만 S자를 얻고,
문장과 문장 사이에서 딱 켜지고 꺼지는 자리는 그대로 남았다. 그 자리에 같은 창을 건다.

### 10.1 경계 정보는 계산되고 있었는데 버려졌다

`semantic_chunk_planner.classify_plan_boundaries()` 는 segment 마다
`kind ∈ {internal, emotion, line, paragraph, explicitPause}` 를 낸다. 그런데
`tts_worker._boundary_gaps_from_plan` 이 `[e["gap_sec"] for e in entries]` 만 꺼내고 kind 를 버렸다.
그래서 오디오 조립 단계에는 "휴지가 있는 진짜 문장 경계"와 "문장 내부 자동 chunk 경계"를 구분할
재료가 **아예 없었다**. 이번 변경의 절반은 그 값을 버리지 않고 함께 돌려주는 것뿐이다(3번째 반환값).

※ `original_segment_index` 는 문장이 아니다. 파서가 segment 를 끊는 지점은 **줄바꿈 / 감정 태그 /
`[쉼 N]` 명시적 쉼** 셋뿐이고 마침표·물음표·느낌표·쉼표는 파서에 없다. `sentence` kind 는 상수에
자리만 있고 매핑이 없어 현재 생성되지 않는다.

### 10.2 어디에 거는가 (사용자 확정 계약)

- `kind ∈ {line, paragraph, explicitPause}` — **열린 경계**. 앞 segment 의 **마지막 chunk 끝**에
  inverted ease-out(1→0), 뒤 segment 의 **첫 chunk 시작**에 ease-in(0→1).
- `kind ∈ {internal, emotion}` — **적용 0**. 같은 문장 안에서 이어진 마침표 문장도, 자동분할이
  만든 문장 내부 chunk 경계도 접합 지점이 아니다.
- 마침표마다 강제로 chunk 를 나누는 일(2단계)은 하지 않았다.
- 텍스트를 다시 파싱하거나 문장부호 규칙을 새로 만들지 않는다 — 판정 재료는 파서 kind 하나뿐이다.

### 10.3 최종 파일 양 끝과의 중복을 구조적으로 막는 방법

경계는 segment 그룹과 그룹 **'사이'** 에만 존재한다. 따라서 첫 그룹의 첫 chunk 시작과 마지막
그룹의 마지막 chunk 끝은 후보 집합에 **들어갈 수 없다**. 조건문으로 빼는 것이 아니라 자료구조가
그렇게 생겼다. `_apply_segment_envelopes` 는 그 사실을 실제로 단언하고(위반 시 RuntimeError),
그 두 자리는 §4 대로 `_finish_and_place` 단일 권위로 남는다.

### 10.4 무엇을 어디에 넣었나

`python/tts_worker.py` 에 `_apply_segment_envelopes` 를 새로 두고 `_concat_with_boundaries`
**직전**에 부른다(조각이 아직 개별 파일인 마지막 자리 — 결합 뒤에는 무음이 이미 들어가 어디가
경계였는지 배열만 보고 알 수 없다). 창·곡선·길이는 §3·§4 그대로 재사용한다(onset 10 ms /
offset 20 ms / smoothstep). `_concat_with_boundaries` 와 `_finish_and_place` 는 **무변경**이다.

길이는 바뀌지 않는다 — gain 곱셈뿐이라 `frames`/`gap_before_samples`/`start_sample` 진단이 이
단계 전후로 동일하고, pause 값도 흔들리지 않는다. 원본 chunk 파일은 덮어쓰지 않고 수정본을
work_dir 에 새로 쓴다(정렬·진단 산출물 보존). subtype 을 보존하므로 창 **밖**은 PCM_16 에서도
비트 단위로 같다(왕복 무손실 실측).

metadata 는 `segment_envelope_onset_count` / `segment_envelope_offset_count` /
`segment_envelope_kind_counts` / `segment_envelope_applied`(경계마다 앞·뒤 chunk 좌표와 샘플 수).
최종 파일 양 끝을 말하는 `boundary_onset_samples` / `boundary_offset_samples` 와는 **다른 자리**다.

### 10.5 GPU 실측 (2026-08-29, 2 segment / 9 chunk, ICL auto)

§9 의 "GPU 재합성을 하지 않았다"와 "장문(다중 chunk) 조립물에서 실측하지 않았다"를 이번에 해소했다.

- 적용 횟수: onset 1 · offset 1 · `{"line": 1}`. 2 segment → 경계 1개 → 정확히 한 쌍.
  좌표는 offset=`[0, 3]`(segment 0 의 마지막 chunk) / onset=`[1, 0]`(segment 1 의 첫 chunk).
  **첫 chunk `[0,0]` 의 시작과 마지막 chunk `[1,4]` 의 끝은 기록에 등장하지 않는다** — 중복 0.
- 경계 join(228219) 직전 480샘플 peak `0.000031`(사실상 디지털 무음). 같은 자리를 envelope 없이
  만든 직전 실행은 `0.005280` 이었다. `sample_jump` 0.00000.
- 경계 직후 onset 창(240샘플) 안 peak `0.000275`, 첫 유의 신호(|x|>0.005)는 **810샘플(33.8 ms)**
  뒤 — 10 ms 창은 첫 자음에 닿지 않는다.
- 선언 gap 은 두 실행 모두 **9600샘플(400 ms)로 동일**하다(pause 계약 불변). 다만 파형에서 잰
  '들리지 않는 구간'은 400.2 ms → 438.1 ms 로 늘었다. 말미 20 ms 가 fade 로 0 에 닿았기 때문이며,
  두 실행의 생성 파형 자체가 다르므로(seed 미지원) 이 차이를 전부 envelope 몫으로 볼 수는 없다.
  **체감 쉼이 최대 onset+offset(30 ms)만큼 길어지는 것은 이 계약의 당연한 결과**다.
- 길이: chunk frames + gap 합계 633,504 → 최종 636,384(+2,880 = tail padding 120 ms). 직전 실행과
  같은 +2,880 이다. 비유한 0, peak 0.6874.

### 10.6 아직 확인하지 못한 것

- **실청취 확인이 없다.** 경계가 부드러워졌다는 주장은 위 수치까지다.
- **경계가 1개뿐인 소재로만 실측했다.** 문단(`paragraph`)·명시적 쉼(`explicitPause`) 경계와
  경계가 여러 개인 장문은 단위테스트(SYNTHETIC)로만 고정돼 있고 GPU 산출물로 재지 않았다.
- **2단계(마침표 문장 분리)는 범위 밖이다.** 같은 chunk 안에서 이어진 마침표 문장은 지금도
  접합 지점이 아니며, 그 자리를 다루려면 chunk 분할 자체를 바꿔야 한다.
