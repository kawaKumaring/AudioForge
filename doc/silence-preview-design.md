# 무음 감지 미리보기 + 청취 (설계) — 2026-08-16

상태: **설계만 (미구현)**. 구현 착수 시 이 문서를 기준으로.

## 1. 사용자 의도 (원문 요약)
- 소리 파일을 불러오면 파형은 보이는데, **무음 제거가 실제로 무엇을 자를지** 확인할 방법이 없다.
- 감지된 무음 구간을 **파형에 표시**하고, 그 **구간 시작·끝을 들어봐서** 진짜 무음인지 확인하고 싶다.
- 완전 자동 도구이되, **수동 조절 기능을 숨겨뒀다가** 선택 시 펼치는 점진적 노출(progressive disclosure).

## 2. 핵심 발견 (설계의 전제 — 반드시 유지)
**"무음 간격" 슬라이더(0~2초)는 감지 파라미터가 아니다.** `audio_utils.py`의 `trim_silence`:
- **감지는 고정값**: 임계 −40dB(`threshold_db=-40`), 프레임 20ms/홉 10ms, 최소 무음 50ms(그보다 짧은 무음은 말소리로 병합). 슬라이더와 무관.
- **`silence_gap_sec`(슬라이더) = 남긴 말소리 세그먼트 사이에 다시 끼워 넣는 무음 길이**. 감지 결과를 바꾸지 않는다.

→ 따라서 "슬라이더를 움직이면 감지 무음이 바뀌어 보인다"는 **거짓 미리보기**가 된다. 감지를 조절하고
싶으면 조절해야 할 knob은 **감지 민감도(threshold_db)**이며, 이는 현재 UI/코드에 **없는 새 파라미터**다.

## 3. 설계 (2단계)

### Phase A — 감지 미리보기 + 청취 (새 파라미터 없음)
- 무음 구간 제거가 켜지면, **고정 알고리즘으로 감지된 '제거될 무음 구간'**을 파형에 오버레이(dim/red).
  - 이는 슬라이더와 독립. 현재 실제로 잘려나갈 부분을 그대로 보여줌.
- 각 구간을 클릭 → 시작·끝 ~0.5초를 재생(audition)해 진짜 무음인지 귀로 확인.
- 슬라이더(무음 간격)는 지금 의미(삽입 간격) 유지 + 툴팁으로 "감지가 아니라 사이에 넣을 무음"임을 명확히.

### Phase B — 숨겨둔 수동 knob = "감지 민감도"
- **새 파라미터 `threshold_db`**(또는 민감도 0~100 → dB 매핑)를 노출(기본 접힘, "고급/수동" 펼침).
- 민감도를 움직이면 **감지 구간이 실제로 변함** → Phase A 오버레이가 실시간 갱신 = 사용자가 상상한
  "움직이면 눈에 보이는" 경험이 여기서 성립.
- 배선: `trim_silence(threshold_db=...)`는 이미 인자로 받음 → config `silenceThresholdDb` 추가 →
  `separate.py`에서 전달 → UI 슬라이더. (min-silence 50ms도 노출할지는 추후.)

## 4. 아키텍처
- **감지 오버레이 위치**: 메인 파형은 `Waveform.tsx`(wavesurfer WebAudio). 구간 표시는 wavesurfer
  **Regions 플러그인**으로 가능 — `SplitEditor.tsx`가 이미 `RegionsPlugin`을 씀(도입 검증됨).
- **Options ↔ Waveform 통신**: 현재 무음 슬라이더는 `Options.tsx`, 파형은 `Waveform.tsx`로 분리.
  감지 파라미터(민감도)와 "미리보기 on" 상태를 **store(app.store)** 에 두고 Waveform이 구독.
- **감지 계산 위치**: 클라이언트(디코드된 버퍼로 RMS) — `SplitEditor`의 `handleAutoDetect` RMS
  로직과 유사. 즉시·인터랙티브(서브프로세스 왕복 없음).

## 5. 위험과 완화 (필수)
- **거짓 미리보기 위험(최우선)**: 클라이언트 RMS 감지가 Python `trim_silence`와 **다른 알고리즘/파라미터**면
  미리보기가 실제 결과와 어긋난다(L-2에서 겪은 함정).
  - 완화: 감지 파라미터(−40dB·20ms/10ms·50ms)를 **단일 소스**로 두고 양쪽이 동일하게 사용.
    JS/Python 알고리즘 복제가 불가피하면 **드리프트 가드**(고정 fixture 오디오로 JS 감지 vs Python
    감지 경계 대조하는 smoke 테스트, L-3의 `_check_emotions` 패턴)를 함께 만든다.
- **성능**: 긴 파일에서 슬라이더 드래그마다 전체 RMS 재계산은 무거움 → 프레임 RMS를 1회 캐시하고
  임계만 다시 적용(임계 변경은 O(n) 비교), 드래그 debounce.
- **framer-motion 대량 stagger 금지**(기존 규칙): 구간이 많아도 컨테이너 단일 렌더, per-region 애니 금지.

## 6. 미결 결정
- 민감도 UI 표현: dB 직접 vs 0~100 민감도(직관적). → 0~100 권장, 내부 dB 매핑.
- 미리보기를 어느 모드에서? (music/conversation은 무음 제거 옵션 있음; transcribe/split은 별도.)
- min-silence(50ms)도 노출할지 — 우선 threshold만, 과잉 노출 경계.

## 8. GUI 통합 — 기존 화면을 해치지 않는 방법 (2026-08-16)

현재 배치(`App.tsx`): **파일 카드(상단: 파일정보 + `Waveform`)** 와 **옵션 패널(`Options`)** 은 별개
카드다. 방금 옵션 패널은 wrap 레이아웃으로 정리했으므로 **거기에 새 컨트롤을 넣지 않는다.**

### 원칙: 미리보기 UI는 "파형 쪽"에 산다 (옵션 패널 불가침)
시각 피드백(오버레이)이 파형에 뜨므로, 그 조작부도 파형 카드에 두는 게 자연스럽고 옵션 패널을
건드리지 않는다. 진입점은 작은 opt-in 하나뿐 → 기본 화면 발자국은 0.

### 3개 레이어 (점진적 노출)
- **Layer 0 (기본, 변화 없음)**: 파형 + 재생 버튼, 옵션 패널 그대로. 아무 것도 안 늘어난다.
- **Layer 1 (opt-in 진입점 1개)**: 무음 구간 제거가 켜진 모드에서만, 파형 컨트롤 행 아래 얇은 줄에
  `👁 무음 미리보기` 토글 1개. 끄면 이 줄도 없음.
- **Layer 2 (미리보기 켤 때만 펼침)**: 파형 아래 얇은 스트립이 부드럽게 열림 —
  ① 감지 구간 수 표시, ② 구간 이동/경계 재생(audition) 버튼, ③ (Phase B) `감지 민감도` 슬라이더.
  미리보기 끄면 접혀 사라짐 → 기본 높이 복귀.

### 오버레이 = 레이아웃 무변경
- 구간 표시는 wavesurfer **Regions 플러그인**이 기존 파형 캔버스 **위에** 그린다 → 파형 카드
  높이/구조 불변. 색은 반투명 dim(경고색 아님)으로 절제.
- 여러 구간이어도 **컨테이너 단일 fade-in만**(per-region motion+stagger 금지 — 렌더러 freeze 규칙).

### 지키는 기존 규칙
- 레이아웃은 inline style만(Tailwind v4 유틸 금지). 크기는 극소값 말고 적절히(파형 톤과 맞춤).
- 옵션 패널의 앵커/wrap 구조 불변. 무음 간격 슬라이더 의미(삽입 간격)도 그대로 + 툴팁 유지.
- Layer 2는 **조건부 렌더**라 평소 DOM에 없음 → 성능·시각 모두 기본 상태 보존.

### 열린 UI 결정 (Phase A 착수 전 확정)
- 진입점 위치: 파형 컨트롤 행 안 vs 그 아래 별도 얇은 줄 → **아래 별도 줄** 권장(재생 컨트롤과 안 섞임).
- 민감도(Phase B) 노출 시점: Layer 2 안 vs 옵션 패널 → **Layer 2 안**(옵션 패널 불가침 원칙).

## 9. 디자인 언어 — 프리미엄(iOS) 감성 유지 (2026-08-16)

새 UI는 "안 깨짐"을 넘어 **기존의 고급스러운 결에 녹아들어야** 한다. 코드에서 실제로 쓰는 관용구:

### 현재 감성의 구성 요소 (지켜야 할 것)
- **부드러운 카드**: `borderRadius 8~12`, `border 1px var(--border-subtle)`, `background var(--bg-elevated)`.
- **모드별 액센트 + glow**: 파형·버튼이 모드 색을 쓰고(예 대화=시안 `#22d3ee`), 재생 버튼은
  `boxShadow: 0 2px 12px <glow>`로 은은한 발광. 새 요소도 **현재 모드 색을 따른다**.
- **절제된 크기**: 라벨 10~11px, 시간은 `fontVariantNumeric: tabular-nums`. 극소값 남발 금지.
- **부드러운 전환**: `transition: all 0.15s`, 펼침은 `transform 0.2s`(쉐브론 회전). 급격한 pop 금지.
- **반투명 레이어**: 오버레이·배경은 `rgba(...,낮은 alpha)`로 겹쳐 얹는 느낌.
- **토글=pill**: 체크박스 숨기고 라운드 pill로(예 `Options`의 chip). 켜짐은 액센트 배경.

### 무음 미리보기에 적용
- **구간 오버레이**: 경고색(빨강) 대신 **모드 액센트를 낮은 alpha**(예 `rgba(34,211,238,0.12)`)로
  칠하고 얇은 액센트 좌우 경계선. 파형 위에 겹쳐도 톤이 튀지 않게.
- **Layer 2 스트립**: 기존 카드 관용구 그대로(`bg-elevated`+라운드+subtle border), 열림은
  `opacity + max-height` 부드러운 ease-out(스프링 느낌). 접힘도 대칭.
- **audition 재생**: 기존 원형 재생 버튼 관용구(모드 색 + glow) 재사용 — 새 아이콘 스타일 만들지 않음.
- **민감도 슬라이더**: 기존 무음 간격 슬라이더와 동일 스타일(`accentColor` 모드색, `height 4`, thin track).
- **living dashboard 결**: 값 변경 시 오버레이가 부드럽게 재배치(재생성 아닌 transition). 단
  **다수 구간에 per-item stagger 금지**, 컨테이너 단일 transition만.

### 참고 색/토큰 출처
- 모드별 색맵: `Waveform.tsx` `MODE_WAVE_COLORS` (wave/progress/cursor/btn/btnGlow) — 그대로 재사용.
- chip/토글·슬라이더 관용구: `Options.tsx`.

## 10. 다듬기 — 설계 2차 개선 (2026-08-16)

비판적 재검토로 나온 개선. **높음**=안 하면 실사용/확신에 문제, **권장/위생**=완성도.

- **R1 (높음) 청취 = "전환 재생" 스테퍼**: 작은 구간 클릭 대신 `◀ ▶`로 무음 순회 + 각 경계를
  **걸쳐 재생**(예: 시작 0.3s 전 말소리 → 무음 0.5s). "말→무음" 전환을 들어야 진짜 무음인지 확신.
  작은 구간 클릭보다 정확·쉬움. Layer 2의 주 조작부로 채택.
- **R2 (높음) 전/후 길이 요약**: Layer 2에 `1:12 → 약 0:48 (−24초)` 한 줄. 제거될 무음 합 +
  삽입 간격(무음 간격 슬라이더)까지 반영해 클라이언트 계산. 숫자 하나로 즉각 확신(iOS 감성).
- **R3 (권장) Layer 1 진입점 초경량화**: "파형 아래 별도 줄"(§8) → **기존 컨트롤 행 왼쪽 끝의
  작은 ghost 👁 아이콘**으로 대체. 미리보기 켜기 전엔 새 줄 0 = "발자국 0"에 더 충실.
  (§8의 진입점 권장을 이걸로 갱신.)
- **R4 (위생) 빈/극단 상태**: 무음 0개 → 은은한 "감지된 무음 없음"; 거의 전체가 무음이면 경고.
  빈 오버레이로 혼란 주지 않기.
- **R5 (높음) 긴 파일 성능**: 실사용 = 1시간 통화. 10ms 홉 RMS ≈ 360k 프레임 → 메인스레드 잭 위험.
  프레임 RMS는 **1회만 계산(청크 + `requestIdleCallback`)**, 임계/민감도 변경은 캐시된 RMS에
  비교만(O(n)). 슬라이더 드래그 debounce. 안 하면 드래그가 버벅임.
- **R6 (위생) 감지 로직 공유**: `SplitEditor.handleAutoDetect`가 이미 클라 RMS 감지 → 공통 유틸로
  추출해 JS측 단일 소스(용도별 파라미터만 분기). JS↔Python 드리프트 가드(§5)는 별개 유지.
