**최종 연결 실패 복구** — 없음 → **연결 완료(실제 앱 확인)**
이어 듣기·저장이 실패하면 최종 음성 줄에 사유와 **다시 시도**가 뜬다.
실패해도 카드·대사·채택은 그대로다(실제 앱 6건).

**카드 생성 실패 복구** — 없음 → **연결 완료(실제 앱 확인)**
카드 줄에 사유와 **다시 생성**을 붙였고, 본체 오류 이벤트도 그 카드로 보낸다.
시작 거절(통로 예외·본체 오류 이벤트 두 모양)과 다시 생성을 실제 앱에서 확인했다.

## 해결한 문제 — 어제의 '열린 문제' 둘

### 1. 생성 시작 거절이 화면에 뜨지 않던 것 — **해결**

어제는 '화면이 삼킨다' 고 적었다. **그 판단이 틀렸다.** 원인은 둘이다.

**원인 ①(제품 결함)** 카드의 상태 줄이 `만드는 중 || 참조 준비 중 || 설정 경고` 일 때만
그려졌다. 거절 직후에는 작업이 이미 풀려 셋 다 거짓이라, 사유를 상태에 넣어도
**그려질 줄 자체가 없었다.** 줄의 조건에 실패를 넣어 고쳤다.
(검사 `평소엔 상태 줄이 없다` 가 이 사실을 직접 붙든다 — 평소 0개였던 줄이
실패 뒤에 생긴다. 즉 실패가 줄을 만들지 못하면 사유는 어디에도 못 뜬다.)

**원인 ②(검사 결함)** 어제 검사의 고정물이 목소리를 `voice` 자리에 넣었다. 화면이 보는
자리는 `builtin` 이다(`cardVoiceOf`). 그래서 카드가 '목소리 없음' 이 되어 **생성 단추가
비활성**이었고, 눌러도 아무 일이 없었다. '통로는 거절하는데 화면이 조용하다' 는 인상은
여기서 나왔다.

확인한 실패 모양 둘:
- **Promise 예외** — `audio:process` 가 거절한다(바쁨·취소 정리 중·파이썬/스크립트 없음
  등 실제 시작 거절이 모두 이 모양이다. 본체 코드에서 `throw` 로 확인).
- **오류 이벤트** — 시작은 받아들이고 본체가 나중에 `audio:error` 를 보낸다.

요청 식별자 대조는 **느슨하게 만들지 않았다.** 남의 식별자를 단 오류는 내 카드에 뜨지
않고 내 작업도 끝내지 않는 것을 반대 사례로 확인했다.

### 2. 앱이 쓰는 파이썬 경로 — **해결(승인받아 수정)**

`externals/env.json` 의 `python` 을 실제로 있는 실행 파일로 바꿨다.
변경 전 파일은 `externals/env.before-python-path-fix-2026-09-27.json` 에 남겼다.
`singing_python`·`singing_script`(Seed-VC)는 그대로다.

★개발본과 master 는 설정이 **하나다.** `develop-run/externals` 가 master 의 `externals`
를 가리키는 연결이라 두 곳을 각각 봐도 같은 파일이다 — 고친 값도 하나다.

환경변수 우회 없이 설정만으로 기본 목소리 목록이 돌아온다(piper `ko_KR-kss-medium` 1개).
