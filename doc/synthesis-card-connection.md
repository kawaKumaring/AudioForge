# 생성 카드 — 실제 연결 (Claude 담당분)

2026-09-27. GUI·UX 는 Codex, 데이터·음성 처리·저장 연결은 Claude.
이 문서는 **연결된 것과 연결되지 않은 것, 그리고 엔진이 실제로 받는 값**을 적는다.

## 엔진이 실제로 받는 값 (코드에서 확인한 사실)

화면의 손잡이와 엔진이 받는 값은 같지 않다. 차이를 숨기면 "보내는 척" 이 된다.

- **말하기 속도** — 실제로 쓴다. 네 엔진(F5·Kokoro·piper·그 외)이 모두 `speed` 를 받아 쓴다.
  워커에 자르는 자리는 없다. 화면의 0.7~1.3 은 범위 안이다.
- **음높이** — 실제로 쓴다(rubberband 반음 후처리). **다만 `[-2.0, +2.0]` 로 잘리고
  0.5 단위로 반올림된다**(`python/pitch_shift.py` `clamp_quantize`).
  → 화면 슬라이더도 같은 범위를 쓴다(2026-09-27 Codex 반영, 공유 상수를 함께 본다).
  범위 밖 값이 들어오는 경로(옛 저장본 등)는 앱이 미리 깎고 **깎았다고 카드에 적는다.**
- **감정 — 보내지 않는다.** 엔진에 스칼라 감정 입력이 없다.
  감정은 `ttsEmotionRefs`(감정별 참조 클립)로만 동작하고, 등록이 없으면
  **기본 참조로 폴백한다**(`python/tts_worker.py`: "미등록 → 기본 참조 폴백(정상)").
  즉 참조 없이 고른 감정은 소리를 바꾸지 않는다.
  → 2026-09-27 Codex 가 **엔진에 닿지 않는 감정 문자열 선택을 화면에서 뺐다.**
  옛 저장본에 남은 미지원 감정은 지우지 않고 해제할 수 있게 두었고, 앱은 그 값을
  **보내지 않으며 안 보낸다고 카드에 적는다.** 실제 감정 참조 연결은 다음 단계다.
- **카드에 없는 값은 제품 기본값**을 쓴다(`shared/labWorkspace` 의 `defaultSettings`).
  특히 `ttsTailMode` 를 안 보내면 워커가 `off` 로 떨어져 **말끝이 잘린다** — 반드시 보낸다.

## 소유권

한 카드의 변경·삭제·정리가 다른 카드나 기존 작업의 파일을 건드리지 않는다.

- 파생 참조 클립 자리는 **`card:<카드 id>`** 다. `default`(고급)·`lab`(일반)·`spk:`(인물)·
  감정 id 와 겹치지 않는다. 공용 파일 작업의 리셋은 `fileWorkspaceClipKeys` 가
  `default`/`spk:`/감정만 고르므로 **카드 자리를 건드리지 않는다.**
- 영상에서 꺼낸 소리는 `userData/cardmedia/<카드 id 지문>/` 에만 산다.
  정리(`card:release-media`)도 그 폴더만 지운다.
- 카드가 되돌릴 수 없게 사라졌을 때만 그 카드 소유분을 정리한다(되돌리기 창이 닫힌 뒤).

## 늦은 응답

- 준비: 카드마다 `reqId`. 지금 기다리는 요청이 아니면 보고를 버린다.
- 생성: 돌고 있는 작업은 **한 건**이고 `cardId`+`reqId` 를 함께 붙든다.
  결과가 왔을 때 그 카드가 사라졌으면 붙이지 않는다.
- 요청 시점의 **대사·원본·설정·적용값**을 붙들어 생성본에 넣는다.
  도중에 고쳐도 결과에는 그때 값이 붙는다.

## 저장과 복원

- 저장 자리는 **`synthesisCards`** — 문장별 작업(`labWorkspace`)과 **다른 자리**다.
  이관 계획이 없으므로 서로를 읽지도 쓰지도 않는다.
- **묵시적 복원이 없다.** 합성에 들어올 때 저장본이 있으면 한 번 묻고, 고른 뒤에만 되살린다.
- 거절해도 저장본은 지우지 않는다(지우는 코드가 없다).
- 카드 순서·대사·설정·생성본·채택을 함께 저장한다.
- 되살릴 때 사라진 생성본 파일은 지우지 않고 **'파일 없음' 으로 표시**하고 재생·채택을 막는다.
- 채택한 생성본이 사라졌으면 채택만 비운다(없는 것을 가리키면 최종 연결이 헛돈다).

## 이번에 연결하지 않은 것

- **최종 음성** — 전체 이어 듣기·연결부 듣기·파일로 저장. 여전히 비활성이다.
- **다중 카드 큐** — 한 번에 한 장만 만든다(파이썬 통로가 하나다).
- 감정(위 사유), 접기, 비슷한 위치 비교 재생, 바뀐 카드만 재생성, 이동·교체 되돌리기.

## 검사

- 순수 계약: 지원 범위 10건, 저장·복원 10건.
- 연결 가드 5건: 실제 경로를 부르는가 · 늦은 응답을 가려내는가 ·
  못 보낸 설정을 띄우는가 · 생성본을 더하기만 하는가 · 생성이 채택을 건드리지 않는가.
- 취소 가드: 카드 화면은 공용 실행 단추를 감추므로 **직접** 취소 수명주기를 듣는다.
- ★**GUI 검사(모델 대체)는 실제 생성 성공이 아니다.** 실제 생성은 저장소의 승인된
  음성 fixture 로 진짜 엔진을 돌려 따로 확인한다.

## 2026-09-27 검수 — 고친 다섯 가지

격리된 Electron 재현으로 드러난 결함들. 각각 **재현 → 원인 → 조치** 순으로 적는다.

### 1. 빠른 메뉴 이동에서 마지막 편집이 사라졌다
재현: 대사 A 저장 대기 → B 로 수정 → 600ms 안에 다른 메뉴로 이동 → 저장값은 **A**.
원인: 저장이 화면 안의 effect 였고 **언마운트에서 타이머를 취소**했다.
조치: 저장 소유자를 화면 밖(`lib/cardWorkSaver`)으로 옮겼다. 화면이 사라져도 타이머가 산다.
  떠날 때는 취소가 아니라 **흘려보낸다**(flush). 앱을 닫을 때도 최선을 다해 남긴다.
  쓰기를 한 줄로 세워 **순서가 뒤집히지 않는다** — 느린 앞 쓰기가 뒤 쓰기를 덮지 않는다.

### 2. 저장 실패 응답을 버렸다
원인: `saveSetting` 은 실패를 던지지 않고 **돌려주는데** 그 값을 `void` 로 버렸다.
조치: 저장 소유자가 실패를 상태로 올린다. 화면에 '저장 실패' 와 **다시 저장**이 뜨고,
  자세한 코드는 툴팁에 둔다. 저장이 성공하기 전에는 성공으로 취급하지 않는다.

### 3. 복원을 거절하면 이전 문서가 덮였다
재현: 저장본이 있는 채로 합성 진입 → '현재 작업 계속' → 새 카드 편집 → 이전 문서가 사라짐.
원인: 저장 문서가 한 칸뿐이라 새 작업이 그 자리를 그대로 차지했다.
조치: 문서를 **두 칸**으로 나눴다 — `current`(지금 것)와 `kept`(치워 둔 것, 최대 5개).
  거절하면 지금 문서를 `kept` 앞으로 **옮긴다.** 지우는 코드가 없다.
  되살리기 팝업은 `current` 와 `kept` 를 **모두 목록으로** 보여 주므로 재시작 뒤에도 닿는다.
  ★생성한 소리 파일이 남는 것과 **작업 문서가 남는 것은 다른 일**이다.

### 4. 삭제 되돌리기 후 목소리 준비가 사라졌다
재현: 준비 완료 카드 → 삭제 → 되돌리기 → 카드는 돌아오는데 생성 단추가 잠긴 채.
원인: 지우는 쪽만 `refs` 를 치우고 되돌리는 쪽은 몰랐다. 화면의 준비 캐시도 남아 재준비도 안 됐다.
조치: 지운 카드의 준비 상태를 `removed` 에 **얹어 두고** 되돌릴 때 함께 되살린다.
  파생 클립은 되돌릴 수 없게 된 뒤에만 지우므로 그대로 쓸 수 있다.
  화면 캐시도 **준비 상태가 없으면 다시 준비**하도록 바꿔 어느 쪽이든 어긋나지 않는다.

### 5. 결과 수신부가 요청을 대조하지 않았다
재현: NEW 요청이 도는 중에 OLD 요청의 결과 이벤트를 넣자, **옛 파일이 지금 대사와 묶여**
  생성본에 붙었다.
원인: 화면이 '작업이 있는가' 만 보고 '누구의 것인가' 를 안 봤다. 요청 식별자를 만들기만 하고
  본체에 보내지 않았고, 본체도 이벤트에 출신을 싣지 않았다.
조치: **요청 → 진행 → 결과 → 오류 → 취소 전 구간**에 식별자를 흘린다.
  화면이 `clientRequestId` 를 실어 보내고, 본체(`audio.ipc.ts` 의 `tagReq`)가 여섯 개
  이벤트에 그대로 되돌려 준다. 화면은 자기 것이 아니면 버린다.
  ★**식별자가 없는 이벤트는 내 것이 아니다.** 느슨하게 받으면 규칙이 있으나 마나가 된다.
  ★본체가 실행을 한 줄로 세우는 것과 **이벤트가 출신을 말하는 것**은 다른 보장이다.
    앞엣것만으로는 화면이 가려낼 방법이 없다.

### 함께 고친 것
- 카드 파형·미리듣기가 **영상 원본 경로** 대신 꺼낸 wav 를 쓴다(준비 경로와 같은 파일).
- 생성본 스냅샷에 **실제로 쓰인 참조 구간**을 남긴다(자동 확정분 포함).
- 옛 생성본에는 적용값 칸이 없다 — 없는 값을 지어내지 않고 '기록 없음' 으로 보여 준다.
  (이 칸을 그냥 읽다가 생성본 목록이 통째로 안 그려진 적이 있다.)

## 2026-09-27 2차 검수 — 고친 세 가지

### 1. 마감 신호에서 요청 식별자가 사라졌다
재현(실제 본체 경로): `progress ID=MAIN-result → result ID=undefined`.
원인: `runner.on('done')` 첫머리에서 식별자를 비웠는데, **result 와 보류된 error 는 그 뒤에**
  나간다. 전역의 '현재 식별자' 를 뒤늦게 조회하는 구조였다.
조치:
- 식별자를 **각 실행의 지역 상수**로 잡는다. 실행 안의 모든 이벤트가 그 값을 쓴다.
- `sendError` 가 어느 요청의 오류인지 **인자로 받는다.** 실행 밖 오류는 식별자를 주지 않는다.
- 마감에서 비우지 않는다. 다음 실행이 시작할 때 덮어쓰는 것으로 충분하다.
- 취소 통로(다른 핸들러)는 남겨 둔 값을 쓴다 — 취소는 그 실행을 겨냥한 것이다.
검사: **본체를 통과하는** 새 검사 12건(`synthesis-cards-main-path.e2e.mjs`).
  실제 `audio:process` 와 PythonRunner 를 타고 모델만 `fixtures/synthetic_tree.py` 로 바꾼다.
  성공·오류·취소 셋 다 본다. 이벤트 주입 검사(29건)는 그대로 둔다.

### 2. 취소 대조에 예외가 남아 있었다
원인: 화면의 판정이 '식별자가 없으면 내 것' 으로 보고 있었다. 그 예외가 1번의 유실을 가렸다.
조치: 잣대를 하나로 합쳤다 — 진행·결과·오류·취소 모두 같은 규칙(`cardEventFault`)을 쓴다.
  남의 신호는 내 작업을 끝내지도, 실패 알림을 띄우지도 않는다(조용히 지나간다).

### 3. 보관본을 고르면 하던 작업이 사라졌다
재현: current=A, kept=[B] → B 를 불러와 고치면 디스크가 current=B', kept=[] 가 됐다.
조치:
- 보관본을 꺼낼 때 **하던 작업을 보관함 앞으로 옮긴다**(`adoptFromKept`).
- 전환 순서를 바꿨다 — **먼저 읽고**(실패할 수 있다) 성공한 뒤에야 저장 문서를 바꾼다.
- ★보관 개수 자르기를 **없앴다.** 예전에는 다섯 개가 넘으면 사용자가 지운 적 없는 작업이
  조용히 사라졌다. '지우는 코드가 없다' 던 설명은 그 점에서 틀렸다.
  목록에 보여 주는 수를 줄이는 것과 저장 문서를 버리는 것은 다른 일이다.

### 함께 고친 것
- 종료 직전 저장을 **기다려 주는 통로**(동기)로 바꿨다. 비동기 요청은 창이 닫히면 사라져
  마지막 편집 직후 종료하면 잃는다. 자동 저장이 쓰던 길과 같은 길이다.
- 동기 통로의 허용 목록에 카드 열쇠를 더했다. 목록 자체는 그대로 닫혀 있다(가드로 고정).

### 이번에 달아 둔 가드

- 보류된 오류가 어느 요청의 것인지 말하지 않으면 운다.
- '식별자 없으면 내 것' 예외가 되살아나면 운다.
- 보관 문서를 자르면 운다 / 하던 작업을 지키는 규칙이 없으면 운다.
- 저장 열쇠가 본체 허용 목록에서 빠지면 운다.
